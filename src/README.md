# JavaScriptの配置

入口は [main.js](main.js)。ゲーム全体の初期化・画面同期は [app/ui.js](app/ui.js) が行う。各機能の処理・設定・画面は同じフォルダへ置き、機能名から関連ファイルを探せる構成にする。

| フォルダ | 責務 |
| --- | --- |
| `app/` | 起動後の連携、行動、イベント、日次処理 |
| `core/` | 状態、保存、日時、共通定数・規則・補助処理 |
| `ui/` | DOM参照、レイアウト、数量入力、編成条件などの共通画面部品 |
| `world/` | 地図、表示範囲、描画、名称、世界観 |
| `battle/` | 戦闘準備、編成、初期配置、部隊陣形と指示、進行、標的選択、移動、士気、援軍、兵員精算、大会戦 |
| `quests/` | 依頼、進捗、期限、依頼一覧 |
| `resources/` | 物資、兵員、維持費、交易・雇用画面 |
| `fleet/` | 船団、船種、造船所、固有船、船維持費、艤装 |
| `codex/` | 兵・船・艤装の紹介、閲覧・比較、永続的な在籍・取得記録 |
| `factions/` | 勢力、貴族、前線、国力 |
| `faith/` | 信仰の恩恵、潮盟拠点と画面・情景 |
| `pirates/` | 無法港、禁制品、海賊依頼、遭遇、経済補正、五列強・海賊王の物語と専用海図 |
| `wanted/` | 犯罪、手配、施設権限、追跡、清算、所属変更、交渉窓口 |
| `bounty/` | 常駐NPC賞金首、世界配置、一覧、地図マーカー |
| `fishing/` | 釣り、魚種、図鑑、報酬、釣り画面 |
| `exploration/` | 自然探索、海図、探索画面 |
| `dangerousSeas/` | 南西・南東の区域判定、釣り優遇、警戒・天候周期・斥候・退避距離、専用探索・限定イベント・賞金首、配置予約と保存状態の補完 |

## 追加・変更するとき

- 各機能のUIは機能フォルダへ置く。`ui/`には複数機能で使う部品を置く。
- 読み込みはファイル位置を基準にした相対パスを使う。ビルドやパス別名の設定は不要。
- `index.html`、CSS、画像はリポジトリのルート側に置く。画面に設定する画像URLはHTMLを基準に解決されるため、JSの移動だけを理由に変更しない。
- ゲーム仕様は [設計書の案内](../design/README.md) を参照する。

## テスト

`npm test`の最初に、全モジュールの構文・読み込みパス・文字コードとHTMLの入口を確認する。続いて既存の機能テストを実行する。

危険海域の検証は `npm run test:dangerous-seas` でも実行できる。純粋な区域・抽選・報酬の計算に加え、天候周期・既知予報・斥候効果、釣り・段階探索・限定イベントの保存失敗と再開、日次危険の保留、既存地点との配置予約を確認する。

既存のVMテストでは `tests/helpers/source.cjs` の `readSource("ファイル名.js")` を使う。実ファイルと依存先を検証して読み込み、モックのキーは従来の `./ファイル名.js` にそろえる。検証用の論理名が衝突しないよう、JSのファイル名は全機能で一意にする。実際の相対パスは `tests/moduleLayout.test.cjs` で変換せず検査する。

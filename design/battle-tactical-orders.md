# 部隊行動・攻撃目標・立て直し 設計書

作成日：2026-10-15。

状態：第1〜4段階を実装し、自動テスト・戦闘シミュレーション・PC／スマートフォン幅の操作を確認済み。ユーザーが採用した「進軍・待機」「部隊別の攻撃目標・担当区域」「後退・立て直し」と、それらを既定でおまかせAIに任せる方針を具体化する。閾値・維持時間は初期実装値で、勝率と時間切れへの影響は今後も調整する。検証の範囲と限界は第14節を参照する。

攻撃目標を全体設定ではなく個別に扱いたいという追加指示に基づくUI改訂案を第15節に記載する。第15節は未実装。第8.2・9節の全味方／一括の攻撃目標設定は現行実装の記録とし、改訂時には第15節の方針へ置き換える。

戦闘の計算・士気・敗走・増援・精算は [戦闘基盤再設計](battle-redesign.md)、部隊陣形と停止中の操作は [部隊陣形・一時停止指示](battle-unit-formations.md)、描画は [兵・艤装の戦闘演出](battle-effects-design.md) を参照する。本書は部隊の行動意図と通常攻撃の目標選択を担当する。

## 1. 目的と採用範囲

部隊をいつ前へ出すか、どの敵を先に崩すか、いつ後方へ下げるかを選べるようにする。通常はAIだけで戦闘を進められ、プレイヤーは必要な部隊・項目だけ手動で上書きできる。

- 通常戦・依頼戦・探索戦・賞金首戦・大会戦へ共通適用する。予備隊は既存の大会戦だけで扱う。
- 行動、攻撃目標、担当区域の既定値をそれぞれ `auto` とする。既存の部隊陣形のおまかせも維持する。
- おまかせは開始時だけの設定ではない。AIが戦況に応じて進軍・待機・立て直しと標的方針を切り替える。
- 手動指示はAIより優先する。行動だけ手動・攻撃目標はおまかせ、などの組み合わせを許可する。
- 追加の攻防倍率、HP回復、兵種能力、指揮ポイント、手動スキルは導入しない。部隊陣形は引き続き攻防と士気の補正を担当する。
- 全滅以外の勝利条件、自由な経由地点指定、敗走兵の戦闘復帰は今回の範囲に含めない。

### 戦術の例

盾兵を待機させて正面を受け、弓兵を敵の上側へ集中させ、後方で待たせた騎兵を進軍させる。士気の落ちた盾兵には立て直しを指示し、空いた前線へ別の近接部隊を進める。これらを手動で組み立てられる一方、おまかせでも兵種ごとの基本運用を行う。

## 2. 実装前の仕組みと変更境界

2026-10-15の実装着手時に確認した内容。以下の左列は本機能を追加する前の挙動を示す。

| 現行の仕組み | 本書で追加・変更すること |
| --- | --- |
| `battleStrategy.targetMode`は味方全軍の方針。`type`では兵種別の固定方針を使う | 部隊別指示と、戦況で変化する標的方針を追加する |
| `battleCore.js`は標的への接近、地形退避、射撃兵の距離維持、支援兵の追随を計画する | 計画の前に部隊の行動意図を確定し、接近の許可と立て直しを扱う |
| 低HP時の退避は、現在地より地形補正が高い隣接マスへ1歩動く処理 | 後方の安全位置へ下がる立て直しとは区別する |
| 射撃兵の距離維持は敵近接兵の隣接時に、標的を射程内に残せる隣接マスへ1歩動く | 進軍・待機のどちらでも継続する。射程を捨てて逃げる処理は立て直し側で扱う |
| 近接兵の拘束範囲は侵入停止、離脱時1歩・攻撃禁止を課す | 新指示でも同じ制約を守る |
| 安全時の士気回復、動揺、敗走がある。HPは自動回復しない | 敗走前に安全を確保し、既存の士気回復で立て直す |
| 大会戦の予備隊は空き枠へ編成順で自動投入される | 投入方式は維持し、登場後の行動指示を追加する |
| 大会戦の準備保存は版3。部隊陣形を保存する | 本書の指示を加える版4を設け、旧版を補完する |

[過去のシミュレーション](battle-simulation-handoff.md)では騎兵の配置・仮想待機で結果が変化した。ただし待機が全条件で優位だったわけではなく、多数の時間切れを含む。本書のAIの効果や勝率を保証する資料とは扱わない。兵種能力・HP倍率・制限時間は今回まとめて変更しない。

## 3. プレイヤーが設定する指示

### 3.1 行動

進軍・待機・立て直しを一つの項目で指定する。進軍指示と後退指示が同時に固定される状態を作らない。

| 表示 | 内部ID | 意味 |
| --- | --- | --- |
| おまかせ | `auto` | AIが進軍・待機・立て直しを選ぶ |
| 進軍 | `advance` | 兵種の通常行動で敵へ接近する。射撃兵の距離維持と支援兵の前衛追随は継続する |
| 待機 | `hold` | 自発的な接近・追撃・支援追随を止める。射程内への攻撃と許可された自衛移動は継続する |
| 立て直し | `regroup` | 敵との距離を取り、安全な後方位置で士気を回復する。手動では解除されるまで前線へ戻らない |

手動の進軍・待機では、AIによる立て直しへの切り替えを行わない。敗走条件は通常どおり適用する。手動指示によって危険な位置へ留まることもプレイヤーの選択として扱い、説明に「自動の立て直しは行わない」と示す。

### 3.2 攻撃目標

| 表示 | 内部ID | 意味 |
| --- | --- | --- |
| おまかせ | `auto` | 兵種・接近されている危険・敵HP・士気から方針を選ぶ |
| 近い敵 | `close` | 四方向距離の短い敵を優先する |
| HP優先 | `hp` | 現在HPの少ない敵を優先する。HP割合との取り違えをしない |
| 後衛優先 | `rear` | 射撃役割の敵を優先し、該当候補がいなければHP優先とする |
| 強敵優先 | `strong` | 既存の強さ計算を使う。今回決める陣形補正は計算へ入れない |
| 敵を指定 | `focus` | 指定した敵部隊を優先する |

「敵を指定」は敵を選ぶまで予約を確定しない。対象の撃破・敗走・退出で指定を解除し、おまかせへ戻す。未投入予備隊は対象にできない。対象が登場tickであっても盤上なら指定可能だが、脅威・拘束・局所支援の計算には既存の登場制限を適用する。

### 3.3 担当区域

初期版は画面上の上側・中央・下側に限定する。自由な領域描画や移動先マスの指定は追加しない。

| 表示 | 内部ID | 意味 |
| --- | --- | --- |
| おまかせ | `auto` | 自部隊の現在位置に近い帯を基本に、候補がなければ他の帯も扱う |
| 全域 | `all` | 区域による優先を付けない |
| 上側／中央／下側 | `upper`／`middle`／`lower` | その帯にいる敵を優先する |

帯は `floor(3 × y / size)` の0・1・2で区分する。左右を交換しても上下の意味は変えない。おまかせの帯は行動判断の更新時に現在のyから確定し、その判断期間中は保持する。

担当区域は標的の優先条件であり、移動禁止領域ではない。区域外への迂回・距離維持・立て直しを許可する。指定敵がある場合は指定を優先する。戦闘開始後の地形・配置変更には使わない。

## 4. 待機と弓兵の距離維持

待機は「追撃しない」であり「一切動かない」ではない。

| 状況 | 進軍 | 待機 |
| --- | --- | --- |
| 敵が射程外 | 接近する | 接近しない |
| 敵が射程内 | 攻撃条件を満たせば攻撃する | 攻撃条件を満たせば攻撃する |
| 敵近接兵が隣接し、距離維持が有効 | 既存の距離維持を試す | 同じ距離維持を試す |
| 後退後に敵が離れた | 必要なら再接近する | 後退した位置で待つ |
| 退路が塞がれている | すり抜けず留まる | 同じ |

- 距離維持は既存どおり1歩、標的を射程内に残せる位置を選ぶ。担当区域・指定敵より自衛移動を先に評価するが、攻撃不能な指定敵のために距離維持まで停止しないよう、自衛の評価では射程内の代替標的を利用できる。
- 距離維持設定が「なし」なら、この自衛移動を行わない。立て直しは別の行動指示なので「なし」でも実行できる。
- 既存の地形退避は進軍では維持する。待機では、敵の最短距離を縮めない候補だけに制限し、地形退避を使った接近を禁止する。
- 支援兵の待機では前衛への追随を止める。衛生兵にHP回復能力を加えない。
- 通常の距離維持後の射撃は維持するが、拘束範囲から離脱したtickは射撃できない。接近・地形退避・立て直しで実際に動いたtickも通常攻撃できない。
- 距離維持で待機開始位置から離れても、勝手に開始位置へ戻さない。「その場を死守」は今回追加しない。

## 5. おまかせAIの共通原則

### 5.1 判断に使える情報

各tick開始時の盤面、HP、士気、前tickの実被害、未処理の士気衝撃、過去の自分の判断履歴を使う。敵の手動予約・同tickのAI判断・将来の移動や艤装抽選結果は参照しない。

味方・敵は同じ判断規則を使い、敵の初期指示もおまかせとする。陣営方向だけを左右反転する。艤装の味方専用という既存仕様は変更しない。

- 距離は四方向距離、兵種判断は `role`・`traits`・兵種IDを使う。
- 脅威・交戦・支援用の味方判定では登場tick・敗走・撃破・退出・未投入を除外する。
- 攻撃対象・占有マスについては、通常戦闘の対象・占有規則を使う。登場部隊や敗走部隊を盤面から消して経路探索しない。
- AI自体では乱数を消費しない。同点は既存のシード・tick・部隊IDによる順位とIDの比較で確定する。
- 部隊配列順によって結果が変わらないよう、判断は同じ盤面から作って一括確定する。

### 5.2 初期調整値

数値は `TACTICAL_ORDER_RULES` に集約する案とする。秒ではなく戦闘tickで数え、一時停止・描画・再生速度から独立させる。

| 項目 | 初期値 | 用途 |
| --- | ---: | --- |
| 通常のAI行動維持 | 2tick | 進軍・待機の細かな往復を防ぐ |
| 通常騎兵の接敵待ち上限 | 4tick | 味方が接敵しない場合の永久待機を防ぐ。重騎兵・略奪騎兵は対象外 |
| 立て直し検討HP | 30%以下 | 被害を受けている低HP部隊の後退判断 |
| 立て直し検討士気 | 35以下 | 動揺した部隊の後退判断 |
| 緊急後退士気 | 20以下 | 通常の維持期間・再後退待ちを無視する |
| 復帰を許可する士気 | 55以上 | 後退開始との閾値差を設ける |
| 安全継続 | 3tick | 立て直しの完了判定 |
| 自動復帰後の再後退待ち | 6tick | 同じ状況で前後を往復するのを抑える |
| 交代候補の距離 | 2マス以内 | 前衛を下げる場合の支えの有無 |
| 好機とする敵HP割合 | 40%以下 | 突破・騎兵投入・標的判断 |
| 好機とする敵士気 | 35以下 | 崩れかけた敵の判断 |

手動の行動変更は次tick開始時に適用し、この2tickのAI維持を待たない。陣形の3tick維持とは別管理で、行動変更によって陣形の維持期間・攻撃待ち・標的保持をリセットしない。

通常のAI維持期間内でも、指定敵の無効化・自衛の開始・緊急後退・立て直し先の危険化は即時に再評価する。進軍・待機を維持している間も移動後の攻撃候補は毎tick確認し、行動維持を理由に射程内の敵への攻撃を止めない。

### 5.3 行動のおまかせ

優先順位は「立て直しの継続・開始 → 兵種別の進軍／待機」。開始条件と完了条件は第7節を使う。

| 対象 | 通常時の判断 |
| --- | --- |
| 盾兵・海賊盾兵 | 射程内に戦闘可能な敵がいれば待機して前線を維持。いなければ進軍 |
| 歩兵・海兵・槍兵・斧兵・突撃兵などの近接兵 | 射程内の敵を攻撃できる位置なら待機。いなければ進軍。対騎兵の標的選択は別途行う |
| 通常騎兵（`cavalry`） | 他の味方近接兵の接敵を最大4tick待って投入する。ただし自分が拘束範囲内、射程内に敵がいる、他の味方近接兵がいない、または待ち上限に達した場合は待機制限を解除する |
| 重騎兵・略奪騎兵 | 接敵待ちを行わず初動から進軍し、射程内に敵がいれば待機して前線を維持する。危険時の立て直しと手動指示の優先は他の近接兵と共通 |
| 射撃兵 | 射程内に戦闘可能な敵がいれば待機して射撃。いなければ進軍。接近された場合の距離維持は第4節どおり |
| 支援兵 | 前衛がいれば進軍として背後へ追随。既存の背後条件を満たす、または前衛がいなければ待機 |

騎兵の「味方の接敵」は、自分以外で立て直し中ではない味方近接兵と敵近接兵のいずれかの射程内に相手がいる状態とする。隣接だけに限定せず槍兵の射程も扱う。初回の待機は最初の通常行動tickから数え、一時停止・標的変更・味方の移動で待ち時間をリセットしない。解除後に再び初動待機へ戻らず、以後は通常の接近・射程内待機と立て直しを行う。

初動待機・基本の狙い方・弱った敵への好機を使うかは、`battleTacticalAI.js`の`TACTICAL_UNIT_POLICIES`で兵種別に指定する。騎乗属性`mounted`は対騎兵特効・突撃抑制・側方経路評価などの物理的な特性に残し、属性だけで初動待機や後衛優先を決めない。重騎兵・略奪騎兵が接敵した場合も、通常騎兵にとって味方の接敵として扱う。

射撃兵だけの軍でも、射程外なら進軍する。両軍が相手の接近だけを待つことを通常AIの既定にしない。

## 6. 標的のおまかせと共通選択規則

### 6.1 標的候補と優先順位

移動のための候補と、実際の攻撃の候補を区別する。前者は到達経路を調べ、後者は移動後に射程内にいる攻撃可能な敵だけを扱う。

1. 戦闘可能な敵を優先する。敗走敵を追うのは戦闘可能な敵がいない場合に限る。
2. 射程内の有効な指定敵があれば最優先で攻撃する。移動判断でも指定敵を最優先とするが、到達経路がなければ追跡不能を表示して代替候補を使う。
3. 指定敵が射程外の場合、進軍なら接近する。待機なら追わず、射程内の別の敵を攻撃する。立て直しは追跡より優先する。指定自体は対象が有効な間保持する。
4. 指定敵以外は既存の局所探索範囲を基本とする。近接・支援は距離3、射撃は距離4。ただし実際に攻撃できる射程内の敵を探索範囲だけで除外しない。
5. 候補内で担当区域を優先し、次に標的方針、四方向距離、同点順位の順で選ぶ。優先区域に候補がなければ他区域を使う。
6. 局所候補がなければ、到達可能な最寄りの戦闘可能敵へ向かう。全敵のHPだけを見て盤面の反対側へ集中しない。

射程外の「到達可能」は、現在の占有盤面で、射程に入るマスまでの経路が見つかること。拘束範囲を通る経路は到達不能とはせず、通常の足止めを受ける。経路なしでも射程内なら攻撃候補にできる。全候補が追跡不能ならそのtickは接近しない。

### 6.2 おまかせの標的方針

以下を上から判定し、最初に成立したものを使う。これは方針の選択であり、担当区域と候補制限は第6.1節に従う。

| 条件 | 方針 |
| --- | --- |
| 射撃・支援兵に敵近接兵が隣接 | 隣接する敵近接兵を自衛候補として最優先し、その中でHP優先 |
| 対騎兵特性があり、局所候補に敵騎乗兵がいる | 敵騎乗兵の中で近い敵を優先 |
| 重騎兵（手動・対騎兵など上記条件を除く） | 近い敵を優先し、低HPや低士気の後衛へ好機だけを理由に標的を変えない |
| 局所候補にHP割合40%以下または士気35以下の敵がいる | 該当する敵の中でHP優先 |
| 自衛が不要な射撃兵・通常騎兵 | 後衛優先 |
| 略奪騎兵・盾兵・その他の近接兵・支援兵 | 近い敵を優先。略奪騎兵にも上記の好機判断は適用する |

自衛候補は、おまかせの担当区域より優先する。手動の担当区域でも、攻撃目標がおまかせなら同じ自衛を行う。手動の指定敵や標的方針をAIが勝手に自衛へ書き換えない。

### 6.3 標的保持と陣形判断

- 通常は既存の標的保持期間（射撃2tick、その他3tick）を使用する。維持中は有効な現在標的を優先し、細かなHP差で乗り換えない。
- 手動の攻撃目標・区域変更、指定敵の無効化、おまかせの自衛開始は維持期間を待たず再評価する。自動のその他の好機は維持期間終了後に反映する。
- 既存の強さ1.5倍などの標的乗り換え条件をそのまま重ねない。本書の保持規則へ置き換え、方針ごとの優先と逆転しないようにする。
- 陣形判断、移動計画、移動後の攻撃は同じ標的方針の評価関数を使う。陣形判断の仮評価では標的ID・保持期間・乱数を変更しない。
- 移動後に射程内へ入った別の敵を攻撃することは許容する。同tickにAIの行動・標的方針・陣形を再決定しない。
- 複数部隊の集中攻撃を許可する。予定ダメージによる全軍の最適配分は追加せず、同tickの過剰集中も選択の結果として扱う。

## 7. 後退・立て直し・前線交代

### 7.1 敗走との区別

立て直し中も `status: active` とし、勝敗上は戦闘可能として扱う。敗走のような退出・恒久損耗・捕虜・周辺衝撃は発生させない。実際に敗走閾値へ達したら通常の敗走へ移り、立て直しの履歴と未適用指示を破棄する。

移動・回復の段階は別の `tacticalState` で表す。後方まで下がっても盤外へ出ず、`escaped` にしない。拘束・局所圧力の物理的な効果は実際の位置・人数・参加状態を使い、立て直し中だからという理由で消さない。

### 7.2 自動で後退を始める条件

脅威ありとは、開始時の敵通常攻撃の射程内、正の局所圧力、または前tickの実被害ありのいずれかとする。未来の艤装射撃は予測しない。

1. 士気20以下で脅威ありなら緊急後退を検討する。交代候補の有無・通常維持期間・再後退待ちを問わない。
2. それ以外は、脅威があり、士気35以下またはHP30%以下かつ前tickに被害ありなら後退を検討する。復帰後6tickの間は開始しない。
3. 通常後退の近接兵には交代候補を必要とする。候補は距離2以内の、自分以外の戦闘可能な味方近接兵で、士気45超・HP30%超・立て直し中ではなく、その敵との交戦を引き受けるマスへ経路があること。現在交戦している味方でも条件を満たせば支えとして数える。
4. 射撃兵・支援兵は交代候補を必須としない。自衛の必要性を優先する。
5. 安全位置への経路または現在地より危険を減らせる後退先がある場合に開始する。完全に塞がれている場合は現在地で通常行動を続け、「退路なし」を表示する。

複数の近接兵が同時に下がる判断で、互いを交代候補として数えない。まず後退希望を共通盤面から抽出し、希望部隊を除く味方を交代候補とする。交代候補1部隊が同tickに支えられる通常後退は1部隊までとし、士気の低い希望部隊、HP割合の低い希望部隊、同点順位の順で割り当てる。この仲裁は敵味方共通とする。

### 7.3 退路と安全位置

味方は左後方、敵は右後方を自軍後方とする。四方向の経路探索と通常の移動競合を使い、移動力・拘束範囲・占有マスの制約を守る。

- 安全位置は、自軍後方方向にある空きマスで、敵の拘束範囲外かつ戦闘可能な敵の通常攻撃射程外とする。現在地が既に安全ならその場で回復段階へ入る。
- 候補の順位は、退路中に敵拘束範囲へ入る回数が少ない順、経路長が短い順、味方近接兵の背後にある順、地形補正が高い順、同点順位とする。候補評価は未来の敵移動を予測しない。
- 安全位置がない場合は、敵の射程に入る数、局所圧力、最寄り敵までの距離の順で現在地より危険が減る後方の隣接マスを探す。それもなければ停止する。単に後端へ近づくためだけに危険を増やさない。
- 後退開始時に安全位置を保持する。占有・敵接近で無効になったときだけ再探索し、毎tick別の安全位置へ向かって往復しない。
- 後退中は射程を維持する必要がない。実際に移動したtickは通常攻撃しない。移動できなかったtickは通常条件に従い射程内へ攻撃できる。
- 敗走用の味方との場所交換は流用しない。通常後退で他部隊を強制移動させず、交代は空いたマスへの進軍で行う。
- 立て直し部隊はAIの前衛追随先・騎兵の接敵確認・交代候補から外す。盤面上の拘束や人数加重の圧力からは外さない。
- 交代候補の割当は後退を許可する判断にだけ使い、候補へ新しい指示を強制しない。候補が手動待機中ならその位置から支えられる場合だけ候補とし、移動を必要とする交代候補は進軍を許可されている部隊に限る。

### 7.4 回復と復帰

安全位置へ到達したら回復段階に入り、追撃せず待機する。敵が接近して安全でなくなれば退路を再探索する。停止中は射程内への攻撃を許可するが、被害を受ければ安全継続を数え直す。

- 士気回復量は既存の「3tick連続で被害なし・隣接敵なし、その後2／tick」を変更しない。本書の安全位置条件はそれより厳しく、敵射撃の射程内を安全な立て直し完了とは扱わない。
- 完了条件は、tick末の士気55以上かつ、敵通常射程外・被害なしを3tick連続で満たしたこと。自動復帰は次tick開始時に行う。
- HPは回復しない。HP割合を復帰条件に含めず、低HPのため永久に回復待ちになる状態を防ぐ。
- 行動がおまかせなら、完了後に現在の盤面から兵種別の進軍／待機を再判断する。後退前の座標へ自動で戻さない。騎兵の初動待機も再実行しない。
- 手動の立て直しは完了後も安全位置で待機する。「立て直し完了・手動指示待ち」と表示し、進軍・待機・おまかせへの変更で解除する。
- 手動で途中解除した場合は次tickから新指示を使う。士気・HP・攻撃待ち・陣形維持期間はそのままにする。
- 立て直し中も時間制限は進む。全員が手動待機・立て直しで継戦可能なら、通常どおり時間切れで引き分けとする。

## 8. tick内の処理順と既存作戦との関係

### 8.1 処理順

1. tickを進め、前tickの登場制限を解除する。受け付け済みの部隊指示を一括適用する。
2. 既存盤上部隊の開始時点の盤面を固定する。AIの行動・担当区域・標的方針、後退希望の仲裁をこの盤面から確定する。
3. 同じ開始盤面と確定した標的方針を使い、既存の部隊陣形を解決する。新陣形を使って標的方針を選び直さない。
4. 既存どおり予備隊を投入する。登場部隊は指示を初期化し、陣形を登場時の盤面で判断する。行動AIの通常判断は次tickから始める。既存部隊の判断を増援後にやり直さない。
5. 盤上全員の占有を使い、敗走、立て直し、既存の地形退避、距離維持、待機、通常接近・追随の順に、部隊ごとの移動計画を作る。
6. 既存の同時移動競合と拘束を解決する。行動種別が変わっても移動待ちの優先順位をリセットしない。
7. 移動後の盤面で通常攻撃を予約し、一括反映する。艤装射撃、士気・敗走、立て直し完了の記録、勝敗・時間切れの順に処理する。
8. 実際の行動変化・移動・攻撃を表示へ渡す。描画から判断履歴や乱数を変更しない。

登場tickの行動・拘束・局所支援なし、被攻撃可という制約を維持する。敗走は手動指示より優先し、待機・指定敵が敗走を止めることはない。

### 8.2 既存の全軍作戦

- 全軍の攻撃方針は部隊指示と二重に適用しない。既存UIの攻撃方針を「全味方へ攻撃目標を一括指示する」操作へ置き換える。
- 既存の `type` は新しい `auto` に移行する。ただし旧兵種固定ロジックとの完全一致を求める意味ではなく、戦況判断を含む新しいおまかせへ移行する。
- 距離維持設定、退避HP閾値、突撃抑制は全軍共通の移動設定として残す。既存の退避HP閾値は地形退避用とし、自動立て直しの初期閾値30%とは別の設定であることを説明する。立て直しの閾値をユーザー設定として増やすのは初期版では行わない。
- 行動が進軍でも、射撃兵は適切な距離から攻撃し、支援兵は前衛の背後へ追随する。進軍を全兵種の接近戦強制としない。
- 部隊陣形の手動指示は行動AIから変更しない。例えば盾壁固定のまま立て直しができる。

## 9. 一時停止・個別指示・一括指示のUI

### 個別操作

準備欄・味方部隊詳細に「行動」「攻撃目標」「担当区域」を置き、初期表示はすべて「おまかせ」とする。部隊陣形は独立した既存項目として残す。通常表示は指示・現在の行動・判断理由・HP・士気を優先し、担当区域や能力値などは詳細を開いて調整できる構成とする。

戦闘中に指示編集を始めると自動で一時停止する。単に部隊詳細を見るだけでは止めない。選択後も自動再開せず、既存の再開ボタンを使う。準備中は即時反映、開始後は次tick開始時に適用する。

指定敵は「敵を指定」から対象選択モードに入り、盤面または敵一覧で選ぶ。選択中は既存の味方選択・配置編集と区別し、キャンセルできる。モバイルでも敵一覧から同じ操作ができる。

### 一括操作

既存の全味方・近接兵すべて・5分類・個別兵種の対象抽出を共有する。操作は「対象」「変更項目」「指示」「N部隊へ指示」とする。行動だけ変えた場合、攻撃目標・担当区域・陣形には触れない。

- 一括の指定敵は同じ敵を選んだ対象部隊へ設定する。待機中の部隊を勝手に進軍へ変えない。
- 対象は実行時点の部隊で確定する。後から新しく編成した部隊への永続ルールは作らない。
- 前衛と未投入予備隊を対象にできる。敗走・撃破・退出・編成外の待機兵・敵は対象にしない。
- 「戦術をすべておまかせ」は行動・攻撃目標・区域の3項目を同時に戻す操作とし、部隊陣形を戻す既存操作とは区別する。

### 表示と予約

- 「行動：おまかせ／現在：待機／理由：射程内から射撃」「現在：後退／理由：士気低下」のように指示と実行状態を分ける。
- 手動立て直しの完了、追跡不能、退路なし、次tickから反映する予約を示す。
- 盤面の補助表示は選択部隊の指定敵・担当区域・後退先・敵拘束範囲に限定する。HP・士気・陣形記号を覆わず、色だけに頼らない。
- 同じ判断理由を毎tickログへ出さない。行動段階の変化、指定解除、立て直し完了を記録する。理由表示は判断を確定したときに更新する。
- 停止中はAI、騎兵の待ち時間、回復、安全継続、維持期間、乱数を進めない。指示を連続変更した場合、項目ごとに最後の予約で上書きする。
- 終了後の指示変更を無効にする。1・2・4倍速や拡大スクロールでも同じ指示・同じ結果になるようにする。

## 10. データ・初期化・保存互換

### 準備中に保持する情報

編成エントリへ `actionOrder`、`targetOrder`、`targetAreaOrder`、`focusEnemyId` を追加する案とする。既存の `rosterUnitId` で盤上部隊と対応させ、人数・レベル内訳・部隊陣形の指示は維持する。

新規編成・自動編成の各指示はおまかせ。既存エントリを維持する編成操作では有効な指示を保持し、新たに生じた部隊だけおまかせにする。準備中の指示編集は人数・配置の未反映判定から除外し、編成の再反映を要求しない。

### 戦闘中だけ保持する情報

実行時の行動段階 `advance`・`hold`・`withdrawing`・`recovering`、判断理由、次回AI変更可能tick、騎兵の初動待機履歴、後退先、立て直し中の安全継続、復帰後の再後退待ち、前tick被害、項目ごとの予約を別に保持する。`status`や既存の陣形情報へ混在させない。

指示をおまかせに戻しても騎兵の初動待機をやり直さず、陣形や攻撃の待ち時間を短縮しない。戦闘リセットで実行時情報を初期化するが、反映済みの準備指示は保持する。新しい遭遇へ実行時情報や指定敵IDを持ち越さない。

立て直しから手動で進軍・待機へ変える場合は後退先・完了待ちだけを解除し、復帰後の再後退待ちは開始する。おまかせへ変えた場合は未完了の立て直しを継続し、完了済みなら次tickに復帰する。指示モードの切り替えだけで回復済みと見なしたり、再後退待ちを短縮したりしない。

### 大会戦の保存

- `pendingEncounter.preparation.version`を4へ進め、前衛・予備隊の指示を保存する。乱数シード・地形・カスタム座標・兵員内訳は既存どおり保持する。
- 戦闘途中は引き続き保存しない。開始後の手動変更・後退先・安全継続・AI判断履歴は保存せず、再読込では保存済みの準備状態へ戻る。
- 版1〜3の部隊別指示がないデータは、行動・区域をおまかせへ補完する。旧全軍の攻撃方針が `hp`・`rear`・`strong`・`close` なら各部隊の手動攻撃目標へ移し、`type`または未設定ならおまかせへ移す。版4の有効な部隊指示は旧全軍値で上書きしない。
- 不正な列挙値は項目ごとにおまかせへ戻す。指定敵が味方・存在しない敵・未投入敵なら指定を解除する。
- 準備中の指定敵は保存された同じ遭遇の敵IDと対応させる。敵再生成・編成変更でIDの意味が変わった場合は解除し、同じ兵種という理由で別部隊へ付け替えない。
- 敵IDが現在の生成順に依存するため、版4には指定敵の検証用に遭遇と元の敵編成の識別情報も持たせる。元編成の順序・兵種・人数・レベルのいずれかが変わった場合は、同じID文字列でも指定を復元しない。描画順の変更だけではこの識別情報を変えない。
- 現在の残兵検証・編成上限・レベル内訳検証を維持する。指示の不備だけを理由に有効な兵員編成全体を破棄しない。

## 11. 実装の責務分割

`battle.js`と`battleCore.js`へAI条件・UI・保存変換を集中させない。

| モジュール | 責務 |
| --- | --- |
| 新規 `src/battle/battleTacticalOrders.js` | 指示定義、補完、準備・実行時の初期化、個別／一括予約と適用 |
| 新規 `src/battle/battleTacticalAI.js` | 共通盤面からの行動・区域・標的方針、後退希望と交代候補の仲裁。DOM・保存へ依存しない |
| 新規 `src/battle/battleRegroup.js` | 安全位置、退路、立て直し段階、完了条件 |
| 既存 `src/battle/battleTarget.js` | 指定敵・区域・標的方針・保持を共有する純粋な選択処理 |
| 既存 `src/battle/battleMovement.js` | 経路探索・占有・競合・拘束。後退でも物理ルールを共有する |
| 新規 `src/battle/battleTacticalOrdersUI.js` | 個別／一括の操作、対象選択、予約と理由の表示 |
| 既存 `src/battle/battleCore.js` | 判断・陣形・増援・移動・攻撃・士気・勝敗の順序を接続 |
| 既存 `src/battle/battle.js` | 編成・停止再開・保存・描画への接続 |

分類定義は既存の陣形一括指示と共有し、二重管理しない。必要な場合は共通の対象抽出モジュールへ切り出す。命名・分割は実装時に既存構成へ合わせて最小限に調整する。追加・変更する関数には日本語のJSDocを付け、AI優先順位と競合規則は関数単位で説明する。

## 12. 実装段階と受け入れ条件（第1〜4段階完了）

### 第1段階：指示・標的の共通基盤

行動・攻撃目標・区域、初期化、予約、標的の共通選択と仮評価を実装する。現行処理との比較に使える固定指示の検証条件を用意する。新AIが未完成の段階で通常プレイの既定動作だけを先に切り替えない。

### 第2段階：進軍・待機と基本のおまかせ

兵種別の接近・待機、騎兵の初動投入、自衛、手動優先を接続する。弓兵の待機・距離維持、支援兵の追随、両軍の待機膠着を重点確認する。

### 第3段階：立て直しと交代

後退希望の仲裁、退路、安全継続、復帰を接続する。HP自動回復なしで成立すること、味方を押しのけないこと、低HPによる前後往復と時間切れへの影響を確認する。

### 第4段階：操作・表示・保存・統合

個別／一括指示、指定敵の選択、補助表示、版4保存と旧版移行を接続する。すべての段階が揃った時点でおまかせを通常プレイの既定にし、実装済みの範囲だけ既存設計書とプレイヤー向けREADMEへ反映する。

### 必須の自動検証

| 観点 | 確認内容 |
| --- | --- |
| 初期値・手動優先 | 全項目おまかせ、項目別上書き、同兵種の異なる指示、無効値補完 |
| 待機 | 射程外へ接近しない、射程内へ攻撃、支援追随停止、地形退避で接近しない |
| 弓兵 | 待機でも距離維持、距離維持なし、退路封鎖、指定敵射程外でも代替標的で自衛、拘束離脱時は射撃不可 |
| 騎兵 | 接敵後投入、待ち上限、近接味方なし、待機中の接敵、自動復帰・モード変更で初動待機を再実行しない |
| 標的 | 方針・区域・自衛・指定の優先、局所候補なし、経路なし、指定無効化、標的保持、仮評価の副作用なし |
| 立て直し | 開始条件と境界値、交代候補の一対一割当、相互候補の禁止、安全位置探索、完全封鎖、味方を交換しない |
| 復帰 | 既存の士気回復量、低HPでも完了、手動は待機継続、自動は次tick復帰、再後退待ちと緊急後退 |
| 状態・勝敗 | 立て直しは戦闘可能、敗走へ移行したら復帰不可、盤外へ退出しない、全軍待機時の時間切れ |
| 停止・予約 | 次tick反映、項目ごとの上書き、停止中の履歴不変、陣形維持・攻撃待ちを短縮しない |
| 増援 | 未投入への指示、登場tick制限、前衛への判断を増援後にやり直さない、兵員精算の不変 |
| 保存 | 版1〜4、旧全軍指示移行、不正ID、同じ遭遇の指定敵、戦闘中変更を保存しない |
| 再現性 | 同シード同結果、配列順変更、左右交換の規則対称性、速度・描画による差なし |

既存の `npm test`、`npx eslint .` と戦闘シミュレーションを実行する。シミュレーションは現行の艤装・船種効果・可変盤面・増援条件を維持し、全おまかせ、手動の待機→進軍、片翼集中、盾兵交代、射撃中心、騎兵中心、退路封鎖を追加比較する。

勝率だけで判断せず、敵後衛への攻撃量、士気敗走、前衛の生存時間、後退・復帰の回数、退路停止、時間切れ率を記録する。多数シード・左右交換で比較し、改善を未計測の段階で断定しない。時間切れが増えた場合は、まずAIの待機・後退条件と経路を見直し、HPや制限時間の一括変更を前提にしない。

ブラウザでは準備→開始→停止→複数指示→再開→終了、指定敵の選択と解除、予備隊への指示、保存・再読込を通して確認する。8・10・12・15マスと各軍上限、PC／スマートフォン幅、拡大スクロールで操作と補助表示を確認する。

## 15. 攻撃目標を部隊ごとに設定するUI改訂案

状態：設計案・未実装。既存の部隊別指示データと戦闘計算を使い、攻撃目標を指定する入口・編集方法・表示を整理する。全項目の既定をおまかせとする方針は維持する。

### 15.1 設計の中心

攻撃指示は、必ず一つの味方部隊を選んでから設定する。「どの部隊へ出す指示か」を編集欄に常時表示し、他部隊への指示と混同させない。

| 項目 | 改訂後の扱い |
| --- | --- |
| 作戦カードの「全味方へ攻撃目標を一括指示」 | 削除する。距離維持・地形退避・突撃抑制などの共通設定は残す |
| 一括の攻撃目標・指定敵 | 削除する。複数部隊を選んで標的を設定する入口も作らない |
| 担当区域 | 攻撃目標を補助する個別設定へまとめ、一括変更から外す |
| 進軍・待機・立て直し | 個別設定に加えて一括指示を維持する |
| 部隊陣形 | 現行の個別／一括指示を維持する |
| 戦術をすべておまかせ | 個別の詳細操作だけに残す。一括操作では攻撃目標・区域をリセットしない |

担当区域の一括操作と全項目リセットの削除は、個別の攻撃指示が別の操作で上書きされるのを防ぐための設計提案。攻撃目標を個別にするというユーザー指示を、対象選択と表示の一貫性まで含めて具体化したものとする。

### 15.2 「狙い方」と「指定した敵」を区別する

現行の「攻撃目標」には、優先方針と具体的な敵の指定が混在している。編集項目は「狙い方」と呼び、選択肢を次のようにする。内部IDと判断規則は第3・6節のままとする。

| 狙い方の表示 | 内部ID | 補足 |
| --- | --- | --- |
| おまかせ | `auto` | この部隊の兵種と周囲の戦況からAIが判断する |
| 近い敵を優先 | `close` | 四方向距離が短い敵を優先する |
| HPの少ない敵を優先 | `hp` | 現在HPの少ない敵を優先する |
| 後衛を優先 | `rear` | 射撃役割の敵を優先する |
| 強い敵を優先 | `strong` | 既存の戦力評価を使う |
| 相手を指定 | `focus` | この部隊が優先する敵を一部隊選ぶ |

表示は「狙い方」「指定した敵」「現在の標的」を分ける。「後衛を優先」と設定していても、近くに後衛がいなければ別の敵と戦うことを正しく表す。

「相手を指定」は強制的な攻撃対象固定ではなく、既存どおり優先指定とする。待機中は追撃せず、立て直しは追跡より優先し、射程内の別の敵への攻撃も許可する。編集欄に「届く位置へ進軍します。待機・立て直しの指示は維持します」と説明する。

### 15.3 準備画面

編成の各行は、兵種・人数・部隊番号に加えて行動と狙い方の短い要約を表示する。各行へ全項目の入力欄を展開せず、「この部隊を設定」から共通の個別編集欄を開く。

表示例：

```text
第6部隊　弓兵　10人
行動：おまかせ　狙い方：後衛を優先
［この部隊を設定］
```

編成が未反映で盤上部隊がまだ存在しない場合も、`rosterUnitId`を使ってその編成エントリを編集できるようにする。指示だけの変更では編成の再反映を要求しない。前衛／予備隊の移動でも同じ部隊の指示を維持する。

### 15.4 個別編集欄

PCでは既存の戦闘詳細欄へ置き、スマートフォン幅では同じ内容を一列で表示する。表示順と操作は画面幅で変えない。

```text
指示する部隊：第6部隊　弓兵　10人
HP 288/288　士気 100

行動　　　　［おまかせ　　　▼］
狙い方　　　［相手を指定　　▼］
指定した敵　敵第9部隊　弓兵
［盤面から選ぶ］［敵一覧から選ぶ］

現在の標的　敵第3部隊　騎兵
［この部隊へ指示］

詳細設定　▶ 担当区域・陣形・個別リセット
```

- 「変更する項目」を選ぶ現行の操作をやめ、行動と狙い方をそれぞれ直接編集できる欄にする。担当区域・陣形・リセットは詳細にまとめる。
- 相手選択の欄は「相手を指定」を選んだ場合だけ表示する。おまかせや後衛優先のときに、無関係な敵一覧を常設しない。
- 部隊を切り替えたら、その部隊の適用中の指示と未適用の予約を読み込む。他部隊の選択値を引き継がない。
- 準備中も戦闘中も、編集した値は「この部隊へ指示」で確定する。変更していない項目へ予約を作らず、行動だけの変更で狙い方や区域へ触れない。
- 「相手を指定」で敵を未選択の場合は確定できない。「敵を選んでください」と表示する。
- 指示の予約後は「第6部隊：狙い方→敵第9部隊の弓兵／再開後の次のカウントで反映」と示す。
- AIが現在の標的を変更しただけでは、手動で設定した狙い方や編集途中の入力を変更しない。
- 「この部隊の狙い方をおまかせに戻す」は、狙い方と指定敵だけを戻す。行動・担当区域・陣形は維持する。
- 全戦術を戻す操作は詳細の「この部隊の行動・狙い方・区域をおまかせに戻す」と明記し、陣形のリセットと区別する。

### 15.5 戦闘中の相手選択

1. 盤面または味方部隊一覧から、一つの味方部隊を選ぶ。
2. 個別の指示欄を開くと一時停止する。詳細を見るだけでは止めない。
3. 「狙い方：相手を指定」から、盤面または敵一覧で候補を選ぶ。
4. 指示元と選択した敵を表示し、「この部隊へ指示」で確定する。
5. 他部隊にも必要なら個別に設定し、「戦闘を再開」を押す。

盤面で敵を押した時点では編集欄の候補を更新するだけとし、即座に予約しない。通常の敵クリックは引き続き敵の詳細を見る操作とし、明示的な相手選択モード中だけ候補選択として扱う。

編集中の指示元は部隊IDで固定する。カーソルを敵や別の味方に重ねても対象部隊は変えず、既存のホバー詳細から編集先が切り替わらないようにする。別の味方を明示的に選んだ場合は、その部隊の指示を読み直す。未確定の編集は予約として残さず破棄し、確定済みの各部隊の予約は保持する。

キャンセルで候補選択をやめても、適用中の指示と確定済みの予約は変えない。相手選択中に戦闘を再開できないようにし、指示の確定またはキャンセルで解除する。明示的にキャンセルした場合は元の狙い方・指定敵へ戻す。

### 15.6 敵と現在の標的の表示

- 敵の表示は内部ID文字列ではなく「敵第9部隊　弓兵」のような名前にする。同兵種が複数いても区別できる番号を、撃破や一覧の並び替えで変更しない。
- 予備隊は「敵予備第3部隊」のように区別し、登場後も同じ識別を使う。未投入の敵は相手候補に含めない。
- 敵一覧は部隊番号・兵種・残HP・士気・盤面位置を表示し、選択中の候補を明示する。PCもスマートフォン幅も一覧から選べる。
- 選択中の味方と指定敵を枠と線で結ぶ。実際の攻撃演出と区別するため「指定」のラベルを付ける。
- 「現在の標的」は有効な`targetId`の部隊を表示する。指定敵と違う場合は「指定敵は射程外」「追跡できないため近くの敵に対処」など、分かる範囲の理由を添える。移動先の選択を「攻撃中」と断定しない。
- 指定敵が撃破・敗走・退出した場合は既存どおりおまかせへ戻し、対象の名前と解除理由を表示する。準備中の盤面再生成や保存復元で相手を失った場合も、別部隊へ自動で付け替えない。

### 15.7 一括操作と保存

一括の戦術欄は「まとめて行動を指示」に改称し、進軍・待機・立て直し・行動のおまかせだけを扱う。既存の全味方・兵種系統・個別兵種の対象選択は、この行動指示と陣形指示に利用する。攻撃目標・区域・全戦術リセットを一括の選択肢に出さない。

内部では攻撃指示を単一部隊へ出す処理と、複数部隊への行動指示を分ける。UIで隠すだけにせず、攻撃指示の入口へ複数対象が渡された場合は適用を拒否し、先頭部隊だけへ黙って適用することも避ける。

指示データの`targetOrder`・`focusEnemyId`・`targetAreaOrder`と、版4の準備保存は維持する。UI改訂だけを理由に保存版を進めたり、既存の個別指示を初期化したりしない。旧版の全軍方針は既存どおり読み込み時に各部隊へ一度移行し、それ以後は部隊別の値として扱う。新しい準備保存に共通の攻撃目標を書き込む必要はなく、旧`strategy.targetMode`は旧版の読み取り互換だけに限定する。

## 16. 騎乗兵の役割別AIへの変更（2026-10-15）

ユーザーの指示により、通常騎兵は投入待ちと後衛攻撃、重騎兵・略奪騎兵は攻撃を受ける前衛として方針を分けた。第5.3・6.2節に現行の条件を反映した。第15節の個別攻撃UI改訂案は今回の変更範囲に含めず、未実装のまま維持する。

- 通常騎兵は既存の最大4tickの初動待機と早期解除条件を維持する。重騎兵・略奪騎兵は初動待機を行わない。
- 重騎兵は近い敵を優先する。略奪騎兵は近い敵を基本とし、低HP・低士気の敵への既存の好機判断を使う。射撃兵・他の近接兵の方針は維持する。
- 味方・敵に同じ規則を適用する。手動の行動・攻撃目標、既存の立て直し、騎乗属性による移動・特効・陣形の処理を維持する。能力値・保存形式・UIの設定項目は変更しない。
- `battleTacticalOrders.test.cjs`へ、3兵種×両陣営の初動と実移動、健康な後衛と近い敵の選択、弱った敵に対する重騎兵／略奪騎兵の違い、手動指示、立て直し、重騎兵・略奪騎兵の接敵による通常騎兵の早期投入を追加する。
- 追加した検証を含む`npm test`は全項目成功。`npx eslint .`はエラーなし、今回変更していない釣りUIの警告1件。戦術28条件も完走し、24条件が時間切れだった。艤装・船種効果・可変盤面・増援の80条件は58条件が時間切れ、平均56.875tickだった。これらは機能・不変条件の検証であり、少数シードの結果から兵種の勝率や最終バランスを断定しない。

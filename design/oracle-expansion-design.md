# 神託の種類追加 設計書

作成日: 2026-10-15  
状態: 実装済み。ユーザーの実装開始指示を受け、本書の提案値を初期値として採用。自動検証は `tests/oracleExpansion.test.cjs` と既存テストで行う。

## 1. 目的と仕様の位置付け

既存の釣り・物資運搬・拠点訪問・自然探索・潮盟支援を使い、神託によって旅の目的と行動に変化を付ける。新しい戦闘形式や施設は追加しない。

- **確定**: ユーザーが指定した追加方針。変更にはユーザーの指示が必要。
- **採用した初期値**: 未指定だった数量・抽選の詳細・進捗管理・失敗時の扱いは、本書の推奨案に従って実装した。ユーザーが直接指定した数値とは区別する。
- 現行の仕様は [全体設計](design.md)、関連仕様は [釣り詳細](fishing-design.md)、[探索・海図・艤装](expansion-design.md)、[潮盟拠点](tide-alliance-design.md)、[危険海域](dangerous-seas-design.md) を参照する。
- 実装した内容をゲームのREADMEと全体設計へ反映する。今後の調整では本書と `ORACLE_CONFIG` を合わせて更新する。

## 2. 現行仕様と維持する前提

`src/quests/quests.js` に、以下の5種類がある。

| 神託 | 条件 | 基本信仰報酬 |
| --- | --- | --- |
| 糧を捧げよ | 指定された加工品2種類を奉納 | 5面ダイス4個の合計 |
| 動け | 指定された海上の座標へ移動して完了 | 同上 |
| 人身を捧げよ | 指定兵種を1人奉納 | 同上 |
| 奪え | 指定地点の敵に勝利 | 同上 |
| 越えよ | 指定地点の強編成に勝利。信仰100以上で抽選対象 | 5面ダイス5個の合計 |

- 季節につき1件をランダム受領する。未完了の神託があれば次の神託を受領できない。
- 期限は受領から90日。期限当日は有効で、超過すると失敗する。
- 基本報酬へ、報酬確定時点の季節の潮盟補正を適用し、最後に一度切り捨てる。
- 「動け」は通常、現在地から縦横の距離10〜15マスの海・浅瀬を選ぶ。候補不足時の範囲拡張を含め、今回の15マス制限を既存神託へ遡って適用しない。
- 新しい神託も選択制にはしない。通常神託で危険海域への移動を要求しない。

## 3. ユーザー確定の追加方針

| 神託 | 確定した方針 |
| --- | --- |
| 海の恵みを捧げよ | 魚種を指定せず、一般魚・大物などの分類と匹数で要求する。奉納対象の優先順は値段を基準にする |
| 祈りを巡らせよ | 対象となる拠点が15マス圏内にある場合のみ生成する |
| 分かち与えよ | 対象となる拠点が15マス圏内にある場合のみ生成する |
| 漂流物探索の神託 | 対象となる漂流物が15マス圏内にある場合のみ生成する |
| 潮盟支援の神託 | 対象となる潮盟拠点が15マス圏内にある場合のみ生成する |

魚種の出現運や季節限定の生息条件によって、指定魚を入手できなくなる形式は採用しない。以下は、この方針を具体化して実装した仕様を示す。

## 4. 追加神託の共通規則

### 距離と候補の固定

- 受領時の現在地を基準とし、既存の `manhattan` と同じ `|x差| + |y差|` で15以下を圏内とする。斜め方向を1マスとして数えない。
- これは座標の距離であり、障害物を回り込む実際の移動日数を保証する値ではない。通常の移動で到達できない地点は候補から除外する。
- 受領時に対象の拠点ID・地点ID・座標を固定する。移動や季節更新で対象を抽選し直さない。
- 圏内に候補がなければ、その種類を抽選候補へ入れない。遠方への範囲拡張や、条件を満たす地点の新規生成は行わない。
- 通常の街・村を対象とし、無法港、危険海域への進入を必要とする地点、受領時点で入場・必要行動が禁止されている拠点は除外する。
- 受領後の手配・勢力関係などによる利用制限は既存ルールに従う。神託を理由に制限を免除しない。

### 種類・対象の抽選

1. 既存の受領条件を確認し、現在地・日付・資産・地点の状態から新種類の候補を列挙する。
2. 生成可能な新種類と既存種類を合わせ、種類単位で等確率に1種類を選ぶ。
3. 選ばれた種類の有効な対象から等確率で対象を選び、必要数量・基本報酬を固定する。
4. 依頼追加と今季の受領記録を一括して確定する。生成できなかった場合は受領枠を消費しない。

同じ種類に対象が多数あっても、その種類自体の出現率は増やさない。魚の一般魚型・大物型も独立した神託種類として抽選枠を増やさない。

新種類の期限は90日、基本信仰報酬は既存の通常神託と同じ5面ダイス4個の合計を初期値とする。資金・名声・国力の追加報酬は設けない。

## 5. 海の恵みを捧げよ

内部ID: `oracle_fish`。

### 要求と生成条件

- 一般魚 `common` を5匹、または大物 `big` を2匹のいずれかを生成時に固定する。有効な2形式は等確率で抽選する。
- 超大物 `giant` は要求・代用の対象に含めない。大物を一般魚の代わりに消費することもない。
- 魚介の名前や生物分類ではなく、`FISH_SPECIES` の `category` を使用する。
- 竿所持時のみ生成する。現在地から危険海域を通らずに到達できる通常海域で、要求分類を全4季節それぞれに釣れるか、魚種定義と地図から確認する。いずれかの季節に釣れる候補がない形式は除外する。既に必要数を所持している形式は生成可能とする。
- 特定の魚種・サイズ・釣った場所・受領後の釣獲という条件は付けない。季節をまたいでも分類と匹数を維持し、受領前の釣果も奉納できる。

### 奉納順と完了

1. `state.expansion.fishing.counts` から、要求分類に属する既知の魚種と所持数を集める。
2. 既存の `fishSalePrice(state, species)` による現在の売却単価が安い順に並べる。同額なら内部の魚種IDの昇順とし、乱数を使わない。
3. 安い魚種から必要数だけ割り当てる。1魚種だけで不足する場合は次の魚種へ進む。
4. 分類全体の所持数が不足する場合は完了不可。一部だけを先に奉納しない。
5. 奉納内訳を確認画面へ表示し、確定時に在庫と単価を再検証する。状況が変わった場合は内訳を更新して再提示する。
6. 成功時に釣果の所持数だけを減らし、信仰付与と依頼完了を一括確定する。

釣果は魚種別の匹数管理であり、個体のサイズ別には選別しない。図鑑の発見・釣獲回数・最大サイズ・航海統計・解放済み報酬は減らさない。奉納を売却や食料加工として記録しない。

表示例: 「一般魚を5匹捧げよ。魚種は問わない。売値の安い釣果から奉納する。」

## 6. 分かち与えよ

内部ID: `oracle_share`。

- 受領地点から15マス以内の通常の村を1つ指定する。現在地の村も候補に含める。
- 初期実装は食料10を届ける形式のみ。原料・加工品の複数形式は初回には追加しない。
- 配達用の物資は支給せず、手持ちの食料を使用する。食料の入手方法は問わない。
- 対象の村に入った状態で、依頼欄から完了する。座標を通過するだけでは完了しない。
- 食料の消費・信仰付与・依頼完了を一括確定する。村への支持や国力は追加しない。
- 食料は航海にも必要なため、確認画面に奉納量と奉納後の残量を表示する。

表示例: 「○○村の人々へ食料10を分かち与えよ。」

## 7. 祈りを巡らせよ

内部ID: `oracle_pilgrimage`。

- 受領地点からそれぞれ15マス以内にある、異なる通常の街・村を2か所指定する。
- 現在地の拠点は対象から除外し、受領後の入場を記録する。対象への訪問順は問わない。
- 長い往復を避けるため、2拠点間の距離も15以下とする。この条件を満たす組がなければ生成しない。1拠点の巡礼へは変更しない。
- 有効な拠点の組を重複なしで列挙し、組単位で等確率に選ぶ。
- 各拠点へ入る処理が成功した時点で、その拠点を訪問済みにする。画面の再描画や潮盟画面を開く回数では数えない。
- 訪問済みは依頼内に保存し、季節更新やロードでも維持する。既に滞在中に神託を受けた場合の遡及達成は行わない。
- 2か所目の入場時に自動完了する。元の受領地点への帰還は要求しない。

表示例: 「○○と△△を訪れ、祈りを巡らせよ。順序は問わない。」

## 8. 沈みしものを拾え（漂流物探索）

内部ID: `oracle_explore`。

- 受領地点から15マス以内に存在する、通常の自然探索の漂流物 `drift` を1つ指定する。
- 初回は漂流物だけを対象とし、難破船・戦場跡・海図・危険海域の専用探索は含めない。
- 探索中または消滅済みの地点は除外する。座標に加えて地点IDを固定し、同じ座標へ後から生まれた別地点では達成できない。
- **自然消滅対策**: `expiresAbs > deadlineAbs` を満たし、神託の期限当日まで残る地点だけを候補にする。既存の地点寿命は延長しない。
- 現行の地点寿命は生成から120日なので、90日の神託に指定できるのは比較的新しい漂流物に限られる。このため圏内でも抽選対象にならない場合がある。出現頻度を増やす調整は別途判断する。
- 指定地点の探索で、非戦闘の報酬確定または戦闘勝利に至れば自動完了する。通常の探索報酬に信仰報酬を加える。
- 戦闘敗北・引き分け・逃走などで地点が消費され、探索報酬を得られなかった場合は神託失敗とする。対象がなくなった依頼を残さない。
- 既存の探索経路から指定地点を探索した場合も判定する。専用の探索ボタンや別の敵・報酬抽選は追加しない。
- 探索終了と神託終了の通知は既存の探索処理の後に表示し、探索・戦果画面へ別イベントを割り込ませない。

表示例: 「指定地点の漂流物を調べ、海に残されたものを拾え。」

## 9. 祈りを支えよ（潮盟支援）

内部ID: `oracle_support`。

- 受領地点から15マス以内の通常の街・村にある、既存の潮盟拠点を1つ指定する。現在地の拠点も候補に含める。
- 対象は `state.tideAlliance.sites` に記録がある拠点とする。「まだ名のない集い」も含め、祠の完成や今季の恩恵対象上位5拠点という制限は付けない。
- 初期条件は、受領後に対象拠点へ「資金2,000以上」または「担い手1人以上」を支援すること。どちらでも達成でき、資金は複数回の支援を合算する。
- 資金と人数を相互換算しない。担い手の兵種・レベルは既存の支援操作でプレイヤーが選ぶ。
- 受領前の累計寄付・累計人数では達成しない。他拠点への支援も数えない。
- 指定拠点で通常の支援が成功する際に依頼内の進捗も更新し、必要量に達したら自動完了する。施設の段階が上がることは要求しない。
- 支援そのものは通常どおり拠点の累計へ加算する。今季の固定済み恩恵を再計算せず、神託報酬には報酬確定時の季節補正を使う。
- 神託期限を超過した場合も、既に成功した支援や拠点の成長は取り消さない。

表示例: 「○○の潮盟へ資金2,000、または担い手1人を送り、祈りを支えよ。」

## 10. 画面・保存・処理の接続

### 表示

- 既存の依頼一覧へ「神託」として追加する。期限・基本報酬・今季の報酬見込みを既存形式で示す。
- 魚は要求分類と必要数／所持数、施しは食料と必要数／所持数、巡礼は拠点別の訪問状態、探索は対象地点と戦闘確率、潮盟支援は受領後の資金／人数の進捗を表示する。
- 目的地の表示・地図ピン・場所確認は既存の仕組みに接続する。巡礼は未訪問の目的地を確認できるようにする。
- 手動完了する奉納・施しには消費内容の確認を用意する。自動完了する種類は、達成につながる行動の案内を表示する。

### 保存と整合性

- 依頼は既存の `state.quests.active` に格納する。共通で内部ID、受領日、期限、基本信仰報酬を保存する。
- 魚は要求分類・必要数、施しは拠点ID・座標・食料数、巡礼は対象拠点ID・座標・訪問状態、探索は地点ID・座標、支援は拠点ID・座標・必要量・受領後の支援実績を保存する。
- 旧セーブには新しい神託を自動追加せず、既存依頼の内容・期限・受領済み季節を維持する。
- 新種類も「神託受領中」の判定へ含め、同時に複数受領できないようにする。
- 神託受領・手動奉納・巡礼の訪問・潮盟支援・非戦闘探索では、元の行動と神託の進捗・報酬・完了状態を一括保存し、保存失敗時は今回の変更を戻す。
- 探索戦闘では既存の戦後処理と同じ保存単位へ含める。戦後保存に失敗した場合は既存仕様どおり結果を現在の旅に保持し、画面を閉じず再保存するよう警告する。神託だけを先に別保存しない。
- ロード後は依頼一覧を取得する際に保存値と固定対象を検証する。不正・消滅対象の神託は理由を通知して失敗終了する。
- 読み込みや途中再開で同じ結果を適用し直しても、在庫消費・進捗・信仰報酬を重複させない。
- 不正な新種類の保存データは、対象や必要量を無作為に補完しない。達成不可の理由を表示して失敗として終了し、追加消費や報酬は発生させない。

## 11. 実装時の検証項目

- 距離15は候補、16は候補外。斜め方向も縦横の合計で判定し、候補不足時に距離を広げない。
- 巡礼は2拠点とも圏内かつ拠点間の距離条件を満たす。対象不足なら生成しない。
- 候補数が多い種類ほど出やすくなる抽選になっていない。候補なしや生成失敗で季節枠を消費しない。
- 魚は同分類の複数魚種を合算し、売却単価の安い順・同額なら内部ID順で必要数だけ消費する。分類違い・超大物・図鑑記録には影響しない。
- 魚の不足時は一部消費しない。既存釣果で達成でき、季節をまたいでも魚種指定へ変わらない。
- 施しは指定村への入場と必要食料を検証する。別村・村の外・食料不足では完了しない。
- 巡礼は受領後の異なる2拠点への入場のみを数え、再描画・同じ拠点への再入場・ロードで訪問数が増えない。
- 漂流物の寿命が神託期限を覆うことを境界値で確認する。同じ座標の別地点で達成しない。
- 探索は非戦闘成功・勝利で達成し、地点を失う非成功結果では神託を失敗終了する。探索報酬や信仰を二重付与しない。
- 潮盟支援は指定拠点への受領後の成功分だけを合算する。過去の支援・他拠点への支援・保存失敗分では進まない。
- 季節をまたいだ報酬の補正、期限当日と翌日、未完了神託による受領制限、旧セーブ・途中再開・保存失敗時の復元を確認する。

## 12. 採用した初期値と今後の調整

実装開始時に以下を初期仕様として採用した。プレイ後の数量・頻度の調整は別途行う。

- 魚は一般魚5匹／大物2匹。有効な形式から等確率に選ぶ。
- 施しは食料10、潮盟支援は資金2,000または担い手1人。
- 生成可能な新種類と既存種類は等確率。基本報酬は通常神託と同じ5面ダイス4個の合計。
- 巡礼は2拠点。受領地点から各15マス以内に加え、拠点間も15マス以内。
- 漂流物は残存寿命が神託期限を覆う地点だけを対象とする。地点生成率や寿命は変更しない。

ユーザー確定の「魚種を指定しない」「値段による奉納優先」「各対象は15マス圏内にある場合のみ」という方針は、これらの調整と分けて維持する。

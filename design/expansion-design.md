# 探索・海図・船の艤装 設計書

本書は探索・海図・艤装を扱う。通常船種・造船所・船取引は [船種・造船所](shipyard-design.md)、戦闘基盤・勝敗・戦後精算は [戦闘基盤設計](battle-redesign.md) に集約する。釣りは [釣り詳細](fishing-design.md)、危険海域の例外は [危険海域](dangerous-seas-design.md) を参照する。

## 1. 目的と方針

漂流物・難破船・戦場跡の探索と、断片を集めて目的地へ向かう海図で航海の目的を増やす。探索報酬は名声で拡大せず、戦闘の報酬と区別する。艤装は船団共通の装備とし、限られた枠の中で攻撃・防御・兵站を選ぶ。

出現率・報酬・価格・設備効果は `src/core/expansionConfig.js` の共通定数に集約する。表示・精算・保存で同じ定義を使い、保存済みの抽選結果は再表示や読み込みで変えない。

## 2. 共通の前提

- 地図は50×50の正方形マス、拡大表示は9×9。移動は上下左右1マスで1日。
- 1季節30日、1年120日。探索地点の寿命・噂履歴には絶対日を使う。
- 現在地は白枠、選択中のマスは黄色枠。新要素でも色の意味を変えない。
- 海上の現在地は船、陸上は枠なし部隊アイコン。街・村では建物中央、部隊左下。
- 神託は選択制にしない。調達依頼の重複、市場の季節更新も維持する。
- 戦闘は1tick＝ゲーム内1秒、最大60tick。表示速度1／2／4倍は現実の進行速度だけを変更する。
- 防御軽減の基本式は `max(1, round(有効ATK * 100 / (100 + 有効DEF)))`。有効DEFには地形補正が含まれる。通常攻撃には兵種特効と陣形補正も適用するため、最終ダメージは [戦闘基盤設計](battle-redesign.md) と [部隊陣形](battle-unit-formations.md) に従う。
- 部隊数ではなく兵員を保有し、戦闘時に部隊を編成する。固定の部隊名・戦歴は追加しない。
- 物資・兵員上限は、基本容量に船種別の容量を合算して艤装などの割合補正を適用する。[船種・造船所](shipyard-design.md) の共通計算に従う。
- 現在の食料消費日は10・30日、必要量は全兵員数÷4の切り捨て。維持費は季節1日に兵種別費用を合計する。

## 3. 漂流物・難破船・戦場跡

### 3.1 基本仕様

| 項目 | 内容 |
| --- | --- |
| 配置数 | 漂流物・戦場跡は共通で最大5個、難破船は別に最大2個 |
| 出現 | 毎日確率で出現。最大数に達している場合は出現しない |
| 寿命 | 出現から120日で自然消滅 |
| 漂流物／戦場跡報酬 | 資金500前後＋高級品2種類・合計3個前後。名声等でスケールしない |
| 難破船報酬 | 資金・高級品は上記の倍。加えて部隊員と確率で船。報酬はスケールしない |
| 出現頻度 | 漂流物／戦場跡は2季節に3件程度、難破船は半年に1件程度 |
| 初期配置 | 漂流物・戦場跡・難破船を各1件 |
| 戦闘確率 | 0%・25%・50%・75%・100%の5段階。段階別にダイアログの案内を変える |
| 敗北・逃走・引き分け | 報酬なし。探索地点も消滅 |
| 陸上の名称 | 漂流物に相当する地点を「戦場跡」と表示 |
| 探索 | 1日消費。確率で戦闘。戦場跡・漂流物は通常編成、難破船・危険海域内は賞金首相当 |
| 表示 | 種別ごとに地図アイコンを追加 |

### 3.2 配置・寿命

- 漂流物と戦場跡は共通枠として合計5個。難破船は別枠2個。上限値は定数化する。
- `sea`／`shoal` に漂流物と難破船、それ以外の非拠点地形に戦場跡を置く。
- 街・村、既存探索地点、海図の目標地点と重ねない。依頼の固定戦闘地点とも可能な限り重複を避ける。
- 毎日、期限切れ地点の除去→種別ごとの出現判定→配置の順。1日につき共通枠・難破船枠それぞれ最大1件を生成する。
- `expiresAbs = spawnedAbs + 120` とし、`today >= expiresAbs` で消滅。候補地がなければその日の生成を見送り、無制限な再抽選をしない。
- 探索開始済みの地点は予約状態にし、日付進行や戦闘中に自然消滅させない。
- 初期配置は各種1件。旧セーブへの初回導入でも一度だけ生成し、再読み込みで補充しない。
- 出現頻度は漂流物・戦場跡の合算。1年120日のため2季節・半年はいずれも60日。漂流物／戦場跡の共通枠は1日5%（3/60）、難破船は1日1/60（約1.67%）とする。上限や候補地不足で見送る分を除く期待値であり、期間内の出現数を保証しない。
- 漂流物／戦場跡を各50%で選んでから適合地形に配置する。

### 3.3 探索の進行

1. 現在地が探索地点なら行動欄に「探索する」を表示する。
2. ダイアログで名称、残存日数、所要1日、戦闘の可能性を表示する。
3. 確定時に地点を予約し、結果・敵・報酬候補を一度だけ抽選する。
4. 1日進行させる。維持費・食料消費は通常どおり適用する。
5. 敵がいなければ探索報酬を付与。敵がいれば既存の戦闘準備へ移る。
6. 戦闘勝利後に探索報酬を付与し、地点を消去する。
7. 結果ダイアログを閉じて通常画面へ戻り、完了状態を保存する。

敵が出た場合の探索報酬は勝利まで保留する。敗北・逃走・引き分けは探索報酬なしで地点を消去する。通常戦闘の報酬・損耗・昇級などは既存どおり処理し、勝利時には通常戦闘報酬と探索報酬を併給する。スケールしないのは探索報酬のみであり、通常戦闘の報酬計算は変更しない。結果画面では両者を区別する。

探索中に日次の別イベントが発生する場合はキューへ積み、探索の戦闘と二重に開始しない。危険海域の日次危険との割込みは [危険海域](dangerous-seas-design.md) の処理順に従う。

### 3.4 報酬・上限超過

- 資金・高級品は名声・敵人数・季節・経過日数に依存しない。敵の強さを報酬額の計算に流用しない。
- 漂流物／戦場跡は資金450～550、高級品は重複なしで2種類を選び合計2～4個。難破船は資金900～1100、高級品合計4～8個。資金・合計数は範囲内の整数を一様抽選し、高級品は両種に最低1個を割り当ててから残りを1個ずつ2種均等に抽選して加算する。
- 難破船の救助兵員はLv1・合計3～5人、船は20%で1隻。救助兵種は全兵種から兵員1人ごとに均等抽選する。救助報酬も名声や敵人数に依存させない。
- 戦闘確率は地点生成時に固定し、5段階を各20%で抽選する。探索ダイアログを開き直しても変えない。

| 戦闘確率 | 現地・確認画面の表示 |
| --- | --- |
| 0% | 戦闘確率0% |
| 25% | 戦闘確率25% |
| 50% | 戦闘確率50% |
| 75% | 戦闘確率75% |
| 100% | 戦闘確率100% |

危険の形容文を重ねず、確認画面では所要日数・期限・戦闘確率を項目で表示する。戦闘のある地点だけ、失敗時の報酬・地点消失を添える。詳しい進め方と日次消費はガイドで説明する。

- 0%は必ず非戦闘、100%は必ず戦闘。地点自体の危険と日次の別イベントを区別する。
- 難破船の部隊員を既存戦闘の拿捕分と混同しない。結果では「救助した兵員」など獲得元を分ける。
- 船を先に加算して上限を再計算し、その後に物資・兵員を加算する。
- 上限超過時に報酬を黙って切り捨てない。超過量と破棄・解雇への導線を表示し、既存の移動制限を適用する。

## 4. 海図の断片と発見

### 4.1 基本仕様

- 3枚で完成する海図と5枚で完成する海図があり、各サイズにつき最大1件、合計最大2件を同時進行する。
- 戦闘報酬では超低確率、依頼報酬では低確率で、資金の代わりに断片を獲得する。依頼は受注前に断片報酬だと分かるようにする。
- 断片への置換確率は戦闘勝利時0.5%、資金報酬のある依頼の生成時3%。定数で管理する。
- 行商人救助は成功時20%で断片1枚を追加謝礼として付与する。当落は救助の戦闘開始前に固定して遭遇へ保存し、敗北・引き分け・逃走では付与しない。通常の資金報酬と救助の謝礼は維持する。
- 危険海域の「海底からの鐘」「亡霊船団の帰港」は最終段階の報酬へ断片1枚を確定追加する。亡霊船団は両結末で共通、途中辞退では付与せず、事故で断片を減らさない。詳細は [危険海域](dangerous-seas-design.md) を参照する。
- 上記の追加断片は既存海図を優先して未予約枠へ割り当て、依頼・噂の予約は消費しない。割当不能なら断片を付与せず、他の報酬は通常どおり受け取る。保存済みイベントの固定報酬へは遡及追加しない。
- 村・街に入るとランダムで断片の噂が発生し、拠点からおよそ10～15マス離れた地点に取得地点を配置する。
- 同じ拠点で足踏みして噂を繰り返せないようにする。噂から得られる断片は同じ海図につき最大1枚。
- 断片獲得時にダイアログを表示。最初の断片では何が記されているかも知らせる。
- 進捗は依頼欄の下側に専用領域として常時表示し、海図の内容をいつでも確認できるようにする。
- 海図は次の3種類。完成報酬には少量の名声も付く。

| 海図 | 3枚の報酬 | 5枚の報酬 |
| --- | --- | --- |
| 古い祭壇 | 信仰90～110（100±10%） | 信仰180～220（200±10%） |
| 隠れた入り江 | 高級品5種類へランダム配分・合計100＋船2隻 | 高級品5種類へランダム配分・合計200＋船4隻 |
| 財宝の隠し場所 | 資金23,750～26,250（基準25,000） | 資金47,500～52,500（基準50,000） |

共通の名声は3枚版が9～11、5枚版が18～22。範囲内の整数を一様抽選する。

### 4.2 進行モデル

`collecting（収集中）→ located（完成・場所判明）→ exploring（現地探索中）→ completed（報酬獲得済み）`

報酬獲得済みとなった海図は `voyageStats.chartsCompleted` に1件加算する。断片完成・噂回収では加算せず、再開・再表示・保存復元でも重複しない。累計10件で最終航海の探奥神話を解放する。旧セーブの過去の回収数は復元せず、追加後から計測する。詳細は [最終航海・航海統計](final-voyage-design.md) を参照する。

[海賊王の海図](pirate-king-story-design.md) は専用の物語進捗で扱い、海図達成数と探奥神話には含めない。専用の噂確率も通常海図とは別設定とする。

- 初回の断片で海図ID、種類、必要枚数を確定する。同じ種類の3枚版と5枚版の並行は許容する。予約が先に発生した場合の内部IDは予約時に確定し、初回獲得時に内容を通知する。
- 海図は通常依頼と同じスクロール領域の末尾に配置し、依頼一覧の折りたたみに追従する。獲得前は信仰・高級品・船・資金・名声のうち該当する種類だけを表示し、数量・範囲・高級品の種類数は明かさない。完成時に最終地点を明かし、現地へ赴いて報酬を得るまで枠を保持する。獲得結果では実際の数量を表示する。
- 完成地点にも共通の探索地点モデルを使う。ただし120日消滅やランダム戦闘を自動適用しない。
- 噂地点・完成地点の寿命は無期限。完成地点に到着後、1日使って探索し、追加戦闘なしで報酬を獲得する。通常の日次維持費・消費は適用する。
- 依頼欄の海図領域は上部へ割り込ませない。スクロールで通常依頼を隠す固定オーバーレイにはしない。見出し・枚数・種類を簡潔に常設し、説明は展開表示する。
- 噂だけが先に発生した場合の表示は「噂の手掛かり」とし、断片を取得した扱いにはしない。

### 4.3 噂・自然探索・海図販売

- 噂は季節初回入場5%。自然探索の断片は漂流物・戦場跡5%、難破船10%。探索開始時に当落を保存し、探索成功時のみ付与する。通常の戦闘断片抽選も維持する。
- 海図売り: 移動イベントの共通クールダウン・優先順に従い、災いの兆しの直後に1%で抽選。1000資金で本物25%。古文書商: 街ごとの季節初回入場10%、2000資金で本物50%。村では出ない。
- それぞれの購入元から同じ海図に本物1枚まで。偽物では取得上限を消費しない。候補と当落をイベントに保存し、購入時は予約・取得上限・資金を再検証する。未予約枠がなければ販売イベントは出さず、購入前に条件が変わった場合も資金を消費しない。販売は予約枠を新設せず、既存の依頼・噂の予約を優先する。

- 入場判定は実際の村・街への入場時だけ。モーダル開閉や再描画では抽選しない。
- 同じ拠点では季節に1回だけ抽選する。不発でも抽選済みと記録する。
- 発生率は季節初回入場で5%。進行中の海図を優先し、新規なら空いているサイズ枠と3種類から均等抽選する。対象が2件ある場合は均等抽選し、予約だけの海図も進行中として扱う。
- 同じ海図に未回収の噂地点がある間は、2つ目を配置しない。
- 噂の断片は現地回収を必須とし、他経路の断片で予約枠を埋めない。カードは取得済み・依頼予約・噂予約を区別する。
- 海図単位で `rumorFragmentClaimed` を記録し、1枚取得後はその海図の噂を生成しない。
- 調査地点までの距離は上下左右移動の最短距離で10～15マス。候補地がない場合は生成を見送る。
- 噂地点での断片回収は1日消費・追加戦闘なし。通常の日次維持費・食料消費は適用する。
- 3枚／5枚の両枠が進行中なら、その中の噂未取得・収集中の海図を対象にする。
- 両枠が完成待ちの場合、進まない断片の噂を発生させない。
- 断片未所持でも噂が出て、海図集めを開始できる。この場合は噂生成時に海図の内部IDと進行枠・断片1枚分を予約し、取得までは「噂の手掛かり」と表示する。噂地点に到着して獲得した時点で初回断片の説明を表示する。
- 拠点をまたぐ全体クールダウンは設けず、季節ごとの拠点判定と海図単位の1枚制限を使う。

### 4.4 断片の予約と報酬固定

- 資金を置き換える判定は一度だけ行う。依頼は候補生成時、通常の戦闘は勝利報酬の確定時に判定する。
- 依頼の表示・受注・達成・ロードで再抽選しない。信仰・名声・好感度など、資金以外は置き換えない。
- 未受注の依頼候補は進行枠を占有しない。通常拠点・貴族の依頼一覧では、現在の海図・依頼予約・噂予約に照らして断片を割り当てられない候補を非表示にする。候補自体は保持し、割当可能になれば再表示する。受注時も割当先を再検証し、表示後に割当不能になった場合は受注を拒否する。予告した断片を黙って資金に戻さない。
- 受注済みの断片報酬は海図IDに紐付けて予約する。取得済み枚数＋予約済み枚数が必要枚数を超える候補は受注できない。
- 噂の生成・回収も予約数を考慮し、完成直前に余剰断片を生まないようにする。
- 依頼失敗時は予約を解放する。枠に余裕がなければ通常戦闘は資金報酬を維持し、報酬なしにしない。
- 任意の海図へ使える未割当断片は持たせない。断片報酬の種別と元の資金額を保持し、受注時の資金再計算で断片報酬を置き戻さない。予約の検証は候補削除・配達物資付与より先に行う。
- 抽選対象は資金報酬のある依頼。資金報酬のない依頼は対象外。予告された断片報酬がある討伐依頼では、その戦闘の追加断片抽選を省く。
- 複数戦から成る依頼でも、断片報酬を予告した依頼に紐づく全戦闘では戦闘側の断片抽選を省く。通常の資金報酬の依頼は戦闘側0.5%の対象とし、当選しても依頼報酬の資金は維持する。自然探索戦の当選は通常戦闘の資金分だけを置き換え、固定の探索資金は維持する。

### 4.5 報酬と完成地点

- 信仰の変動幅は基準値の±10%。範囲内の整数を一様抽選する。
- 財宝の資金は基準額の95%を切り捨てた下限～105%を切り上げた上限の整数を一様抽選する。
- 高級品は5種類で3枚版が合計100個、5枚版は200個。配分は各種1個を先に割り当て、残りを1個ずつ5種均等に抽選して加算する。必ず全5種が含まれ、合計も一致する。
- 名声の基準値は10／20。変動幅は9～11／18～22（±10%）。
- 完成地点は海図割当時の現在地から最短距離10～20マスで内部固定し、完成時に公開する。入り江は海／浅瀬、祭壇・財宝は非拠点陸地。候補不足の場合は距離条件だけを段階的に緩和する。
- 断片の出現率と3枚／5枚版の抽選比率。すべて設定表に集約する。

### 4.6 取引・護送・専用依頼での入手

海図の完成まで進展を待つ時間を減らし、普段の航海・取引・依頼の中で断片を集められるようにする。既存の戦闘・依頼・自然探索・噂・海図売り・古文書商の確率は、この追加だけを理由に引き上げない。

#### 4.6.1 入手経路

| 入手経路 | 内容 | 設定値・適用範囲 |
| --- | --- | --- |
| 行商人の商品 | 移動中に出会う行商人の取引品として、まれに通常海図の断片1枚を提示する。価格を見て購入でき、購入成立時に断片を得る。救助の謝礼とは別の入手機会とする | 遭遇の商品生成時10%、3000資金。本物1枚、同じ海図への行商人購入は1枚まで |
| 難民護送の完了謝礼 | 護送に成功すると、通常の報酬に加えて低確率で通常海図の断片1枚を得る。護送した船乗りが持っていた古い海図を謝礼として渡す | 受注時10%で当落固定。移動イベントの難民護送だけを対象とし、貴族の難民受け入れは含めない |
| 既存の調達・討伐依頼 | 既存の物資納品・敵討伐の形式を使い、通常海図の断片1枚が確定報酬となる依頼を少数追加する。候補の段階で断片報酬と分かり、海図を進めるために受注できる | 通常拠点ごと季節に20%で最大1件、通常3件とは別枠。調達／通常海賊討伐を均等に選び、納品内容・敵規模は既存生成処理を使う。資金だけを断片1枚へ置換する |
| 無法港の取引 | 略奪品として持ち込まれた本物の通常海図断片1枚を販売する。戦闘をしない航海でも、自分から港へ向かって購入できる機会とする。同じ海図への購入は無法港全体で1枚まで | 各港で季節に一度、取引を初めて開く時25%で在庫1枚を生成し、不発も保存。4000資金、本物のみ、好感度による価格・利用条件の追加なし |

確率・価格・適用範囲は `CHART_CONFIG` へ集約する。難民護送10%と行商人救助20%は別設定とする。断片が確定報酬の調達・討伐依頼は、現行の資金報酬を3%で置き換える処理に加える入手機会であり、その確率は変更しない。「海図収集家の調達依頼」「海図収集家の海賊討伐」として表示し、新しい物資として古文書は追加しない。

表示方針：プレイヤー向けのイベント本文・商品名・ガイド・READMEでは、入手や真贋の具体的確率、抽選時点、予約枠・購入元上限などの内部処理を説明しない。世界内の自然な文章で入手機会を伝え、実際の価格・在庫・所要日数・依頼の確定報酬・入手結果は判断に必要な情報として表示する。難民護送の追加謝礼の当落は事前表示せず、取得した場合だけ結果で知らせる。確率・取得条件は維持し、開発用の設定・設計書・テストには詳細を保持する。

行商人の商品と無法港の取引は、既存の海図売り・古文書商とは別経路として扱う。既存購入イベントの出現率・価格・本物確率を新経路へ自動転用しない。無法港側の概要は [無法港・海賊勢力](pirate-havens-design.md) にも記載する。

#### 4.6.2 予約・保存・表示

- すべて通常の3枚／5枚海図を対象とし、第4.2・4.4節の既存海図優先・予約方式を共用する。海賊王の専用海図には付与しない。
- 商品の対象海図・価格・数量は取引候補の生成時に固定する。画面の開閉・再描画・保存復元で再抽選しない。購入時に資金・在庫・未予約枠・購入元上限を再検証し、割当不能なら代金を消費しない。
- 無法港の購入済み記録は港ごとではなく購入元全体で管理し、複数港を巡って同じ海図へ2枚以上購入できないようにする。
- 確定報酬の調達・討伐依頼は候補の段階で対象海図を予告し、受注時に再検証して断片1枚分を依頼IDへ予約する。達成時だけ付与し、失敗・期限切れでは予約を解放する。断片報酬を予告した討伐依頼の関連戦闘は、第4.4節と同様に通常の戦闘断片抽選から除く。
- 難民護送の追加謝礼は受注時に当落を固定して依頼へ保存し、取得した場合だけ結果に表示する。成功時だけ未予約枠へ付与し、失敗・期限切れ・護送中断では付与しない。再表示・再読み込み・完了処理の再実行で抽選や付与を重ねない。
- 追加謝礼を割り当てられなくても、難民護送の通常報酬は維持する。任意の海図に使える未割当断片や新しい収集ゲージは導入しない。
- 既に生成・保存された商品、依頼、受取済み報酬は維持し、新しい経路は実装後に生成する候補から適用する。購入・非戦闘の達成・断片取得・取得済み記録を一括で保存し、保存失敗時は巻き戻す。討伐は戦果の途中で保存せず、既存の全戦後保存に依頼・断片を含める。戦後保存に失敗した場合は既存どおり現在の戦果を保持して再保存を促す。
- 商品や依頼の表示は既存の取引・依頼画面を使う。断片は通常物資・禁制品の在庫へ混ぜず、海図の取得処理へ接続する。

## 5. 船の艤装

### 5.1 基本仕様

- 艤装は街でのみ行える。初期装備枠は1枠。
- 最大5枠。2枠目は5000資金、3枠目は10000資金、4枠目は15000資金、5枠目は20000資金で順番に拡張する。
- 同じ設備は同時に複数装備できない。
- 購入済みの設備は保管し、付け替えできる。
- 装備変更前に変更後の上限と超過量を表示する。超過分は既存の売却・破棄・解雇で整理できる。
- 艤装効果は陸戦も対象。兵站・救命・見張り効果も海陸で無効化しない。

### 5.2 支援射撃

- 砲撃支援は威力300・20tick間隔・25000資金。1戦1発には制限しない。ガレアスは発射間隔を変えず、威力を最大20%増加させる。
- 初回発動はモリ5tick、バリスタ10tick、ファイヤバリスタ15tick、砲撃20tick。戦闘開始直後の発射はしない。船種補正は `shipyard-design.md` に従う。
- 一時停止中は進まず、速度変更で発射回数は変えない。
- 同時発射は装備枠順で処理し、各発射時に生存敵から再選択する。既に撃破された相手に重ねて発射しない。
- ターゲットは生存敵から均等抽選する。部隊の攻撃方針とは独立する。
- 艤装射撃後にも生存判定を行い、撃破・勝利・戦果集計を通常攻撃と共用する。砲撃は戦後の拿捕や討伐達成を迂回しない。
- 各tickで「通常行動→支援射撃→終了判定→60tickの時間切れ判定」とする。ただし通常行動で勝敗が決まっていれば支援射撃を行わない。
- 砲撃の発動候補は20・40・60tick。戦闘がそこまで続いている場合のみ発射する。
- ブドウ弾2種は `attack.allEnemies` により、発射時の生存敵それぞれを1回ずつ攻撃する。初弾は6／12tick。単体射撃の均等抽選とは分け、味方と撃破済みの敵は対象外。枠順に発動し、先行する射撃で全滅したら以降は発射しない。水色寄りの青／赤い炎色で全対象への射撃を描画する。

**防御計算は全支援射撃で現行式を共用する。** DEF46ならモリ（威力30）は21、バリスタ（100）は68、砲撃支援（300）は205ダメージとなる。ガレアスによる威力補正はDEF軽減前に適用する。

### 5.3 バフ・兵站計算

- 設備は船団共通とし、船数で効果や装備枠を増やさない。初期の聖船でも使用可能。
- 近接／遠隔の区分は兵種の `role`（`melee`／`ranged`）で判定し、射程の数値や表示名では判定しない。支援役は近接・遠隔専用の補正を受けず、全兵員を対象とする補正だけを受ける。
- 同じ能力の割合効果は加算する。鉄の被膜＋舷の丸盾なら近接DEF＋15%、遠隔DEF＋5%。
- 戦闘開始時に装備の有効効果を固定する。人数・レベル補正後の値へ艤装倍率を掛け、地形補正と重複して二度適用しない。
- バフの丸め位置は既存能力計算と統一し、計算用値を再描画のたびに増やさない。
- 上限は `floor(既存上限 * (1 + 増加率合計))` とする。貨物テント＋拡張船倉なら物資上限＋30%。
- 維持費は全兵員の維持費を合計してから10%軽減し、最後に切り捨てる。兵種・レベル・部隊ごとには丸めない。装備時は `floor(維持費合計 * 90 / 100)`。
- 食料も既存の必要量 `floor(全兵員数 / 4)` を算出してから10%軽減し、最後に切り捨てる。装備時は `floor(既存必要量 * 90 / 100)`。少人数時の端数による実質軽減率の増加は許容する。
- 消費処理と維持費予告は同じ計算関数を参照する。艤装変更直後の予告も更新する。
- 救命設備・見張り台は各兵種5人分を加算する。実兵員・積載・維持費・食料消費には加算しない。
- 衛生兵は待機中も含む保有人数を戦闘開始時に記録して集計する。戦後の救助・拿捕で増えた衛生兵は、その戦闘の軽減へ遡って使わない。
- 効果人数はそれぞれ `min(10, 実人数 + 設備による5人分)`。
- 攻撃系・バフ系・救命／見張り設備は陸戦にも適用する。
### 5.4 艤装画面

- 街の「造船所」で中央の地図カードを艤装画面に切り替える。「地図に戻る」で終了し、街を離れた場合も閉じる。購入・変更の最終確認だけ小さなダイアログにする。
- ヘッダの「艤装変更」を初期表示とし、「詳細確認」で現在の全数値と装備中の艤装・効果を表示する。変更画面の比較は変化する数値のみ表示する。
- 地図カードと幅を統一し、カテゴリ変更で下部の位置・高さを変えない。一覧と比較欄は独立してスクロールし、狭いカードでは上下に並べる。同じカテゴリで設備を選んだ際は一覧のスクロール位置を保つ。
- 支援射撃はモリが水色、バリスタが紫、ファイヤバリスタが赤い炎色、砲撃が橙色。砲撃、ファイヤバリスタ、バリスタ、モリの順に線幅・発光・着弾を大きくする。
- 上部に装備枠と拡張費用、下部に攻撃・バフ・兵站の設備一覧を表示する。
- 各設備に価格・効果・未購入／保管中／装備中を表示する。
- 購入・装備前の実効比較を表示する。維持費120→108、物資上限105→126、衛生兵効果の増分0など、現在の兵員・設備に基づく差を示す。
- 枠が満杯の場合は交換対象を選んでから比較する。既存装備に単純加算した仮値を購入効果として表示しない。ATK／DEFは対象兵種と倍率、支援射撃は威力・間隔・標的方式を示し、敵DEF不明時に実ダメージを断定しない。
- 未購入設備は購入、保管中は装備、装備中は取り外しを選べる。購入だけでは自動装備しない。
- 拡張は2枠目→3枠目の順に購入。資金不足や二重購入は不可。
- 購入・付け替え・枠拡張は日数を消費しない。付け替え無料、設備の売却は不可。
- 変更確認で物資・兵員の現所持数、変更後上限、超過量を表示する。超過しても確認後の取り外しは可能。
- 戦闘中・街の外では購入・装備変更不可。閉じるだけでは未確定の変更を反映しない。
- 戦闘画面には有効設備をまとめて表示し、支援射撃は発射元の船側から敵へのエフェクトで区別する。部隊詳細のATK／DEFも効果込みにする。

### 6.2 状態の概念モデル

保存領域は `state.expansion`（`version: 1`）。自然探索は `exploration`、海図は `charts`、艤装は `outfitting` に保持する。同じ親領域の `fishing` は [釣り詳細設計](fishing-design.md) に従う。

| 状態 | 主な項目 |
| --- | --- |
| 探索地点 | 一意ID、内部種別、座標、出現絶対日、消滅絶対日（無期限はnull）、固定危険度、進行状態、関連海図ID |
| 探索処理 | 一意ID、対象地点ID、開始日、日数適用済み、固定済み敵・報酬、付与済み状態 |
| 海図 | 一意ID、種類、必要枚数、取得済み枚数、予約数、噂取得済み、最終地点、進行状態 |
| 噂履歴 | 拠点ID→最終抽選季節、海図ID→未回収地点ID |
| 艤装 | 開放枠数、購入済み設備ID集合、枠ごとの設備ID |
| 依頼報酬 | 資金／断片の内部種別、元の資金額、予約海図ID、付与済み状態 |

内部IDに日本語名を使わない。描画用名や説明は定義表から取得する。

### 6.3 保存・復元と二重獲得防止

- 初期化と旧セーブ補完で、初期配置済みフラグを使って自然探索地点を各種1件だけ生成する。海図なし・購入設備なし・1枠を設定する。既存の探索状態を復元できた場合は初期配置を追加しない。
- 既存の依頼報酬は復元時に断片へ再抽選しない。旧セーブの資金報酬を維持する。
- 報酬付与と消費済み地点／予約解放を同じ完了処理で更新し、保存を要求する。
- 獲得ダイアログの閉じる・再表示は報酬付与の入口にしない。
- 探索開始前に地点の予約・固定した敵と報酬・日数適用前の記録を保存する。1日適用後に日数適用済み状態と日次イベントをまとめて保存し、戦闘準備へ入る。読み込みでは最後に保存した段階から同じ探索へ復帰する。
- 日数消費の適用済みフラグを保存し、再開で追加の1日や別の敵を発生させない。戦闘自体の途中保存は追加しない。
- 保存失敗時に成功表示だけで進めず、従来の失敗通知を使う。ブラウザ保存を任意に巻き戻す行為まで防止する設計にはしない。
- 不明設備ID、重複装備、枠数超過、範囲外座標、壊れた関連IDを復元時に検査する。
- 無法港の季節取引在庫は `expansion.charts.havenStocks` に保存する。予約は依頼ID・噂地点IDから整合性を検証し、未取得・予約なしの仮の海図は枠を解放する。噂地点が残る海図の枠は解放しない。
- 完了済み地点は削除し、無制限な完了履歴を持たない。噂履歴は拠点数に比例する最終判定だけを残す。ログは既存の200件上限を維持する。

## 7. 地図・ダイアログの見た目

- 漂流物: 木箱と浮材。難破船: 壊れた船体と傾いたマスト。戦場跡: 折れた旗と盾。既存の地形・船に合う輪郭と色調で描く。
- 海図の噂: 断片を示す小さな紙片。完成地点: 祭壇／入り江／宝箱を区別する。
- 丸いバッジ枠や、新たな黄色の現在地枠は追加しない。
- 全体表示では簡略記号、拡大表示では詳しい図柄。現在地と重なったら地点中央・部隊左下を基本とし、海上の船との重なりも確認する。
- 配達先強調の導線を海図の「場所を確認」に共用する。
- 結果ダイアログの資金・物資・信仰・船・兵員・名声は既存の資源アイコンを使う。ログは文字のみ。
- ボタンは通常幅で横書き。海図2件と多数の依頼がある場合、狭い画面、長い設備説明を確認する。

## 8. 不変条件

- 配置上限、候補地ゼロ、120日境界、年越し、複数日進行、予約地点の期限保護。
- 探索キャンセル、日次イベント競合、勝利・敗北・逃走・引き分け、二重クリック、ロードと報酬の二重付与。
- 船を含む報酬の上限再計算、超過物資・兵員の整理、上限を超えたまま移動できないこと。
- 噂の再入場・季節更新・拠点横断・未回収地点・同一海図1枚制限。
- 3枚／5枚同時進行、予約中に別経路で取得、依頼失敗による予約解放、両枠が完成待ちのケース。
- 断片報酬の受注前表示と実際の獲得一致、旧依頼の資金報酬維持。
- 艤装の二重購入、重複装備、資金不足、保管と付け替え、拡張順、取り外し時の超過予告。
- バフの累積加算防止、近接／遠隔区分、地形との順序、維持費予告と実消費の一致。
- 救命設備なしでも待機衛生兵が有効であること、設備と合算して10人上限になること、戦後に加入した衛生兵が遡って効果を与えないこと。
- 支援射撃の5／10／20tick、同時発射、撃破済み標的、一時停止・速度変更、60tick境界、戦果集計。
- 旧セーブ・途中再開・破損フィールド・保存容量不足、ログ上限。

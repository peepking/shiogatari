## 更新方針

- 同じルールの変更は担当文書で行い、他の文書には概要とリンクを置く。READMEはプレイヤーが操作や判断に使う情報を説明する。
- 「実装済み」「未実装の候補」「過去の実装記録」を区別する。過去の調査結果・段階計画は現在の機能説明として使わない。
- 初期草案3本は対応する正式設計書へ統合済み。採用されなかった数値や廃止された案は現行仕様へ持ち込まない。
- 担当文書と実装が食い違う場合は、差異を確認してから更新する。未確定のゲーム仕様を文書整理だけで決定しない。

## 開発時の確認

- `npm test`：既存の自動テストを順番に実行する。
- `npx eslint .`：JavaScriptの静的検査を行う。
- `npm run simulate:battles`：可変盤面・艤装・船種効果・大会戦の援軍を組み合わせた戦闘検証。`-- --details` で条件別の結果を確認する。

ローカル起動はLive Serverなどでリポジトリのルートを公開する。ビルド工程は不要。

# 勢力別賞金・犯罪・清算 設計書

本書は犯罪・勢力別手配・施設制限・清算・手配追跡を定める。常駐NPC賞金首と固有船は [賞金首・固有船](bounty-system-design.md)、無法港の配置・兵種・禁制品・依頼は [無法港](pirate-havens-design.md) に分ける。数値は各機能の共通定数で管理する。

## 1. 設計方針

- 手配額・最終犯罪日・自然解除・追跡・施設制限を勢力ごとに分離する。通常3勢力と外洋海賊を対象とする。
- 表示名は既存の北海連合・群島同盟・湾岸城塞群・外洋海賊を使う。内部IDは `north` / `archipelago` / `citadel` / `pirates`。
- 合計賞金は計算値。施設制限は現在地の支配勢力の手配額だけを参照する。
- 明示的な犯罪選択の成立時に記録する。通常の戦闘・賞金首討伐・戦争中の前線行動を一律に犯罪へ変更しない。禁制品の所持・売買自体にも賞金を付けない。
- 戦闘系犯罪の戦利品は勝利時だけ。敗北・逃走・引き分けでも犯罪と行動回数の消費は取り消さない。
- 手配解除は賞金だけを変更する。支持度・好感度・犯罪履歴は戻さない。
- 船の耐久・修理・緊急修理は導入しない。
- 犯罪は短期的利益と追跡・施設制限の代償を選ぶ行動にする。ある勢力圏を追われても別勢力圏や無法港で活動を継続できる余地を残す。
- 独立した悪名ゲージを追加しない。要注意人物になっただけで買取価格を悪化させない。

## 2. 保存データ

```js
wanted: {
  version: 2,
  byFaction: {
    north: { amount: 0, lastCrimeAbs: null },
    archipelago: { amount: 0, lastCrimeAbs: null },
    citadel: { amount: 0, lastCrimeAbs: null },
    pirates: { amount: 0, lastCrimeAbs: null }
  },
  history: [],
  pursuitUntil: null,
  settlementActions: {},
  emergencyFood: {},
  amnestySeasons: {},
  forgeryUntil: null,
  judicialUntil: null,
  detention: null
}
```

- 履歴：`{ kind, factionId, amount, day }`。直近50件、解除後も保持。
- `settlementActions[settlementId]`：窃盗の最終実行季節、拠点襲撃の最終実行季節、利用禁止期限を保存する。季節は `year * 4 + season`、日付は既存の絶対日を使う。
- `pursuitUntil`：正規軍追跡と賞金稼ぎが共有する次回遭遇可能日。通常の戦争遭遇とは区別する。
- `detention`：`{ factionId, remaining }`。没収後の投獄開始状態を保存し、途中再読込では残日数を再処理する。毎日の中間保存は行わない。
- 値の補完は安全な非負整数、既知勢力IDに限定する。未知の勢力への犯罪を別勢力へ付け替えない。対象が決定できなければ犯罪行動そのものを成立させず、資産・回数も消費しない。

### 旧セーブ

旧世界共通賞金は0へ移行する。履歴から勢力を推測しない。既存の罪状・日付は「旧記録・対象勢力不明」として残し、存在しない加算額を表示しない。移行は版番号で一度だけ行い、その後の勢力別賞金を消さない。進行中の依頼・戦闘を作り直さない。

## 3. 犯罪成立と対象の固定

共通の犯罪判定で、名誉家臣ロック、兵員・資金・所持品、季節枠、対象勢力、イベントの有効性を検証する。表示時だけでなく確定時にも同じ判定を行う。

1. 選択前に対象勢力、加算賞金、段階変化、関係悪化、敵規模、勝利時の予想利益を表示。
2. 確定時に再検証し、成立行動・対象・賞金・敵編成・報酬条件を保存可能な状態へ固定。
3. 賞金、履歴、回数消費、進行先を一組として保存する。保存失敗時は一組を戻す。
4. 戦闘結果から賞金を再加算しない。勝利報酬も同じ成立行動について一度だけ処理。

イベント選択の二重クリック、戦闘準備への復帰、報告の再実行を処理済み印で防ぐ。履歴50件の切り捨てを二重適用防止の仕組みに使わない。

| 犯罪 | 対象 | 加算額 |
| --- | --- | ---: |
| 商人襲撃・救助からの襲撃 | 商人の所属勢力 | 1,000 |
| 難民襲撃 | 難民の所属勢力 | 1,500 |
| 通常検問・禁制品検問の強行突破 | 検問担当勢力 | 2,000 |
| 海賊依頼の達成（運び屋・納品・密輸・隊商襲撃・商船団襲撃） | 依頼の被害勢力 | 500 |

海賊依頼の被害勢力は生成時の `pirateVictim` に固定する。占領や報告場所で対象を変えない。対象勢力が保存されていない旧依頼から犯罪を推定加算しない。賞金加算額は `CRIME_REWARDS` に集約する。

## 4. 名誉家臣

- 名誉家臣である間、賞金を増やす新しい犯罪行動は対象勢力を問わずロックする。戦争相手への明示的犯罪も例外にしない。
- 犯罪系依頼の新規受注も従来どおり不可。理由と「名誉家臣を辞する」導線を表示する。
- 自勢力賞金1,000以上で家臣機能を一時停止する。所属データは残し、賞金が閾値未満になれば機能を再開する。自動除名はしない。
- 停止判定は共通化し、新規貴族依頼・軍資金提供・前線行動へ適用する。受注済み報告・辞任・清算は停止しない。貴族面会は現地支配勢力による施設制限に従う。
- 仕官中でも自勢力の手配による追跡を免除しない。辞任は港外からも可能とし、確認画面で失う資格・特典を説明する。辞任しても賞金・支持度・好感度を変更しない。
- 受注済み海賊依頼の達成報告は犯罪ロックの例外として許可し、生成時に固定した勢力へ賞金を加算する。報告禁止や依頼の自動失敗にはしない。新規受注・襲撃など他の犯罪行動は引き続きロックする。
- この報告により自勢力賞金が1,000以上になった場合も、報酬受取と達成処理を完了した上で家臣機能を即時停止する。報告を途中で取り消したり、例外を理由に賞金免除したりしない。

## 5. 施設制限と例外窓口

手配の段階、理由、利用可否は `WANTED_POLICY` を使う共通関数から求め、入口・施設画面・確定処理で同じ判定を使う。

| 手配額 | 段階 | 累積する制限 |
| ---: | --- | --- |
| 0 | 手配なし | 通常利用 |
| 1～999 | 要注意人物 | 施設制限はない。手配追跡の対象になる |
| 1,000～2,999 | 指名手配 | 貴族面会、通常・貴族依頼の新規受注、兵員雇用を制限 |
| 3,000～5,999 | 重罪人 | 通常取引と造船購入も制限 |
| 6,000以上 | 入港拒否 | 拠点内部を開かず、港外窓口を表示 |
| 10,000以上 | 大物賞金首 | 施設制限は入港拒否と同じ。賞金稼ぎ追跡は最上位段階 |

兵員雇用の制限には潮盟・釣り仲間の追加枠を含める。造船売却・艤装変更・釣り小屋は入港可能な段階なら既存条件で利用できる。入港拒否時はこれらも停止し、開いた画面からの確定にも制限を適用する。行商人のイベント取引は施設制限の対象外とする。

### 常に残す導線

- 賠償・投降・辞任。
- 受注済み依頼の達成報告。通常・貴族・前線・海賊依頼と神託を含む。ただし元の報告先・達成条件・期限は維持し、どの港でも報告可能にはしない。
- 無法港の犯罪系依頼の受注・報告。海賊から手配中でも可能。ただし名誉家臣の新規受注禁止は優先する。
- 最低限の食料購入。拠点ごとに季節30個まで、通常購入単価の1.5倍を切り上げる。通常在庫と独立し、資金と積載上限は必要。高く買う非常手段として交易利益を生まないようにする。

最低限食料の購入枠は `wanted.emergencyFood[settlementId] = { season, used }` に保存する。確認後に現在の価格・所持資金・空き容量・残枠を再検証し、保存失敗時は資金・食料・季節枠を戻す。占領で支配勢力が変わっても同季節の使用数は維持する。

利用禁止30日と入港拒否は別条件。どちらも港外例外は塞がない。街だけでなく村の入口でも利用できる。無法港では海賊勢力の手配額だけを施設制限に使う。

### 検問・入口の優先順位

入港拒否・襲撃後利用禁止を先に判定し、拒否時は入場検問・入場イベントを呼ばない。滞在中に条件を満たした場合も入口へ戻す。入港可能な場合の検問は [無法港](pirate-havens-design.md) の禁制品・支持度による規則に従う。手配額による検問確率の加算は行わない。

検問の強行突破や賄賂は手配解除ではない。強行突破では担当勢力へ犯罪を記録し、同じ検問での再抽選・二重徴収を防ぐ。

## 6. 無法港と黒ひげ

- 犯罪系依頼は賞金0・黒ひげ好感度最低でも受注可能。海賊賞金が高くても港外の依頼窓口は維持。
- 黒ひげ本人と会える場所は既存の本拠地のみ。各無法港の依頼・清算窓口に本人がいる扱いにはしない。
- 黒ひげの好感度で依頼報酬が変わる場合、生成時に倍率と資金報酬を固定し、受注前に表示する。達成直前の好感度で増減させない。
- 資金報酬の倍率：敵対80%・警戒90%・中立100%・厚遇120%。既存の関係境界（−30、0、30）を使用する。`PIRATE_REWARD_RATES` で調整し、資金のみ最後に切り捨てる。依頼に元額・倍率・関係を保存し、受注済み／提示済みの旧依頼は変更しない。断片報酬・名声には適用しない。報酬欄には補正後の金額を表示する。
- 好感度最低でも依頼達成による関係回復を可能にする。品揃えや雇用は季節内に固定し、出入りで再抽選しない。
- 通常勢力合計賞金、海賊賞金、黒ひげ好感度を分けて表示する。

## 7. 解除方法

### 賠償・投獄・自然解除

**賠償**：対象勢力の現在賞金×1.5、端数切り上げ。確認後の現在額・所持資金を再検証し、支払いと対象勢力だけの全額解除を一括保存する。資金不足なら成立させない。保存失敗時は資金・手配を戻す。

**投獄**：対象勢力の賞金を全額解除する代わりに禁制品を全没収し、`min(120, 30 + floor(賞金 / 3000) × 30)` 日経過する。資金・通常物資の追加没収は行わない。確定前に日数・没収・到達予定日・経過する維持費支払い回数を表示する。日数は `DETENTION_CONFIG` で管理する。

投降時点で禁制品の没収と `wanted.detention = { factionId, remaining }` を一括保存する。その後は日次処理で日付・依頼期限・世界情勢・維持費・食料・季節報酬を進め、釈放時に保存する。毎日の中間保存は行わず、中断・保存失敗時は保存済みの投獄開始状態から残日数を再処理する。没収は再実行しない。釈放の保存に失敗した場合は日数経過と世界を巻き戻し、操作をロックして同じ処理を再試行できるようにする。

投獄中の通常通知はキューに保持して釈放後に表示する。名誉家臣の勧誘抽選、移動遭遇、入場検問は行わない。予定された災いは釈放後の通常日次処理まで延期する。未解決イベントがある状態では投降できない。釈放時は投降先の手配だけを解除し、履歴・所属・好感度は変更しない。他勢力の手配には通常の日数経過による自然解除だけを適用する。

**自然解除**：各勢力の最終犯罪から600日で0。別勢力の犯罪で期限を延長しない。UI参照前・犯罪記録前・日次処理で期限切れを整合させる。賞金0なら最終犯罪日をnullにするが履歴は残す。

### 恩赦・身分偽造・司法取引

恩赦・身分偽造・司法取引は第10節の「窓口で交渉」から利用する。

- 恩赦依頼は食料50の納入、期限60日、対象勢力の賞金最大1,000減額。同時1件、各勢力で季節1回とし、資金・名声・信仰・国力は得ない。条件は `AMNESTY_CONFIG` に集約する。報告先と対象勢力は受注時固定し、占領後も元の拠点へ納めて元の勢力を減額する。入港拒否・利用禁止・名誉家臣の状態でも受注・報告できる。既存の依頼カードで進捗・期限・地図確認・納品を行う。
- 恩赦の受注季節は `wanted.amnestySeasons[factionId]` へ保存し、完了・期限切れでも同季節には再受注できない。期限切れは追加の賞金・関係悪化なしで終了する。対象の手配がなくなった場合は納品不可とし、食料を消費しない。履歴・好感度・利用禁止期限は変更しない。受注・報告の保存失敗時は季節枠・依頼・食料・賞金を戻す。
- 身分偽造：無法港の入口・滞在中の「窓口で交渉」で利用。通常勢力1つの残額を半分に切り捨て、費用は減額分×関係補正（敵対1.2・警戒1.1・中立1・厚遇0.8）を切り上げる。失敗なし、全勢力・全港共通で30日待機。名誉家臣や海賊からの手配中も利用可能。賞金を増やす行動ではないため犯罪ロックの対象外。犯罪日・履歴・好感度・拠点利用禁止は維持し、残額0のときのみ犯罪日をnullへ戻す。`FORGERY_CONFIG` で調整。`wanted.forgeryUntil` を保存し、犯罪追加時も保持。費用・対象賞金の確認後変化は再確認を求め、保存失敗時は資金・賞金・待機期間を戻す。
- 司法取引：通常拠点の入口・滞在中の「窓口で交渉」から禁制品1種類を10個引き渡す。現地支配勢力の賞金を最大3,000減らし、黒ひげ好感度−20（下限−100）、海賊賞金＋1,000を適用。情報提供を伴う引渡しとして海賊側の犯罪履歴に記録し、同勢力の最終犯罪日を更新する。名誉家臣は所属先を問わず利用不可で辞任が必要。入港拒否・利用禁止中は利用できる。全勢力・全拠点共通で30日待機、失敗抽選なし。資金・通常報酬は発生しない。通常勢力の最終犯罪日・支持度・利用禁止は変更せず、賞金0のときのみ犯罪日をnullにする。
- 調整値は `JUDICIAL_CONFIG` と `CRIME_REWARDS.judicial_deal`。待機期限は `wanted.judicialUntil` として正規化・保存する。確認後の現在拠点・支配勢力・賞金額・引渡品・資格を再検証し、占領等で変化した場合は再確認を求める。保存失敗時は引渡品・両勢力の賞金・犯罪履歴・好感度・待機期限をすべて戻す。

## 8. 拠点の窃盗・襲撃

### 村・街の規模と報酬抽選

市場・兵糧庫・武器庫・拠点襲撃の基準報酬に、村0.5倍・街1.5倍（無法港も街）を適用する。資金・各物資はそれぞれ基準×規模の80%切り捨て～120%切り上げの整数を一様抽選。確認時は範囲を表示し、成立時に一度抽選する。戦闘報酬は遭遇データへ保存し再開で再抽選しない。受取容量は最大数量で事前判定。支持度・貴族好感度悪化と守備隊人数計算にも同じ規模倍率を適用する。賞金加算・季節制限・兵種・通常戦闘報酬は維持する。

無法港の禁制品在庫は [無法港設計書](pirate-havens-design.md) に集約する。

### 基準値

以下の資金・物資・関係悪化へ規模倍率を適用し、資金・物資は前述の範囲から抽選する。賞金には倍率を掛けない。基準値は `THEFT_TYPES` と `CRIME_REWARDS` に集約する。

| 行動 | 賞金加算 | 基準資金・物資 | 基準支持度・担当貴族好感度 |
| --- | ---: | --- | ---: |
| 市場窃盗 | 500 | 資金500・塩2 | 各−2 |
| 兵糧庫窃盗 | 1,000 | 食料30・木材5 | 各−4 |
| 武器庫窃盗 | 1,500 | 武具8・鉄10 | 各−8 |
| 拠点襲撃 | 5,000 | 資金5,000・食料50・木材10 | 各−15 |

### 窃盗

市場・兵糧庫・武器庫で共通の `theftSeason` を使い、拠点ごとに季節1回。選択成立時に枠を消費する。市場・兵糧庫は戦闘と日数消費なしで即時獲得し、武器庫は兵員がいる場合だけ守備隊と戦い、勝利時に通常戦闘報酬とは別に獲得する。敗北・逃走・引き分けでは追加報酬なし、賞金と季節枠は戻さない。無法港で実行した場合の対象勢力は海賊。

窃盗は入場後のみ可能とし、名誉家臣・入場拒否・未解決イベント中は不可。容量不足なら成立させず、報酬を自動廃棄しない。確認後の拠点・勢力・担当貴族・季節を再検証し、保存失敗時は戦闘準備を含め報酬・犯罪・季節枠・支持度・好感度を一緒に戻す。保存復元・占領・手配解除でも当季の枠を戻さない。

### 拠点襲撃

通常拠点ごとに季節1回、窃盗とは別枠。戦闘開始時に敵編成と報酬を固定し、敗北・逃走・引き分けでも回数を戻さない。勝利時だけ資金・物資等を得る。国家戦争の占領処理を呼ばない。

守備隊は強編成の人数へ1.5倍と拠点規模倍率を適用し、20部隊・200人を上限とする。敵編成は確認時に生成して保存する。無法港は襲撃対象外。

窃盗とは別の `raidSeason` を使い、成立時に `bannedUntil = 現在日 + 30` を保存する。占領・賠償・敗北・逃走でも枠や禁止期間を戻さず、禁止終了日から入場できる。利用禁止は拠点IDへ保存し、既存依頼の報告・最低限食料・清算を妨げない。

窃盗・襲撃の戦利品は基準報酬から抽選し、交易在庫を奪わない。戦闘前の報酬を保存し、通常報酬との合算で容量超過した場合は手動で整理する。国家の戦況・国力・近隣貴族への討伐貢献には算入しない。

## 9. 追跡

- 正規軍追跡：現在地から8マス以内の最寄りの通常拠点を基準に、その支配勢力の期限内の手配だけを見る。名誉家臣でも免除しない。遭遇成立時の追加抽選率は30%（`PIRATE_CONFIG.wantedChance`）。敵人数と兵種は通常遭遇の生成規則を使う。
- 賞金稼ぎ追跡：正規軍追跡が選ばれなかった場合、期限内の4勢力合計賞金から下表の最上位の該当段階を選ぶ。抽選率は毎日の発生率ではなく、遭遇成立時の条件付き確率。
- 同じ移動では追跡を最大1件とし、正規軍追跡→賞金稼ぎ追跡→通常遭遇の順で判定する。イベント・戦闘が保留中なら追加しない。
- 賞金稼ぎの人数は範囲内の整数を均等抽選し、既存の強編成・賞金稼ぎ兵種プールとLv1～3を使う。最大20部隊とし、名声や上限以上の賞金で人数を増やさない。高額手配でも大会戦へ変更しない。

| 合計賞金 | 追加抽選率 | 敵人数 |
| ---: | ---: | ---: |
| 1以上 | 5% | 20～40 |
| 3,000以上 | 10% | 40～70 |
| 6,000以上 | 15% | 70～110 |
| 10,000以上 | 20% | 110～160 |

追跡は `pursuitKind: "regular"`／`"hunter"` で識別する。戦後結果・降伏・準備中の逃走・祈りによる回避で `wanted.pursuitUntil` を終了日＋3日に設定し、その日から再抽選できる。処理済み印で重複時の延長を防ぎ、犯罪追加・保存復元でも期限を保持する。撃退しても賞金は減らさない。

通常の戦争遭遇と名声由来の既存の賞金稼ぎ遭遇は、この追跡とは区別して共通猶予の対象外とする。固定NPC賞金首とも別機能。段階表は `HUNTER_TIERS`、共通猶予は `PURSUIT_COOLDOWN_DAYS` に集約する。

## 10. UIと実装責務

### 行動導線

- 賞金首一覧のプレイヤー欄は手配・履歴の確認専用。犯罪・辞任・手配清算の操作を置かない。
- 拠点の行動欄「窓口で交渉」：賠償・投降・恩赦・司法取引・最低限食料。無法港では身分偽造も表示する。入口・滞在中で利用でき、入場拒否・襲撃後の利用禁止では入口を隠さない。
- 拠点の行動欄「裏の行動」：窃盗・拠点襲撃。窃盗は入場後のみ。通常拠点への襲撃は入口から実行可能で、入場拒否により禁止しない。季節枠・兵員等の条件は維持する。名誉家臣には辞任理由と「所属・身分」への導線を表示する。
- 「旅の行動」→「所属・身分」：所属勢力・停止理由・確認付き辞任。フィールド・入口・滞在中・謁見中で利用できる。戦闘・未解決イベント・投獄中は変更不可。自動辞任は行わない。
- 専用の共通ダイアログで内容を切り替え、既存の行動カードの狭幅1列表示を引き継ぐ。各処理の保存失敗時の巻き戻しと確定時の再検証は維持する。

- 賞金首一覧：プレイヤー欄に4勢力別の額・段階・自然解除日、合計額。過去犯罪は既存の高さ制限付き折りたたみを継続。
- 犯罪選択：加算先・金額・段階変化を事前表示。名誉家臣の場合は理由を表示し無効化する。
- 拠点入口：制限の理由、利用できる港外機能、辞任・賠償・投降を整理する。施設ごとにばらばらのモーダルを積まない。
- `src/wanted/playerWanted.js`を勢力別データ、犯罪一意記録、自然解除の中心にする。施設権限・清算・犯罪行動・追跡は責務別モジュールへ分ける。
- `src/pirates/pirateEncounters.js` は近隣勢力の手配、`src/app/actions.js` は移動時の追跡・犯罪選択、`src/pirates/pirateQuests.js` は依頼の被害勢力を参照する。取引・雇用・受注は確定処理でも施設権限を検証する。
- 数値は定数へ集約。現在額・段階・制限理由・支払い見積もりをUI専用の別式で計算しない。

## 11. 不変条件

必須検証：対象勢力の正しさ、600日境界、旧データの再消去防止、犯罪と報酬の二重反映防止、報告時の元地点条件、海賊からの手配中でも依頼窓口が残ること、名誉家臣の犯罪選択と確定時の拒否、占領後の制限更新、投獄中断からの再開と季節処理、資金不足時の解除導線、追跡の重複と猶予、施設を開いた後の条件変化。

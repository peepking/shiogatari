# 勢力別賞金・無法港拡張 設計書

状態：勢力別手配、犯罪ロック・辞任・賠償・投獄・施設制限・最低限食料、追跡猶予と賞金稼ぎの段階化、拠点窃盗・襲撃、恩赦依頼、黒ひげの依頼報酬補正、身分偽造・司法取引を実装済み。正規軍追跡の段階化などは後続。接続範囲の詳細は第11節。初期草案を本書へ統合済み。

本書は犯罪・勢力別手配・施設制限・清算・手配追跡の参照先とする。常駐NPC賞金首と固有船は [賞金首仕様書](bounty-system-design.md)、無法港の配置・兵種・禁制品・依頼は [無法港設計書](pirate-havens-design.md) に分ける。

本文の「確定」は承認済み仕様。「調整案」は初期候補を示す。第11節は実装経緯を残す記録であり、操作の配置は第10節、報酬の規模倍率と抽選は第8節を参照する。過去の未実装記載を現在の状態と解釈しない。

## 1. 確定した方針

- 手配額・最終犯罪日・自然解除・追跡・施設制限を勢力ごとに分離する。通常3勢力と外洋海賊を対象とする。
- 表示名は既存の北海連合・群島同盟・湾岸城塞群・外洋海賊を使う。内部IDは `north` / `archipelago` / `citadel` / `pirates`。
- 合計賞金は計算値。施設制限は現在地の支配勢力の手配額だけを参照する。
- 明示的な犯罪選択の成立時に記録する。通常の戦闘・賞金首討伐・戦争中の前線行動を一律に犯罪へ変更しない。禁制品の所持・売買自体にも賞金を付けない。
- 戦闘系犯罪の戦利品は勝利時だけ。敗北・逃走・引き分けでも犯罪と行動回数の消費は取り消さない。
- 手配解除は賞金だけを変更する。支持度・好感度・犯罪履歴は戻さない。
- 船の耐久・修理・緊急修理は導入しない。
- 犯罪は短期的利益と追跡・施設制限の代償を選ぶ行動にする。ある勢力圏を追われても別勢力圏や無法港で活動を継続できる余地を残す。
- 独立した悪名ゲージを追加しない。要注意人物になっただけで買取価格を悪化させない。

## 2. 保存データ

```js
wanted: {
  version: 2,
  byFaction: {
    north: { amount: 0, lastCrimeAbs: null },
    archipelago: { amount: 0, lastCrimeAbs: null },
    citadel: { amount: 0, lastCrimeAbs: null },
    pirates: { amount: 0, lastCrimeAbs: null }
  },
  history: [],
  nextActionId: 1,
  pursuitUntil: null,
  settlementActions: {},
  detention: null
}
```

- 履歴：`{ actionId, kind, factionId, amount, day }`。直近50件、解除後も保持。
- `settlementActions[settlementId]`：窃盗の最終実行季節、拠点襲撃の最終実行季節、利用禁止期限を保存する。季節は `year * 4 + season`、日付は既存の絶対日を使う。
- `pursuitUntil`：正規軍追跡と賞金稼ぎが共有する次回遭遇可能日。通常の戦争遭遇とは区別する。
- `detention`：投獄を日次で進める場合の対象勢力・残日数・処理ID・没収済み印。途中再読込で二重没収や即時釈放を起こさない。
- 値の補完は安全な非負整数、既知勢力IDに限定する。未知の勢力への犯罪を別勢力へ付け替えない。対象が決定できなければ犯罪行動そのものを成立させず、資産・回数も消費しない。

### 旧セーブ

旧世界共通賞金は0へ移行する。履歴から勢力を推測しない。既存の罪状・日付は「旧記録・対象勢力不明」として残し、存在しない加算額を表示しない。移行は版番号で一度だけ行い、その後の勢力別賞金を消さない。進行中の依頼・戦闘を作り直さない。

## 3. 犯罪成立と対象の固定

共通の犯罪判定で、名誉家臣ロック、兵員・資金・所持品、季節枠、対象勢力、イベントの有効性を検証する。表示時だけでなく確定時にも同じ判定を行う。

1. 選択前に対象勢力、加算賞金、段階変化、関係悪化、敵規模、勝利時の予想利益を表示。
2. 確定時に再検証し、行動ID・対象・賞金・敵編成・報酬条件を保存可能な状態へ固定。
3. 賞金、履歴、回数消費、進行先を一組として保存する。保存失敗時は一組を戻す。
4. 戦闘結果から賞金を再加算しない。勝利報酬も同じ行動IDで一度だけ処理。

イベント選択の二重クリック、戦闘準備への復帰、報告の再実行を処理済み印で防ぐ。履歴50件の切り捨てを二重適用防止の仕組みに使わない。

| 犯罪 | 対象 | 加算額の初期案 |
| --- | --- | ---: |
| 商人襲撃・救助からの襲撃 | 商人の所属勢力 | 1,000 |
| 難民襲撃 | 難民の所属勢力 | 1,500 |
| 通常検問・禁制品検問の強行突破 | 検問担当勢力 | 2,000 |
| 海賊の運び屋・納品 | 依頼の被害勢力 | 500 |
| 海賊の密輸 | 同上 | 1,000 |
| 海賊の隊商・船団襲撃 | 同上 | 1,500 |

海賊依頼は既存の `pirateVictim` を利用し、生成時に賞金も固定する。占領や報告場所で対象を変えない。旧依頼で被害勢力が保存済みならその値を使い、欠損していれば移行時に個別確認・補完する。根拠のない犯罪加算は行わない。

## 4. 名誉家臣

- 名誉家臣である間、賞金を増やす新しい犯罪行動は対象勢力を問わずロックする。戦争相手への明示的犯罪も例外にしない。
- 犯罪系依頼の新規受注も従来どおり不可。理由と「名誉家臣を辞する」導線を表示する。
- 自勢力賞金1,000以上で家臣機能を一時停止する。所属データは残し、賞金が閾値未満になれば機能を再開する。自動除名はしない。
- 停止は共通判定に集約する。貴族との面会、仕官に由来する新規依頼・特典・軍資金提供等へ適用する範囲を実装前に一覧化する。受注済み報告・辞任・清算を停止しない。
- 仕官中でも自勢力の手配による追跡を免除しない。辞任は港外からも可能とし、確認画面で失う資格・特典を説明する。辞任しても賞金・支持度・好感度を変更しない。
- 受注済み海賊依頼の達成報告は犯罪ロックの例外として許可し、生成時に固定した勢力へ賞金を加算する（確定）。報告禁止や依頼の自動失敗にはしない。新規受注・襲撃など他の犯罪行動は引き続きロックする。
- この報告により自勢力賞金が1,000以上になった場合も、報酬受取と達成処理を完了した上で家臣機能を即時停止する。報告を途中で取り消したり、例外を理由に賞金免除したりしない。

## 5. 施設制限と例外窓口

賞金段階は草案の初期案を使用する。段階、理由、利用可否は共通関数から返し、入口・施設画面・取引確定で重複実装しない。

| 手配額 | 段階 | 累積する制限 |
| ---: | --- | --- |
| 0 | 手配なし | 通常利用 |
| 1～999 | 要注意人物 | 検問率上昇。買取単価は変更しない |
| 1,000～2,999 | 指名手配 | 貴族面会、通常依頼の新規受注、通常の兵員雇用を制限 |
| 3,000～5,999 | 重罪人 | 通常取引と造船購入も制限 |
| 6,000以上 | 入港拒否 | 拠点内部を開かず、港外窓口を表示 |
| 10,000以上 | 大物賞金首 | 施設制限は入港拒否と同じ。追跡の強化段階 |

通常雇用の制限対象には潮盟・釣り仲間の追加枠を含める案とする。専用枠からの制限回避を作らない。造船売却、艤装変更、釣り小屋など表で明記されていない施設は、入港可能な段階では既存条件で利用可能とする初期案。入港拒否では港外例外だけを提供する。

### 常に残す導線（確定）

- 賠償・投降・辞任。
- 受注済み依頼の達成報告。通常・貴族・前線・海賊依頼と神託を含む。ただし元の報告先・達成条件・期限は維持し、どの港でも報告可能にはしない。
- 無法港の犯罪系依頼の受注・報告。海賊から手配中でも可能。ただし名誉家臣の新規受注禁止は優先する。
- 最低限の食料購入。数量・価格の調整案は、拠点ごとに季節30個まで、通常購入単価の1.5倍（切り上げ）。通常在庫と独立し、資金と積載上限は必要。高く買う非常手段として交易利益を生まないようにする。

利用禁止30日と入港拒否は別条件。どちらも港外例外は塞がない。街だけでなく村の入口でも利用可能にする。無法港では通常勢力の手配額を施設制限に使わない。

### 検問・入口の優先順位

入港拒否・襲撃後利用禁止の窓口判定を先に行い、同じ入場で通常検問と拒否イベントを重ねない。入港可能なら、既存の禁制品・支持度による確率へ手配補正を加える。禁制品0の手配なしは既存どおり0%。手配がある場合だけ禁制品0でも検問対象になる変更を明記する。

「強行突破」はその拠点への一時的な入場許可であり、賞金解除ではない。施設の手配判定は解除しない案とし、存在意義と勝利時の許可範囲を第2段階で確定する。賄賂も手配解除と混同させず、同じ窓口での連打・再抽選を防ぐ。

## 6. 無法港と黒ひげ

- 犯罪系依頼は賞金0・黒ひげ好感度最低でも受注可能。海賊賞金が高くても港外の依頼窓口は維持。
- 黒ひげ本人と会える場所は既存の本拠地のみ。各無法港の依頼・清算窓口に本人がいる扱いにはしない。
- 黒ひげの好感度で依頼報酬が変わる場合、生成時に倍率と資金報酬を固定し、受注前に表示する。達成直前の好感度で増減させない。
- 実装済みの初期値：敵対80%・警戒90%・中立100%・厚遇120%。既存の関係境界（−30、0、30）を使用する。`PIRATE_REWARD_RATES` で調整し、資金のみ最後に切り捨てる。依頼に元額・倍率・関係を保存し、受注済み／提示済みの旧依頼は変更しない。断片報酬・名声には適用しない。報酬欄の表示額は補正反映済み。
- 手数料・品揃え・雇用優遇は第4段階。好感度最低でも依頼達成による回復を可能にする。品揃えや雇用の季節固定を壊して出入りで再抽選させない。
- 通常勢力合計賞金、海賊賞金、黒ひげ好感度を分けて表示する。

## 7. 解除方法

### 初回実装

**賠償**：対象勢力の現在賞金×1.5、端数切り上げを初期値とする。確定時の現在額で再検証し、支払いと全額解除を一括保存する。資金不足なら成立させない。

**投獄**：対象勢力の賞金を全額解除。禁制品を全没収し、30～120日経過。最初は追加の資金・通常物資没収を入れず、季節維持費と食料消費を代償にする案。日数の調整案は30日＋賞金3,000ごとに30日、最大120日。確定前に日数・没収・到達予定日・経過する維持費支払い回数を表示する。

投獄中は日付、依頼期限、世界情勢、維持費、食料、季節報酬を通常どおり更新する。移動扱いにはせず、移動遭遇・入場検問・プレイヤー操作を挟まない。時間処理の終端で該当勢力だけ解除する。没収を先に行い、保存済み進捗から残日数だけ再開する。キューへ積まれる既存イベントの扱いも検証する。

**自然解除**：各勢力の最終犯罪から600日で0。別勢力の犯罪で期限を延長しない。UI参照前・犯罪記録前・日次処理で期限切れを整合させる。賞金0なら最終犯罪日をnullにするが履歴は残す。

### 恩赦・身分偽造・司法取引（実装済み）

恩赦の受注・納品・減額・季節枠は第11節に記載する。身分偽造・司法取引の操作は第10節の「窓口で交渉」へ配置する。
- 身分偽造の実装初期値：無法港の入口・滞在中の「窓口で交渉」で利用。通常勢力1つの残額を半分に切り捨て、費用は減額分×関係補正（敵対1.2・警戒1.1・中立1・厚遇0.8）を切り上げる。失敗なし、全勢力・全港共通で30日待機。名誉家臣や海賊からの手配中も利用可能。賞金を増やす行動ではないため犯罪ロックの対象外。犯罪日・履歴・好感度・拠点利用禁止は維持し、残額0のときのみ犯罪日をnullへ戻す。`FORGERY_CONFIG` で調整。`wanted.forgeryUntil` を保存し、犯罪追加時も保持。費用・対象賞金の確認後変化は再確認を求め、保存失敗時は資金・賞金・待機期間を戻す。
- 司法取引の実装初期値：通常拠点の入口・滞在中の「窓口で交渉」から禁制品1種類を10個引き渡す。現地支配勢力の賞金を最大3,000減らし、黒ひげ好感度−20（下限−100）、海賊賞金＋1,000を適用。情報提供を伴う引渡しとして海賊側の犯罪履歴に記録し、同勢力の最終犯罪日を更新する。名誉家臣は所属先を問わず利用不可で辞任が必要。入港拒否・利用禁止中は利用できる。全勢力・全拠点共通で30日待機、失敗抽選なし。資金・通常報酬は発生しない。通常勢力の最終犯罪日・支持度・利用禁止は変更せず、賞金0のときのみ犯罪日をnullにする。
- 調整値は `JUDICIAL_CONFIG` と `CRIME_REWARDS.judicial_deal`。待機期限は `wanted.judicialUntil` として正規化・保存する。確認後の現在拠点・支配勢力・賞金額・引渡品・資格を再検証し、占領等で変化した場合は再確認を求める。保存失敗時は引渡品・両勢力の賞金・犯罪履歴・好感度・待機期限をすべて戻す。
- 特赦、脱走幇助、港湾税、独立した先制攻撃は将来候補。

## 8. 追加犯罪

### 村・街の規模と報酬抽選（以下の固定報酬記載に優先）

市場・兵糧庫・武器庫・拠点襲撃の基準報酬に、村0.5倍・街1.5倍（無法港も街）を適用する。資金・各物資はそれぞれ基準×規模の80%切り捨て～120%切り上げの整数を一様抽選。確認時は範囲を表示し、成立時に一度抽選する。戦闘報酬は遭遇データへ保存し再開で再抽選しない。受取容量は最大数量で事前判定。支持度・貴族好感度悪化と守備隊人数計算にも同じ規模倍率を適用する。賞金加算・季節制限・兵種・通常戦闘報酬は維持する。

無法港の禁制品在庫は [無法港設計書](pirate-havens-design.md) に集約する。

### 窃盗

市場・兵糧庫・武器庫を合わせて拠点ごとに季節1回。選択成立時に枠を消費する。市場と兵糧庫は即時獲得、武器庫は戦闘勝利時に獲得する。武器庫は兵員ゼロで選べない。資金・品目・数量・関係悪化の基準値は第11節、規模倍率と抽選は本節に従う。無法港で実行すれば対象は海賊。

### 拠点襲撃

通常拠点ごとに季節1回、窃盗とは別枠。戦闘開始時に敵編成と報酬を固定し、敗北・逃走・引き分けでも回数を戻さない。勝利時だけ資金・物資等を得る。国家戦争の占領処理を呼ばない。

利用禁止は成立時から30日を初期仕様とする。占領で支配勢力が変わっても期限を消さない。利用禁止は拠点IDへ保存し、既存依頼の報告と清算を妨げない。賞金・守備隊規模・報酬の基準値は第11節に記載する。

現行の戦利品は基準報酬からの抽選とし、交易在庫を奪う処理は行わない。将来、実在庫からの略奪を採用する場合は予約・減算時点を別途確定する。

## 9. 追跡

- 正規軍追跡：現在地から8マス以内の既存の近隣通常拠点判定を利用し、その支配勢力の手配だけを見る。名誉家臣でも免除しない。
- 賞金稼ぎ：4勢力の合計賞金が基準。従来の名声による遭遇種別と、新しいプレイヤー追跡を内部IDで区別する。固定NPC賞金首とも別機能。
- 同じ移動では追跡を最大1件。正規軍追跡→賞金稼ぎ→既存遭遇の優先順を初期案とする。イベント・戦闘が既に保留中なら追加しない。
- 追跡遭遇終了後の共通猶予は3日を調整案とする。勝利だけでなく逃走・敗北・投降・引き分けでも適用し、連戦で操作不能にしない。撃退で賞金は減らさない。
- 出現率と編成は有限の段階表で管理し、賞金へ無制限比例させない。20部隊の上限と通常戦の扱いを維持。高額でも自動的に大会戦へ変えない。
- 正規軍の戦争遭遇は既存条件を維持し、追跡と同一の猶予で全戦闘を止めない。猶予は手配追跡の連続を防ぐ機能として説明する。

## 10. UIと実装責務

### 行動導線の再設計（従来の賞金首一覧内の操作配置を置き換える）

- 賞金首一覧のプレイヤー欄は手配・履歴の確認専用。犯罪・辞任・手配清算の操作を置かない。
- 拠点の行動欄「窓口で交渉」：賠償・投降・恩赦・司法取引・最低限食料。無法港では身分偽造も表示する。入口・滞在中で利用でき、入場拒否・襲撃後の利用禁止では入口を隠さない。
- 拠点の行動欄「裏の行動」：窃盗・拠点襲撃。窃盗は入場後のみ。通常拠点への襲撃は入口から実行可能で、入場拒否により禁止しない。季節枠・兵員等の条件は維持する。名誉家臣には辞任理由と「所属・身分」への導線を表示する。
- 「旅の行動」→「所属・身分」：所属勢力・停止理由・確認付き辞任。フィールド・入口・滞在中・謁見中で利用できる。戦闘・未解決イベント・投獄中は変更不可。自動辞任は行わない。
- 専用の共通ダイアログで内容を切り替え、既存の行動カードの狭幅1列表示を引き継ぐ。各処理の保存失敗時の巻き戻しと確定時の再検証は維持する。

- 賞金首一覧：プレイヤー欄に4勢力別の額・段階・自然解除日、合計額。過去犯罪は既存の高さ制限付き折りたたみを継続。
- 犯罪選択：加算先・金額・段階変化を事前表示。名誉家臣の場合は理由を表示し無効化する。
- 拠点入口：制限の理由、利用できる港外機能、辞任・賠償・投降を整理する。施設ごとにばらばらのモーダルを積まない。
- `src/wanted/playerWanted.js`を勢力別データ、犯罪一意記録、自然解除の中心にする。施設権限・清算・犯罪行動・追跡は責務別モジュールへ分ける。
- `src/pirates/pirateEncounters.js`の世界共通賞金参照と所属勢力免除を変更。`src/app/actions.js`の既存犯罪呼出、`src/pirates/pirateQuests.js`の被害勢力、取引・雇用・受注の確定処理へ接続する。
- 数値は定数へ集約。現在額・段階・制限理由・支払い見積もりをUI専用の別式で計算しない。

## 11. 実装記録と基準値

本節の「賞金首一覧」内の操作配置は導入当時の記録。現行の配置は第10節に集約する。「固定報酬」は抽選前の基準値として読み、第8節の規模倍率・抽選を適用する。

恩赦依頼を実装済み。港外の賞金首一覧から受注し、既存の依頼カードで進捗・期限・地図確認・納品を行う。初期値は食料50の納入、期限60日、対象勢力の賞金最大1,000減額。同時1件、各勢力で季節1回とし、資金・名声・信仰・国力は得ない。条件は `AMNESTY_CONFIG` に集約する。報告先と対象勢力は受注時固定、占領後も元の拠点へ納めて元の勢力を減額する。入港拒否・利用禁止・名誉家臣の状態でも受注/報告できる。

受注季節は `wanted.amnestySeasons[factionId]` へ保存し、完了・期限切れでも同季節には再受注できない。期限切れは既存の日次依頼処理で取り除き、追加の賞金・関係悪化はない。賠償などで対象の手配がなくなった場合は納品不可として食料を消費しない。履歴・好感度・利用禁止期限は変更しない。受注/報告の保存失敗時は季節枠・依頼・食料・賞金を戻す。

通常拠点の襲撃を実装済み。入口または滞在中の賞金首一覧から選択する。調整用初期値は賞金5,000・支持度/担当貴族好感度各−15、勝利時に資金5,000＋食料50＋木材10を通常戦闘報酬へ追加。強編成の人数計算に1.5倍を適用し、20部隊・200人上限を維持する。無法港は襲撃対象外。初期設定は `THEFT_TYPES.settlement_raid` と `CRIME_REWARDS` に集約する。

窃盗の `theftSeason` と別の `raidSeason` を使い、開始時に `bannedUntil = 現在日 + 30` を保存する。既存の窃盗枠を上書きしない。勝敗・逃走で回数や禁止期間は戻らず、賠償・占領でも禁止は消えない。禁止終了日は入場可能。期間中は元の条件による報告・最低限食料・清算を維持する。戦利品は固定報酬で拠点在庫を複製せず、拠点占領・戦況・国力の処理を呼ばない。

武器庫窃盗を実装済み。市場・兵糧庫と同じ季節枠を使い、開始時に賞金1,500・支持度/担当貴族好感度各−8を確定する。守備隊は既存の強編成ルールで確認時に生成し、人数を表示したうえで編成を保存する。兵員ゼロでは選択不可。追加戦利品の初期値は武具8＋鉄10（勝利時だけ、通常戦闘報酬に加算）。敗北・引き分け・逃走では追加報酬なし、賞金と季節枠は戻さない。国家の戦況・国力・近隣貴族への討伐貢献は加算しない。戦利品は戦闘前の条件に固定し、通常報酬と合算して容量超過した場合は既存の手動整理を用いる。保存失敗時は戦闘準備も含めて開始前へ戻す。

第3段階の市場・兵糧庫窃盗を接続済み。滞在中の賞金首一覧の「犯罪行動」から選択し、対象勢力・賞金・固定報酬・関係悪化を確認して成立する。初期値：市場は資金500＋塩2・賞金500・支持度/担当貴族好感度各−2、兵糧庫は食料30＋木材5・賞金1,000・各−4。`THEFT_TYPES` と `CRIME_REWARDS` に集約。交易在庫からの略奪ではなく固定報酬とし、戦闘・日数消費はない。容量不足なら成立させず、報酬を自動廃棄しない。

`wanted.settlementActions[settlementId].theftSeason` を共有し、保存復元・占領・手配解除でも当季の窃盗枠を戻さない。名誉家臣、入場拒否、未解決イベント中は不可。確認後の勢力・担当貴族・季節変更を拒否し、保存失敗時は報酬・犯罪・季節枠・支持度・好感度を一緒に戻す。武器庫・拠点襲撃・全犯罪共通の行動IDは後続対象。

合計賞金による賞金稼ぎ追跡を接続済み。遭遇が成立した際、正規軍追跡が選ばれなければ期限内の4勢力合計から抽選する。調整用初期値は合計賞金1以上で5%・20～40人、3,000以上で10%・40～70人、6,000以上で15%・70～110人、10,000以上で20%・110～160人。これは毎日の発生率ではなく遭遇成立時の条件付き抽選率。人数は範囲内の整数を均等抽選し、既存の強編成・賞金稼ぎ兵種プールとLv1～3を使用、最大20部隊。名声や上限以上の賞金で人数を増やさない。数値は `HUNTER_TIERS` に集約する。

新追跡は `pursuitKind: "hunter"` で識別し、正規軍と共通の猶予を使う。通常の名声由来の賞金稼ぎ遭遇は従来のまま。撃退しても賞金は減らさない。正規軍追跡の出現率・人数は現行のままで、その段階表への移行は後続対象。

正規軍追跡の猶予を実装済み。追跡抽選を通常の戦争遭遇と分離し、準備情報の `pursuitKind: "regular"` で識別する。戦後結果・降伏・準備中の逃走・祈りによる回避で `wanted.pursuitUntil` を終了日＋3日に設定し、その日から再抽選可能。処理済み印で重複時の延長を防ぎ、犯罪追加・保存復元でも期限を保持する。通常の戦争遭遇と名声由来の既存「賞金稼ぎ」は猶予の対象外。合計賞金由来の新しい賞金稼ぎ抽選・追跡の段階表は後続実装。

賞金6,000以上の入港拒否を接続済み。街・村・無法港の現支配勢力だけを判定し、拒否時は入場検問・入場イベントを呼ばない。滞在中に条件を満たした場合も表示同期時に入口へ戻す。入口の案内から「賞金首・港外窓口」で最低限食料・賠償・投降・辞任を利用できる。受注済み報告は元の条件のまま依頼カードから行う。拒否中の無法港は既存の依頼受注ボタンを港外にも表示し、犯罪依頼を維持する。入港拒否中は船売却・艤装変更・釣り小屋取引も停止し、開いた画面からの確定にも制限を適用する。賞金1,000～5,999の船売却・艤装変更は引き続き可能。

投降・投獄を賞金首一覧へ追加済み。日数の初期値は30日＋賞金3,000ごと30日、最大120日（`DETENTION_CONFIG`）。禁制品のみを没収し、追加の資金没収は行わない。投降時点で没収と `wanted.detention = {factionId, remaining}` を一括保存する。その後は同期の日次処理で維持費・食料・依頼期限・世界情勢を進め、釈放時に保存する。中断・保存失敗時は保存済みの投獄開始状態から残日数を再処理する方式とし、毎日の中間保存は行わない。保存失敗時は日数経過と世界状態を巻き戻して操作をロックし、再試行できる。没収は再実行しない。

投獄中の通常通知はキューに保持して釈放後に表示する。名誉家臣の勧誘抽選は行わず、予定された災いの処理は釈放後の通常日次処理まで延期する。移動遭遇・入場検問は呼ばない。未解決イベントがある状態からの投降は拒否する。釈放時は投降先の手配だけを解除し、履歴・所属・好感度は変更しない。他勢力の手配には通常の日数経過による自然解除のみ適用する。

通常取引・造船購入の制限を賞金3,000以上で接続済み。船の売却や行商人のイベント取引は維持する。最低限食料は設計の初期案（拠点ごと季節30個、通常買値の1.5倍を切り上げ）で賞金首一覧へ追加した。通常在庫とは独立し、所持資金・空き容量・確認後の価格変化を再検証する。購入枠は `wanted.emergencyFood[settlementId] = {season, used}` として保存し、犯罪追加時の正規化でも保持する。保存失敗時は資金・食料・季節枠を戻す。

施設制限の接続済み範囲：現在の支配勢力の期限内賞金が1,000以上なら、兵員雇用（潮盟・釣り仲間の追加枠を含む）、貴族面会、通常・貴族依頼の新規受注を拒否する。表示と確定時で共通判定を使用する。受注済み報告は依頼カードから従来の達成条件で実行できる。無法港の犯罪依頼の受注窓口は残し、名誉家臣の新規受注禁止は維持する。下記の先行実装の未接続項目は、この記載を優先する。

家臣機能停止の接続済み範囲：自勢力の期限内賞金が1,000以上なら、新規貴族依頼・軍資金提供・前線行動を表示時と確定時に拒否する。所属データは残し、賠償や自然解除で条件を外れると自動再開する。賞金首一覧には停止理由を表示する。受注済み報告と辞任は停止しない。貴族面会そのもの・情報イベント等の特典はまだ制限していない。面会制限は報告窓口を確保する施設制限の段階で追加する。

第2段階の先行実装：名誉家臣による既存の襲撃・検問突破は表示時と実行時に禁止する。受注済み海賊依頼の報告は例外のまま。賞金首一覧を拠点入口でも開けるようにし、確認付き辞任と現地勢力への賞金額1.5倍（切り上げ）の賠償を追加した。賠償は対象勢力だけを解除し履歴を保持する。確認後に状態を再検証し、保存失敗時は資金・手配・所属を戻す。施設制限・家臣機能停止・最低限食料・投獄・追跡猶予は未実装。

1. 勢力別状態・履歴・旧セーブ移行・既存犯罪の対象固定・自然解除・一覧表示。
2. 名誉家臣のロック／辞任／停止、施設権限、報告例外、最低限食料、賠償、投獄、追跡の猶予と段階化。
3. 拠点窃盗・商船襲撃表示・通常拠点襲撃。報酬表を確定してから接続。

## 12. 検証と残る確定事項

必須検証：対象勢力の正しさ、600日境界、旧データの再消去防止、犯罪と報酬の二重反映防止、報告時の元地点条件、海賊からの手配中でも依頼窓口が残ること、名誉家臣の犯罪選択と確定時の拒否、占領後の制限更新、投獄中断からの再開と季節処理、資金不足時の解除導線、追跡の重複と猶予、施設を開いた後の条件変化。

受注済み海賊依頼の報告は名誉家臣の犯罪ロックの例外と確定した。第1段階の勢力別手配基盤を設計するための回答待ちはない。

残る調整・検討事項：手配による検問上昇率、正規軍追跡の段階化、強行入港の成功時効果、黒ひげの品揃え・雇用優遇。既に実装した食料・投獄・犯罪報酬・賞金稼ぎ・恩赦・偽造・司法取引の初期値は本書の該当節を参照する。

将来候補として、恩赦依頼の海賊討伐・要人救出・軍需納品・前線防衛、特赦、捕虜の脱走幇助、港湾税の踏み倒し、独立した正規軍への先制攻撃、海賊関係者への明示的な襲撃を残す。採用や数値は未確定であり、現行仕様へ混ぜない。無法港の窃盗は現行仕様だが、通常拠点襲撃の対象に無法港は含めない。

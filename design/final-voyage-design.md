# 最終航海・航海統計

状態：実装済み。10種類の条件判定・航海統計・結末表示・シード指定による再出発に対応する。海没神話は条件未定・未実装の候補として残す。

関連仕様：[全体設計](design.md)、[賞金首・固有船](bounty-system-design.md)、[勢力別手配](faction-bounty-expansion-design.md)、[潮盟拠点](tide-alliance-design.md)、[魚図鑑](fishing-design.md)。

## 1. 目的と範囲

最終航海は、自由に続けられる旅へ任意の区切りを付ける機能とする。条件を達成しても強制終了せず、プレイヤーが結末を選んだときに神話として記録する。

- 採用する結末は畏怖・討伐・解体・立身・溶合・大航海・蒐集・救済・踏破・探奥の10種類。
- 条件を満たした結末があれば「旅の行動」に「最終航海」ボタンを追加する。
- 複数の結末を達成している場合は、すべてを同等に選択できる。自動的な優先順位や排他関係は設けない。
- 結末の本文と航海統計をダイアログに表示する。
- 「旅を続ける」と「最初から始める」を用意する。続行時は資産・部隊・日付・世界を維持する。
- 最初から始める場合は既存のシード入力・ランダム生成を共用し、確定時に新規データを作成する。

数値条件は設計・判定用に記載する。プレイヤー向けの短い紹介文とエンディング本文には、必要資金・必要隻数などの具体的な条件を記載しない。

## 2. 合意済みの方針と草案上の解釈

ユーザー確認済み：畏怖神話は現在の手配賞金の合計で判定する。一度達成した結末は、その後に資産や賞金が減っても選択可能なまま保存する。

追加の合意：蒐集・救済・踏破の3神話と追加統計をすべて採用する。資金は売却代金を含む累計収入とし、旧セーブの復元できない累計は機能導入後から計測する。兵士の損耗も統計に追加する。海没神話は紹介を残すが、今回の実装対象には含めない。

以下の解釈で実装する。

- 「信仰500」は現在信仰が500以上と解釈する。
- ヴァリアント船は固有船の保有個体数。同じ船種を複数所持していれば各個体を数える。
- 「船50隻」は通常船と固有船を合算した従船数。常に存在する象徴的な聖船は含めない。
- 部隊員は保有する全兵種・全レベルの合計。待機・出撃・予備隊の配置で二重に数えず、潮盟の担い手として恒久離脱した人員は含めない。
- 神殿は実在する潮盟拠点の最終発展段階を数える。今季の恩恵対象に選ばれていない神殿も含める。
- 「100年経過」は新規開始時点からゲーム内で100年分の日数が進んだこととする。現実のプレイ時間とは区別する。

## 3. 結末の条件

同じ行の条件はすべて同時に成立する必要がある。資産を消費する条件ではない。

| 内部ID案 | 結末 | 解放条件 | 判定元 |
| --- | --- | --- | --- |
| `awe` | 畏怖神話 | 現在の手配賞金合計が100,000を超える、かつ名声3,000以上 | `totalWanted(state.wanted)` と `state.fame` |
| `hunt` | 討伐神話 | ヴァリアント船を20隻以上所持 | 正規化した `state.fleet.variants` の個体数 |
| `dismantling` | 解体神話 | 現在資金1,000,000以上、かつ従船50隻以上 | `state.funds` と `totalShips(state.fleet)` |
| `rise` | 立身神話 | 名声5,000以上、かつ保有部隊員500人以上 | `state.fame` と `totalTroops()` 相当の保有数 |
| `merging` | 溶合神話 | 現在信仰500以上、かつ神殿2拠点以上 | `state.faith` と `tideStage(site)` の最終段階 |
| `great_voyage` | 大航海神話 | 開始から100年以上経過 | `absDay(state) - startedAbs >= 100 * DAY_PER_YEAR` |
| `collection` | 蒐集神話 | 実装済みの魚種をすべて図鑑に登録 | `FISH_SPECIES` の全種で図鑑の `count > 0` |
| `salvation` | 救済神話 | 難民の救助人数が累計300人以上 | `voyageStats.refugeesRescued` |
| `exploration` | 踏破神話 | 生成された村・街・無法港をすべて訪問 | 世界の対象拠点ID集合と訪問済みID集合 |
| `discovery` | 探奥神話 | 海図を完成させ、現地探索の報酬を累計10件以上回収 | `voyageStats.chartsCompleted` |

畏怖神話の境界は厳密に `> 100000`。ちょうど100,000では解放しない。他の数値条件は `>=` とする。現在の手配賞金は期限切れ・恩赦・清算などの処理後の値を使い、統計用の累計賞金は条件に流用しない。

解放は、行動の結果がすべて確定した時点、日付更新・手配期限処理後、旧セーブの読み込み後に判定する。一連の処理中の一時的な資産増加では解放しない。成立した結末はIDと初回達成日を保存し、再描画や再読み込みでは重複通知しない。

現在の暦は1季節30日、1年120日。100年は12,000日で、新規開始が神歴1000年春1日なら神歴1100年春1日が最初の達成日になる。

蒐集神話は魚種追加で現在の達成率が下がっても解放を取り消さない。踏破神話は村・街・無法港へ実際に入ったときだけ訪問とし、マップ上の通過・選択・ホバーは含めない。拠点の名前や所属が変わっても同じIDは同じ拠点として扱う。対象が0件の世界では踏破を解放しない。新規拠点追加後も、既に解放した踏破は維持する。

探奥神話は海図の種類・サイズを問わず、完成地点での探索報酬を受け取った海図を1件として数える。断片が揃っただけの海図、噂からの断片回収、探索開始前・中断中の海図は数えない。報酬回収と海図の消費に合わせて加算し、再開や再読み込みで重複しない。

## 4. 短い紹介文

既存の案内と同じ「神話名＝短い情景」の書き方を維持する。討伐神話の「格上に敗れる」説明は、固有船の収集と戦功に合う内容へ改める。

| 結末 | 紹介文 |
| --- | --- |
| 畏怖神話 | その名は港を震わせ、姿なき帆影が人々の畏れとして語り継がれる。 |
| 討伐神話 | 強敵の旗を越えて船を連ね、海を脅かす者たちを退けた航跡が神話となる。 |
| 解体神話 | 富と船団を港へ還し、船を解き、旗を畳んで新たな暮らしへ渡す。 |
| 立身神話 | 人々を率いて名を成した潮語りが、民草の尊敬を集める旗となる。 |
| 溶合神話 | 祈りを沿岸に根づかせ、海の意思を理解した潮語りが海そのものとなる。 |
| 大航海神話 | 幾代もの港と季節を渡り、果てなき旅そのものが海の記憶となる。 |
| 蒐集神話 | 海の命を航海録に集め、その一頁が遠い岸の学びとなる。 |
| 救済神話 | 行き場を失った人々を岸へ届け、その名が帰る場所として語り継がれる。 |
| 踏破神話 | あらゆる港に足跡を残し、離れていた岸をひとつの旅で結ぶ。 |
| 探奥神話 | 散らばった海図を読み解き、忘れられた海の奥に眠る物語を呼び覚ます。 |

既存の海没神話「越えるべき試練で倒れ、嵐に呑まれ消える」は条件未定・未実装の候補として紹介を残す。今回の10種類とは分け、敗北や船の喪失から解放しない。既存の沈黙エンド候補も今回の範囲には含めない。

## 5. エンディング本文案

本文は各200〜300文字程度。具体的な達成条件を列挙せず、海・港・帆・祈りを中心に現在の語り口を広げる。以下の出来事は「旅がこう語り継がれる」という神話上の結末であり、船の解体や主人公の消滅をゲーム状態へ適用するものではない。

### 畏怖神話

あなたの名を記した紙は、潮風に裂かれても港から消えなかった。酒場で誰かがその名を口にすると、喧騒は一瞬だけ静まり、船乗りたちは沖の暗がりへ目を向けた。あなたが奪ったもの、守ったもの、見逃したもの。その違いを知る者は少なく、噂だけが波より速く海を渡っていく。やがて人々は、水平線に帆がなくともあなたの船影を見るようになった。海は何も裁かず、ただその名を深く抱いた。畏れは祈りにも似た声となり、灯を落とした港の夜に、ひとつの神話が生まれた。あなたの航跡は、誰も確かめられないまま、遠い海の戒めとなる。

### 討伐神話

あなたの船団には、かつて異なる旗を掲げていた船が並んでいる。傷の残る舷側も、癖のある舵も、それぞれに越えてきた戦いを覚えていた。港を閉ざした名、航路を奪った名、船乗りが声を潜めて呼んだ名。それらの残響は、今やあなたの帆の下で同じ潮を受ける。凱旋を告げる鐘が鳴ったとき、あなたは勝利の数を語らず、戻らなかった者のために海を見た。人々が覚えたのは、恐ろしい海にも渡る道を残した船団だった。強敵の物語を越えた航跡は、次の旅人を送り出す灯となり、あなたの名は討伐の神話として静かに語り継がれていく。

### 解体神話

最後の入港を迎えた朝、港にはあなたの船を知る人々が集まった。積荷は倉へ運ばれ、擦り切れた綱はほどかれ、遠い海を渡った旗は丁寧に畳まれる。あなたは大きな別れの言葉を用意せず、波に濡れた船腹へ手を置いた。船を支えた板は家の梁になり、帆は雨を避ける屋根になり、残された富はまだ名もない暮らしの支えになった。海から得たものが、ようやく陸へ根を下ろしていく。夕暮れ、岸壁には旅立ちを急がない影がひとつ残った。人々はその穏やかな終わりを、失われた船団ではなく、港を生んだ航海の神話として覚えている。

### 立身神話

あなたの旗が見えると、港の人々は仕事の手を止めた。かつては行き先も定まらない旅人だったあなたの周りに、今はそれぞれの故郷と願いを持つ者たちが集まっている。彼らをひとつにしたのは、命令だけでも、勝利だけでもなかった。飢えた日に分けた食事、帰りを待った夜、同じ波を越えると決めた朝。その積み重ねが、誰も倒れたままにしない旗を育てた。あなたが岸へ降りると、人々は肩書きより先に名を呼んだ。海を渡った潮語りは、いつしか人々の進む先を照らす者になっていた。その旗の下で生まれた信頼は、民草が語る立身の神話となる。

### 溶合神話

沿岸の祈りは、あなたが去った後も途絶えなかった。朝には石段を洗う人がいて、夕べには灯を守る人がいる。海へ向けた声は、どの港でも少しずつ違い、それでも同じ潮の深みへ届いていた。あなたはある日、その声と波音の間に境目がないことを知る。神託を求めて耳を澄ませる必要は、もうなかった。呼吸のたびに海が満ち、目を閉じるたびに遠い岸の灯が見えた。船乗りたちは、凪の水面にあなたの面影を見たという。姿を探す者はやがていなくなり、祈りのそばに残る温かさだけが伝えられた。潮語りが海と溶け合った神話は、今日も寄せる波の中にある。

### 大航海神話

あなたが初めて船を出した港の名を、もう誰も同じようには呼ばない。岸壁は築き直され、灯台は代わり、見送った人々の声は子や孫の語る昔話になった。それでも海へ続く道だけは、あなたの足元に残っている。古い航海録を開けば、今はない店の匂いも、忘れられた旗の色も、昨日のことのように潮風を伴って立ち上がった。あなたは過ぎた季節を惜しまず、まだ名のない水平線へ帆を向ける。いつしか人々は、あなたが海を旅しているのか、海があなたを通して時を渡るのかを語り合うようになった。終わりを決めないその航跡こそが、大航海の神話となる。

### 蒐集神話

濡れた航海録には、海の命が少しずつ書き留められていた。光を受けて銀にひるがえるもの、岩陰で季節を待つもの、深い水底から思いがけず姿を現すもの。あなたはその違いを急いで名付けず、手触りや岸の匂いまで一緒に覚えていった。港の子どもが頁をのぞくと、遠い海の話が身近な水面へつながっていく。やがて航海録は幾つもの手で写され、あなたの知らない岸にも届いた。あなたが集めたのは、ただ珍しい命の名前ではなかった。海にはまだ知る喜びがあるという、小さな驚きだった。その驚きを受け継ぐ者がいるかぎり、蒐集の神話は新しい頁を開き続ける。

### 救済神話

岸が見えたとき、船の上に張り詰めていた沈黙がほどけた。抱えてきた荷はわずかでも、降り立った人々には、それぞれ明日へ持ち越したい願いがあった。あなたは行く先を決めてやるのではなく、選べる場所へ送り届けた。やがて港には新しい店が生まれ、畑には見知らぬ歌が流れ、灯を囲む食卓に昔とは違う言葉が交じるようになった。あなたの船を覚えている者は、助けられた日のことより、その後に始まった暮らしを語った。帰る場所は、失った故郷だけとは限らない。海を渡って結ばれた日々の中に、あなたの名は静かに残り、人々を岸へつなぐ救済の神話となる。

### 踏破神話

あなたの足跡は、賑わう街の石畳にも、村の細い桟橋にも、旗を問わない入り江にも残った。どの岸にも同じ海が寄せているはずなのに、迎える声も、煮炊きの匂いも、別れの作法も少しずつ違う。あなたはその違いを航海録へ重ね、遠い港の話を次の岸へ運んでいった。知らない土地の名は、やがて誰かの会ってみたい人の住む場所になる。帰路の水平線を見たとき、世界は出発の日より狭くなったのではなく、親しい場所を増やしていた。旅人が地図に指を置くたび、離れていた岸はあなたの航跡でつながる。その道を歩く者たちが、踏破の神話を今日も先へ運んでいく。

### 探奥神話

あなたが開いた海図には、途切れた線と、名のない入り江が残されていた。断片を重ねるたび、ただの染みに見えた印が、遠い誰かの航跡へ変わっていく。岩陰に眠る港、潮の底に沈んだ船、祈りだけが残る古い岸。あなたはそこに隠されたものを持ち帰り、忘れられた場所の名を航海録へ書き足した。見つけた宝よりも、帰りを告げる声が海の沈黙をほどいていった。やがて船乗りたちは、道が消えてもあなたなら海の奥を読めると語るようになる。閉じられた海図の先にも、まだ誰かを待つ岸がある。その扉を開き続けた旅は、探奥の神話として次の帆を導いていく。

## 6. 表示と操作

### 6.1 案内と行動ボタン

補助カードの既存「最終航海」は紹介文を読む案内として残す。今回追加する「旅の行動」のボタンとは役割を分け、条件未達でも紹介を読めるようにする。

行動ボタンは解放済みの結末が1つ以上ある場合に表示する。通常の旅へ戻ったときに利用でき、戦闘準備・戦闘中・未確定の神託・イベント選択・探索処理・釣りセッション・拘留処理中は開けない。進行中の処理を中断して結末を確定しない。

解放は処理が確定した段階で記録してよいが、その通知から進行中の処理を飛ばしてダイアログへ移動しない。判定とボタンの利用可否は別の責務とする。

### 6.2 結末の選択と記録

1. 行動ボタンを押すとダイアログを開く。解放済みが1種類ならその本文へ進み、複数なら名前と短い紹介文を並べる。
2. 選んだ結末の本文と「この神話を記録した時点の航海統計」を表示する。
3. 初めて本文を表示したときに結末ID・記録日・統計のスナップショットを保存する。解放と閲覧は別々に記録する。
4. 一覧へ戻って他の解放済み結末も選べる。閲覧済みの結末には「記録済み」を添える。
5. 同じ結末の再閲覧では初回記録日と統計を維持する。現在の統計も「現在の航海」として切り替えて確認できる案とする。

保存に失敗してもゲーム状態を消去しない。本文は閲覧できるが未保存であることを示し、再保存できるようにする。複数結末の閲覧や画面の再描画だけでは統計を加算しない。

### 6.3 続行と新規開始

- 「旅を続ける」、閉じるボタン、背景クリック、Escapeはダイアログを閉じるだけ。日数経過・費用・船や兵の消失は発生しない。
- 「最初から始める」で共通のシード入力画面へ進む。入力の初期値・空欄時は `DEFAULT_WORLD_SEED`、現時点では2025。「ランダム生成」も利用できる。
- シード入力には現在の航海・統計・結末記録を新規データへ置き換える旨を示す。生成・編集だけでは変更しない。
- シード入力のキャンセルでは最終航海の画面へ戻り、現在の航海を維持する。不正入力は入力画面で修正できる。
- 新規開始の確定時だけ世界・状態・累計統計・解放記録・閲覧記録を初期化し、既存の初期依頼などを生成する。旧画面やタイマーを残さず、新規状態を保存する。
- 結末を見たことによる別の資産報酬や能力強化は初期版では設けない。周回をまたぐ実績保存は別機能の候補とする。

## 7. 航海統計

### 7.1 基本統計の6項目

| 希望された項目 | 表示名案 | 集計の定義 |
| --- | --- | --- |
| 稼いだ合計資金 | 累計収入 | ゲーム内の報酬・戦利品・物資や魚や船の売却など、確定した受取額の合計。初期資金・読み込み・手動上書きは除外。支出と相殺しない |
| 倒した兵の数 | 撃破した敵兵 | 出撃済みでHPが0になった敵部隊の人数合計。勝敗に関わらず戦後に1回加算。未投入の予備隊・敗走しただけの部隊・戦闘開始前の放棄は除外 |
| 損耗した兵士 | 累計兵士損耗 | 戦闘・食料不足・維持費不足・災いなどで、実際に保有部隊から恒久的に失われた人数。原因別の内訳も表示 |
| 期限切れも含めた合計賞金 | 累計手配賞金 | プレイヤー自身に新しく加算された手配賞金の総額。勢力をまたいで合算し、期限切れ・恩赦・清算後も減らさない。NPC賞金首の討伐報酬は含めない |
| 稼いだ信仰 | 累計獲得信仰 | 依頼・神託・潮盟・図鑑の季節報酬などの確定した増加分。祈りや損失で減っても累計は維持。初期値・手動上書きは除外 |
| 魚図鑑の進捗 | 魚図鑑 | 実装済み魚種に対する登録種数・総種数・達成率。`FISH_SPECIES` 内で図鑑の `count > 0` の種を数え、未知IDは分母・分子へ含めない |

「撃破した敵兵」は死亡人数ではない。現行戦闘は部隊単位の戦闘不能と戦後の恒久損耗を区別しているため、既存の `killedEnemyCount(meta)` に対応する撃破人数として説明する。

資金は受取額と利益を区別する。例えば売却代金100・購入費80の取引では累計収入に100を加算し、20を利益と呼ぶ集計とは分ける。同時に購入と売却がある一括取引や自動売却でも、資金残高の差額から収入を推定しない。売却代金を含む「累計収入」という定義・表示名で合意済み。

同じ犯罪行動の再処理は既存の成立印を尊重し、累計賞金を二重加算しない。賞金首から受け取った資金報酬は累計収入の内訳へ入れる。魚図鑑は現在の記録をそのまま表示するので、管理用の全開放を使った場合も現在値として表示される。

### 7.2 採用する追加統計

以下の追加統計をすべて採用する。基本統計と合わせて表示し、長くなる場合は「旅と戦い」「人々への支援」「資産」「釣り」のまとまりで読みやすくする。

| 項目 | 集計の定義 |
| --- | --- |
| 航海年数・経過日数 | 航海開始日からの経過日数を120日で年・残りの日に分けて表示。実時間は含めない |
| 訪れた村・街・無法港の数 | 実際の入場時に拠点IDを保存し、種別別と合計を表示。同じ拠点は一度だけ数える。踏破神話と同じ訪問記録を使う |
| 海図の達成数 | 海図を完成し、現地探索の報酬を回収した累計件数。断片の完成だけでは数えない。同じ海図は1回だけ加算し、探奥神話と同じ累計を使う |
| 戦闘の勝利・敗北・引き分け | 戦闘終了処理で結果別に1回加算。終了結果のない準備取消は除外。戦闘中の逃走は現行の結果コードで集計 |
| 討伐した賞金首・獲得した固有船 | NPC賞金首の討伐成立件数と、固有船の累計獲得個体数を別々に表示。同種も個体ごとに数え、売却・喪失で累計は減らさない。現在保有数も併記 |
| 救助した難民・潮盟へ送り出した担い手 | 難民を目的地まで護送した人数と、確定した潮盟への派遣人数を独立集計。途中の受け入れ・護送受注だけでは救助数を加算しない |
| 最大船団・最大部隊・最高名声 | 行動の確定後の保有従船数・保有兵数・名声の最高値。現在値が減っても記録を維持する |
| 累計支出・潮盟への支援額 | 実際に支払った資金の累計。取引・雇用・維持費・支援・その他の内訳を持つ。未払いの不足額は支出に含めない。潮盟への支援額は支出の内訳として併記し、合計へ二重加算しない |
| 釣り上げた魚の数・最大の魚 | 成功した釣果を1匹ずつ加算し、最大体長の魚種・体長cm・釣獲日を記録。売却・解体で累計は減らさず、図鑑全開放では加算しない。同じ最大体長なら最初の記録を残す |

### 7.3 兵士損耗の集計

損耗は味方兵士の恒久的な喪失と定義し、合計と「戦闘」「食料不足」「維持費不足」「災い」「その他の強制喪失」の内訳を表示する。

- 戦闘では戦後精算が返す損耗人数を加算する。戦闘中のHP0・敗走だけでは計上せず、信仰による救護で回復した人数も除く。
- 戦闘外は損耗適用後の実際の減少人数を数える。保有0人なのに要求損耗が1人となる場合などは、実損0人として扱う。
- 解雇、潮盟への派遣、部隊奉納などの自発的な離脱、兵種転換、昇級、編成の移し替え、手動上書きは損耗に含めない。
- 同じ確定処理で総数と原因別を更新し、原因別の合計が総数と一致するようにする。戦後精算と兵数差分の両方で二重に加算しない。
- 新規開始でリセットし、旧セーブは他の累計と同じく機能導入後から計測する。

### 7.4 難民救助の人数

現行の移動イベントと難民護送依頼には護送人数が定義されていないため、救済神話の実装時に人数を保存する必要がある。移動イベントの難民護送と貴族の難民受け入れ依頼を対象とし、目的地への引き渡しが成立した時点だけ `refugeesRescued` に加算する。食料の提供だけでは到着が確認できないため救助人数には含めない。

人数は各護送30人固定とし、依頼生成時に保存して再読み込みで変えない。人数のための乱数は追加せず、既存の報酬・費用を人数に応じて変更することも今回の範囲には含めない。30人は将来調整できる依頼の値として保存し、救済神話の条件300人と区別する。

旧セーブで進行中の人数未保存の護送は人数不明として扱い、その護送から人数を推定加算しない。新しく人数を持つ依頼から計測する。支援先への派遣は別の担い手統計へ記録し、救助人数へ重複加算しない。

## 8. 保存と旧セーブ

導入前のセーブには全期間の収入・信仰獲得・撃破数が保存されていない。犯罪履歴は直近50件、通常ログは直近200件に制限されており、過去の累計を正確に復元できない。

保存領域：

| 領域 | 保存する情報 |
| --- | --- |
| `voyageStats` | 版、航海開始日、計測開始日、全期間計測か途中開始か、収入・支出内訳・信仰・手配賞金・敵兵撃破・味方損耗内訳・戦闘勝敗・賞金首討伐・固有船獲得・難民救助・潮盟派遣と支援・釣獲・海図達成の累計、訪問拠点ID集合、船団・部隊・名声の最高値、最大魚の記録 |
| `finalVoyage` | 版、解放済み結末IDと初回達成日、初回閲覧日とその時点の統計スナップショット |

新規ゲームは初日から計測し、初期資金を収入へ入れない。旧セーブは初回読み込み時に累計を0から計測開始し、画面には「累計値は統計機能の導入後から」と明示する。現在の資産や残るログを全期間の収入へ置き換えない。現在資産・図鑑・神殿・日付で判定できる結末は読み込み時に解放できるが、過去に条件を満たしたかどうかは推定しない。

旧セーブの最高資産は読み込み時の現在値を初期値とし、以後の最高値を更新する。訪問記録は過去のログから復元せず、読み込み時点で入場済みの滞在先と以後に入場する拠点から記録する。難民救助・損耗・釣獲数・最大魚なども導入後の確定結果から計測し、図鑑や所持魚から過去の釣果を累計へ補充しない。現在図鑑の進捗と航海経過日数は引き継ぐため、途中計測の累計・最高値・訪問記録とは表示上区別する。

旧セーブの航海開始日は、現在の仕様で固定されている神歴1000年春1日を補完値とする。累計計測開始日と航海開始日を混同せず、旧セーブでも大航海神話を導入日からやり直させない。開始日の異なる保存方式を導入する場合はこの補完規則を更新する。

海図の累計達成数 `chartsCompleted` がない既存セーブは0で補完する。過去の回収履歴は保存されていないため、この項目の追加後から計測する。既存の収入などの累計や、既に保存された神話の統計は引き継ぐ。

未知の結末IDや不正な統計は表示・判定から除外する。累計値は非負の安全な整数として正規化し、上限へ達した場合は上限で止める。未保存の進行を失って古いセーブへ戻った場合は、統計もそのセーブ時点へ戻る。

## 9. 実装の分担

- `src/endings/endingConfig.js`：内部ID・紹介文・本文。条件値は `endings.js` へ置き、日本語の名前を条件分岐のキーにしない。
- `src/endings/endings.js`：条件判定、解放と閲覧記録の正規化、初回統計スナップショット。表示に依存しない処理とする。
- `src/endings/endingUI.js`：行動ボタン、複数結末の選択、本文・統計・続行・新規開始の接続。
- `src/core/voyageStats.js`：累計の初期化・正規化・加算・表示用集計。報酬や取引の確定箇所で実額を受け取る。
- `src/core/state.js` / `storage.js`：新領域の生成、保存と旧セーブ補完。
- 既存の取引・造船所・報酬・信仰支給・犯罪・戦後処理・食料と維持費の損耗・災い・入場・難民護送・潮盟支援・釣果記録：状態の確定と同じタイミングで統計を記録する。UI同期時の資産差分やログ文章の解析で代用しない。
- `src/ui/worldResetUI.js`：通常のリセットと最終航海の双方から開ける共通入口。取消時の戻り先を渡せるようにする。

`src/app/ui.js` へ条件・本文・累計集計を集中させない。戦闘結果や報酬の二重処理防止は各機能の確定処理と合わせ、統計だけ独自に二回加算される経路を作らない。

## 10. 確認する項目

- 各条件の直前・ちょうど・直後。特に畏怖の100,000と100,001、信仰500、100年の前日と当日。
- 魚図鑑の最後の1種、難民救助299人と300人、最後の未訪問拠点の入場で追加3神話が解放されること。図鑑全開放は釣獲累計を増やさず、魚種追加後も解放済み蒐集を維持すること。
- 海図9件では探奥を解放せず、10件目の報酬回収で解放すること。断片完成・噂回収・保存中断・再表示・再読み込みで達成数を誤加算しないこと。
- 村・街・無法港を重複なく数え、通過・ホバーを訪問に含めず、対象0件で踏破を解放しないこと。
- 複数条件が同時に成立する場合、一方の神話を見ても他方が選べること。
- 資産の減少・手配解除・保存再読み込みで解放済みの結末が失われないこと。
- 固有船の同種個体、通常船との合算、待機兵や予備隊、潮盟への恒久離脱、恩恵対象外の神殿を正しく数えること。
- 各戦闘経路の勝ち・負け・引き分けで撃破数を加算し、未出撃・敗走のみ・中断・結果の再処理では加算しないこと。
- 戦後の救護適用後、食料不足、維持費不足、災いで実損だけを加算し、損耗0・解雇・潮盟派遣・奉納・昇級・兵種転換・再処理を誤加算しないこと。原因別損耗の合計が総数と一致すること。
- 難民護送の受注と受け入れでは救助人数を増やさず、引き渡しで1回だけ加算すること。潮盟の派遣人数と支援額を別々に集計すること。
- 魚の売却・解体で累計釣獲を減らさず、失敗・釣果の再表示・図鑑全開放では増やさないこと。最大魚と資産最高値の記録を維持すること。
- 売買を同時確定する取引、船の自動売却、季節の信仰支給、犯罪の期限切れと清算が累計の定義と一致すること。
- 初回閲覧の統計が固定され、再閲覧・図鑑の魚種追加・現在統計の更新で当時のスナップショットを書き換えないこと。
- 旧セーブの途中計測表示、不正値補完、保存失敗、統計と結末履歴の新規開始時の初期化。
- 続行・閉じる・シード取消・ランダム生成だけでは状態が変わらず、新規開始の確定時だけリセットされること。
- キーボード操作、複数結末の長い一覧、200〜300文字の本文と統計が狭い画面でも読めること。

## 11. 採用した追加結末と残す候補

蒐集・救済・踏破はユーザー承認により採用済み。探奥は海図を10件完成し、報酬を得る結末の追加要望に対応する。条件は第3節、紹介文は第4節、200〜300文字の本文は第5節に記載する。

| 採用結末 | 条件 | 紹介文 |
| --- | --- | --- |
| 蒐集神話 | 魚図鑑を完成 | 海の命を航海録に集め、その一頁が遠い岸の学びとなる。 |
| 救済神話 | 累計で難民300人を救助 | 行き場を失った人々を岸へ届け、その名が帰る場所として語り継がれる。 |
| 踏破神話 | 生成された村・街・無法港をすべて訪問 | あらゆる港に足跡を残し、離れていた岸をひとつの旅で結ぶ。 |
| 探奥神話 | 海図を完成し、現地探索の報酬を累計10件回収 | 散らばった海図を読み解き、忘れられた海の奥に眠る物語を呼び覚ます。 |

蒐集神話は現在の図鑑記録を利用しやすい。救済は新たな累計、踏破は拠点ごとの初回訪問記録が必要。討伐・財産・信仰以外の遊び方にも区切りを用意できる。

海没神話は紹介のみ残す未実装候補とする。条件・判定・解放・閲覧記録を今回の実装へ追加しない。

## 12. 質問・懸念点

確認済み：売却代金を含む累計収入、旧セーブの導入後計測、海没神話の紹介のみ保持、追加3神話と追加統計の全面採用。

残る検討点は以下とする。

1. 大航海神話の12,000日はかなり長い目標。条件は提示された100年のままとし、将来の長期待機などはイベント・維持費・期限処理を飛ばさない別設計にする。
2. 討伐神話は固有船の現在保有数で判定するため、獲得後の売却・喪失により達成が遅れる。同じ船種の複数個体を数える解釈を草案に置く。
3. 続行できる以上、解体や溶合は物理的な状態変更ではなく、旅を神話として語る結末になる。
4. 難民護送は新規依頼30人固定で計測する。旧進行依頼は人数不明として累計へ加算しない。

手動上書きや図鑑全開放は、ローカル環境で `debug=1` を指定したデバッグ起動時だけ表示・実行できる。起動判定は `src/core/debugMode.js`、管理操作は `src/ui/debugUI.js` へ集約し、セーブにはデバッグ状態を保存しない。手動上書きは累計獲得値へ加算しないが、現在資産の条件判定や現在の図鑑表示には反映される。管理操作によるゲーム状態の変更は通常起動へ戻しても残る。この操作を使用した旅を区別したい場合は、管理操作の使用記録を別の任意仕様として検討する。

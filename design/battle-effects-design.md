# 兵・艤装の戦闘演出設計

作成日：2026-10-14。更新日：2026-10-15。

状態：第0段階の調査・設計と、第1〜5段階の共通描画時計・移動・攻撃5カテゴリ・艤装の砲座と時間差斉射・負荷と視認性調整を完了。自動検証に加え、ブラウザで全盤面サイズの各軍上限・5艤装同時発動・PC幅とスマートフォン幅・拡大スクロール選択・終了後の停止を確認済み。演出時間・振幅・暫定の兵種対応は今後も調整できる値とし、物理端末ごとの通しプレイや好みに応じた追加調整は今回の完了範囲と分ける。

戦術、士気、増援、勝敗、戦後処理は [戦闘基盤再設計](battle-redesign.md)、陣形と停止中の指示は [部隊陣形・一時停止指示](battle-unit-formations.md) を参照する。本書は、それらの結果を伝える表示を担当する。

## 1. 目的と変更範囲

移動開始・攻撃・命中に短い動きを付け、兵や艤装が行動している感触を出す。通常の演出は小さく短くし、強い砲撃・斉射だけを大きくする。多数の兵が同時に動いても、部隊、HP、陣形、敗走表示、選択位置を読み取れることを優先する。

兵種ごとに別の演出を作らず、承認済みの「斬撃」「刺突／突撃」「打撃」「射撃」「砲撃／爆発」の5カテゴリを共有する。兵種間の違いはカテゴリへの対応と少数の調整値で表す。火炎などは既存の形に色・粒・残光を重ね、カテゴリを増やさない。敵味方は既存の陣営表示と演出色で区別し、カテゴリの識別は色だけに頼らない。

第1段階で共通基盤と通常射撃を実装し、他の通常攻撃・艤装は短いラインと火花による互換表現を共通基盤へ移した。当時は移動線と兵の位置表示を維持した。第2段階では移動の補間・前傾・歩行・停止を加え、移動線を小さな足元演出へ置き換えた。第3段階で互換表現を5カテゴリ固有の形状へ置き換え、兵画像だけに攻撃・被弾姿勢を加えた。第4段階で戦場直下に艤装専用の砲座帯を設け、砲口からの射撃・照準・反動・時間差斉射を加えた。第5段階では戦況表示を演出の上へ移し、文字を縁取りで補強したうえで、全盤面サイズの上限編成・5艤装・狭い画面の描画と操作を検証した。

`battleCore.js`、`outfitting.js`、ゲーム乱数、HP、ダメージ確定時刻、移動座標、射程、攻撃間隔、勝敗、報酬、保存形式は変更しない。ダメージとHP表示は従来どおりtick内で即時反映し、演出だけが結果へ追随する。今回はダメージUIの遅延を採用しない。

## 2. 調査済みの現行構造

対象はネイティブES Modulesで動くHTML Canvas 2Dゲーム。`src/battle/battle.js`が準備UI・戦闘タイマー・描画・終了通知を担当し、`battleCore.js`が戦闘計算を担当する。基準は`BATTLE_RULES.tickMs = 1000`で、1・2・4倍速は戦闘タイマーの実時間間隔を変えている。盤面は8・10・12・15マス。以下は第0段階の調査記録を含み、第1〜3段階の仮想始点は第4段階の砲座位置へ置き換える。

| 現行構造 | 演出へ接続するときの注意 |
| --- | --- |
| 通常攻撃1回で`attackFx`へ発射用と`impact: true`の2レコードを追加 | 2回の攻撃として再生しない。第1段階では新規のimpactレコードを1攻撃の代表として取り込む |
| 攻撃FXの初期ttlは2。毎tick冒頭にレコードをコピーしてttlを減らす | オブジェクト同一性で新旧判定しない。新tickで`ttl === BATTLE_RULES.attackFxTtl`のものだけを取り込む |
| 攻撃FXは兵IDを保持し、現行描画は現在の兵座標を参照 | 取込時に始点・終点をコピーし、後の移動で軌跡が動かないようにする |
| 通常攻撃の描画は攻撃者または標的のHPが0だと省略 | 新演出は発生済みイベントを描く。撃破・相打ちの決め手を現在の生死で捨てない |
| tick処理の中で終了判定後に`finishBattle()`→`pauseBattle()`が走る | 最終tickのイベントを取り込んでから残り演出の再生へ接続する。戦後処理を演出待ちにしない |
| 艤装の支援イベントは`support`、`equipmentId`、`to`、`impact`を持つ | 艤装は兵の役割・通常攻撃とは別に分類する |
| 第1〜3段階の艤装の始点は盤外の仮想位置`(-0.4, size - 1)` | 当時は砲身や実際の砲座位置がなかった。第4段階は専用Canvas帯の実際の砲口へ置換する |
| ブドウ弾2種は`allEnemies: true`で敵ごとに支援イベントを発行 | 発射光は1tick・1艤装につき1回、着弾は各標的に表示する |
| 移動FXは1マスごとに発生し、同じ兵が1tick内で複数件を持つ | 第2段階の移動補間では同じ兵の経路を順に連結する |
| `moveFx.retreat`は通常接近以外の移動にも付く | 支援兵の追随も含むため、敗走の判定には使わない。敗走は部隊の`status`で確認する |

通常攻撃は移動後に予約して一括反映し、同tickで倒れた兵の予約攻撃も成立する。演出側はこの順序を変えない。衛生兵・斥候の`role: support`は戦術上の役割であり、艤装FXの`support: true`とは意味が異なる。衛生兵に戦闘中の回復能力を追加しない。

## 3. 攻撃5カテゴリと兵種対応

| カテゴリ | 完成時の形と動き | 兵種対応の初期案 |
| --- | --- | --- |
| 斬撃 | 短い弧、細い残像、刃が抜ける光。残光をすぐ消す | 歩兵`infantry`、海兵`marine`、海賊斧兵`pirate_axe` |
| 刺突／突撃 | 前に伸びる線、穂先の閃光、短い踏み込み。突撃は勢いを強める | 鉾槍兵`halberd`、海賊槍兵`pirate_spear`、騎兵`cavalry`、重騎兵`cavalier`、略奪騎兵`raider_cavalry`、海賊突撃兵`pirate_assault` |
| 打撃 | 一瞬の圧縮、丸い衝撃波、少量の破片 | 盾兵`shield`、海賊盾兵`pirate_shield`。衛生兵`medic`・斥候`scout`は暫定でこのカテゴリへ配置 |
| 射撃 | 小さな発射光、細い弾と尾、短い着弾火花 | 弓兵`archer`、弩兵`crossbow`、海弓兵`seaArcher`、海賊弓兵`pirate_archer` |
| 砲撃／爆発 | 強い発射光、太い軌跡または火球、広がる着弾と薄い煙 | 艤装の砲撃・火炎系を中心に使用。現時点で兵へ一律には割り当てない |

衛生兵・斥候の武器表現、海賊突撃兵の突撃表現は素材に合わせて確認する暫定対応。盾兵の打撃も盾そのものによる攻撃と断定せず、短く重い攻撃の共通表現として扱う。未知の兵種には安全な共通表現を用意する。

演出カテゴリは戦術用の`role`・`traits`から独立して定義する。例えば射程2の槍兵を射撃へ分類せず、兵種IDの明示対応を使う。同じカテゴリ内の兵に個別の描画処理を増やさず、大きさ・速度・色などの設定差で調整する。

## 4. 移動と艤装の完成方針

### 移動：第2段階

移動開始で軽く前傾し、移動中は小さい上下動、停止時は一度だけ重心が戻る。騎乗兵は上下動と足元の軌跡を少し強める。砂埃・水しぶきは足元に間欠的に出し、地形に合わせる。位相や粒の向きは兵IDなどから表示専用に決め、全員の動きが完全に同期する見え方を避ける。戦闘用の乱数列を消費しない。

補間・傾き・上下動は表示座標にのみ適用する。実際の兵座標、当たり判定、経路、選択判定へ影響させない。敗走・場所譲り・2マス移動・停止・指示変更でも表示姿勢が残らないようにする。第1段階で維持した移動線は、第2段階で足元の砂埃・水紋へ置き換える。

### 艤装：第4段階

戦場の正方形Canvasを維持し、直下に専用Canvas帯を追加して簡素な木台・金属砲身を描く。照準→砲口の発射光→砲身の後退→復帰と薄い煙を共通時計で動かす。複数艤装は装備枠順に短い時間差で見せ、通常射撃は控えめ、砲撃支援は大きな発射・着弾を使う。時間差は表示だけに使い、既存の枠順処理・抽選・ダメージ順を変更しない。詳細は第4段階の実装仕様を参照する。

| 艤装 | 第3段階のカテゴリ | 演出の初期方針 |
| --- | --- | --- |
| モリ投擲`harpoon` | 射撃`projectile` | 細い矢と小さな命中。軽い発射感 |
| バリスタ`ballista` | 射撃`projectile` | 太めの矢と短い尾。単体への重い射撃 |
| ファイヤバリスタ`fire_ballista` | 砲撃／爆発`blast` | 火球・爆発へ火の粒を追加 |
| ブドウ弾バリスタ`grape_ballista` | 射撃`projectile` | 1回の発射から複数標的へ広がる散弾 |
| 火炎ブドウ弾`fire_grape_ballista` | 砲撃／爆発`blast` | 複数標的の火球・爆発へ火の粒を追加 |
| 砲撃支援`cannon` | 砲撃／爆発`blast` | 強い発射光、重い弾道、大きめの着弾と薄い煙 |

第1段階では仮想始点と従来系の艤装別色・太さを使う短いライン／火花に留めた。第3段階では形状を上記カテゴリへ置き換え、艤装固有の色と強弱を維持した。第4段階も共通5カテゴリの弾と着弾を維持し、始点だけを実際の砲口へ移す。全体射撃の発射光は1tick・1艤装につき1回とし、着弾は標的ごとに保持する。衝角など射撃イベントを持たない設備へ砲座や新しい攻撃を追加しない。

## 5. 第1段階の実装仕様

### 責務とイベント取込

| ファイル | 第1段階で担当する内容 |
| --- | --- |
| `src/battle/battleEffectConfig.js` | 5カテゴリ、兵種対応、艤装の互換表示、演出時間・幅・色などの調整値 |
| `src/battle/battleEffects.js` | イベントの取込、座標コピー、描画時計、Canvas描画、停止／再開／倍速／終了後の残り再生／破棄 |
| `src/battle/battle.js` | tick結果と演出の接続、描画呼出、画面ライフサイクルへの接続 |
| `src/battle/battleCore.js`・`src/fleet/outfitting.js` | 今回変更しない。従来の計算とFX発行を継続 |

新しいtickごとに`attackFx`の`impact: true`かつ初期ttlのレコードを取り込む。同じtickを再描画しても再登録しない。第1段階では通常攻撃は攻撃者と標的、艤装は仮想始点と標的の座標をその時点でコピーした。艤装の始点は第4段階で砲口へ置き換える。レコードの配列と兵オブジェクトは書き換えず、現在のHP0を理由にイベントを除外しない。存在しないIDなど座標を解決できないイベントは安全に省略する。

支援の発射光はtickと`equipmentId`を単位にまとめる。全体射撃の標的ごとの着弾はまとめて消さない。画像読込・ホバー・選択・画面拡大に伴う`renderBattle()`の呼出は表示だけを行う。

### 描画時計とライフサイクル

戦闘の進行は従来のタイマー、演出の進行と再描画は`requestAnimationFrame`で管理する。演出時間は実時間差に表示速度を掛けて進める。描画フレームから戦闘tickを呼んだり、フレーム間隔に合わせてダメージを再計算したりしない。

| 操作・状態 | 演出側の扱い |
| --- | --- |
| 開始 | 時計の基準を設定し、フレーム予約を1本だけ開始する |
| 一時停止 | 演出の進捗を凍結し、フレーム予約を停止。停止中も選択等の再描画は可能 |
| 再開 | 実時間の基準を取り直す。停止中に経過した時間を加算しない |
| 1・2・4倍速変更 | 現在の進捗を保持し、以降の進み方へ新しい速度を適用する |
| 戦闘終了 | 最終tickを取り込み、戦闘と戦後処理は直ちに確定。画面が表示中なら残り演出だけを有限時間再生して停止する |
| 閉じる・再初期化・新規航海 | フレーム予約・キュー・時刻・取込済みtickを破棄し、次の戦闘へ持ち越さない |
| タブ・戦闘画面の非表示 | 残り演出を破棄し、復帰時に過去の攻撃をまとめて再生しない |

終了処理から画面が閉じられた場合は、終了後の残り再生を再起動しない。画像ロードの遅いコールバックも演出ループを新設しない。停止、再開、速度変更の繰返しでフレーム予約が増えないことを確認する。

第1段階で追加した攻撃の同時演出は160件に制限し、超過時は古い演出から破棄する。1フレームの実時間差は最大100msとして、長い描画停止から復帰した瞬間の飛びを抑える。新tickでは古い演出だけを取込時刻まで進めてから新しい演出を追加し、発生前の待ち時間を新しい弾に加算しない。これらの制限は表示だけへ適用する。

### 最初の表示と調整値

第1段階では通常射撃を小さな発射光→始点から終点へ動く細い弾と短い尾→着弾火花の順に描いた。近接など他の通常攻撃は短いラインと火花、艤装は色・幅を分けた互換表現を使っていた。第3段階では下記のカテゴリ固有形状へ置き換える。クリティカル情報は既存のフラグだけを使い、新しい判定を行わない。

| 種類 | 1倍速での初期仮値 | 適用範囲 |
| --- | ---: | --- |
| 通常射撃 | 300ms | 発射から着弾・消失まで |
| その他の通常攻撃 | 260ms | 互換ライン・火花の消失まで |
| 艤装 | 420ms | 互換発射・着弾の消失まで |

これらは戦闘間隔やダメージ時刻ではなく表示時間。実機確認後に設定で調整する。大きさはセル幅に合わせ、Canvasの解像度・拡大表示で始点や着弾位置がずれないようにする。Canvas状態は保存・復元し、透明度や発光設定を兵・地形へ漏らさない。

## 6. 第2段階の実装仕様

`src/battle/battleMovementEffects.js`で移動イベントの取込・経路補間・姿勢・足元描画を担当する。新tickの`moveFx`のうち初期`ttl === BATTLE_RULES.moveFxTtl`（3）だけを座標ごとコピーし、同じ兵IDのイベントを配列順に連結する。場所譲りの交換後に続く移動も一続きに扱い、同tickの再描画や次tickのTTL更新によるレコードのコピーで重複再生しない。次tickが演出の途中に来た場合は、その時点の表示位置から新しい残り経路へつなぐ。実際の部隊座標やイベント配列は書き換えない。

1倍速での表示時間は、移動開始60ms＋1歩180ms＋停止100msとする。1歩は340ms、2歩は520ms。歩兵・騎乗・重装で前傾、上下動、停止時の沈みを調整し、歩行の位相は兵IDから表示専用に決める。ゲーム乱数は消費しない。足元は地形に合わせて少量の砂埃または水紋を描く。`retreat`は支援兵追随などにも付くため敗走と同一視せず、敗走表示は部隊の`status`を基準にする。端に到達して`escaped`になった部隊は、最後の経路の演出中だけ表示して薄く消す。

重騎兵など騎乗・重装の両方に当てはまる兵は重装の小さな振幅を優先する。甲板では砂埃を出さず短い踏み跡へ置き換える。描画遅延で移動が重なったときは開始姿勢を繰り返さず、現在位置から未到達経路と新しい経路をつなぐ。過去経路が異常に蓄積した場合だけ、現在位置と最新経路を残して1部隊最大16点に抑える。

移動を`battleEffects.js`の共通描画時計へ含め、攻撃がないtickも移動が残る間はフレームを予約する。通常攻撃・艤装の始点または終点が同tickに移動していれば、関連部隊の移動所要時間の最大値だけ攻撃表示を待たせ、移動後に保存した発射位置・着弾位置と兵の位置を合わせる。待つのは表示だけであり、HP、ダメージ、戦闘計算、結果確定は従来どおり即時とする。

長い描画遅延中に次tickの移動が始まった場合、その兵を始点・終点とする過去の攻撃演出だけを省略する。古い座標から兵が離れた後に発射光や着弾を出さず、現在tickの移動と攻撃を優先する。無関係な兵の移動では既存の攻撃を消さない。攻撃回数・HP・戦闘イベントそのものは省略しない。

兵画像だけに傾きと上下動を適用する。HPバー、陣形印、選択リング、敗走印は補間した中心へ追随するが、傾けない。クリック・ホバーの選択は引き続き論理セルで判定する。一時停止、再開、倍速変更、終了後の残り再生、非表示、閉じる、初期化は共通時計の既存規則へ従い、破棄後に姿勢・足元演出・待機中の攻撃を持ち越さない。

第2段階は実装・自動検証済み。複数マス・場所譲り・経路コピー・重複防止・途中tick・逃走退出・姿勢復帰・兵種と地形の差・入力保護・停止再開・倍速・攻撃表示待ち・描画遅延時の旧攻撃省略・非表示と破棄を`battleMovementEffects.test.cjs`で確認し、既存の戦闘計算再現性を維持した。保存を共有しないヘッドレスEdgeで、攻撃のないtickの連続描画、前傾と位置補間、一時停止中のCanvas画像一致、4倍速での再開、閉じた後の演出停止、ページエラーなしを確認した。この段階では基本動作を対象とし、全盤面・上限編成の確認は後述の第5段階で実施した。

## 7. 第3段階の実装仕様

### 5カテゴリの共通形状

`src/battle/battleAttackEffects.js`へ攻撃形状の描画を分離する。`battleEffectConfig.js`は兵種ID・艤装IDからの明示的なカテゴリ対応と調整値、`battleEffects.js`は取込・保存した座標・共通時計・移動待ちと攻撃・被弾姿勢の合成を担当する。同じカテゴリは通常兵と艤装で同じ描画関数を使い、色・幅・強さの設定で変える。役割や射程からカテゴリを推測せず、未知の兵種・艤装は安全な共通カテゴリへ戻す。

| カテゴリ | 識別する形と経過 | 攻撃者の兵画像 |
| --- | --- | --- |
| 斬撃`slash` | 短い弧が走り、細い残光がすぐ消える。命中点には小さい閃光 | 軽く構え、刃の向きへ回転して戻る |
| 刺突／突撃`thrust` | 伸縮する直線と穂先。前方へ伸びた後、短く引き戻す | 目標方向へ短く踏み込んで戻る |
| 打撃`strike` | 圧縮から広がる円形衝撃と少量の破片 | いったん沈み、打ち出して姿勢を戻す |
| 射撃`projectile` | 矢形の弾と短い尾。着弾は小さい火花 | 小さく構えて射撃の反動を戻す |
| 砲撃／爆発`blast` | 火球が短い放物線を進み、着弾で広がる爆発と薄い煙 | 通常兵への割当なし。艤装の砲座姿勢は第4段階 |

大きさはセル幅に対する比率で決め、8・10・12・15マス、通常・拡大表示、Canvas解像度変更で形状と位置を保つ。通常攻撃は260ms、通常射撃は300ms、艤装は420msを初期表示時間とする。クリティカルは既存の`crit`を使って大きさを約1.2倍に強め、ダメージ・命中判定・乱数を追加しない。火炎艤装は`blast`へ火の粒や残光を重ね、6種類目のカテゴリを作らない。

### 攻撃・被弾姿勢

姿勢は画像用の`attackX`・`attackY`・`attackAngle`・`attackScaleY`として返し、既存の移動姿勢と合成する。HPバー・陣形印・選択リング・敗走印は攻撃や被弾で揺らしたり縮めたりしない。クリック・ホバーは引き続き論理セルを使う。艤装イベントは標的の被弾だけに使い、兵を発射元として動かさない。

標的は着弾の短い明滅と小さな揺れで被弾を伝える。同時に複数の攻撃が当たっても揺れを単純加算せず、最大振幅を採用して上限へ制限する。攻撃姿勢にも上限を設け、同時イベントで画像が過度に飛んだり傾いたりしないようにする。発生済みの撃破・相打ち演出はスナップショット座標へ表示し、HP0を理由に形状を消さない。

画像専用のずれは合成後の長さを0.22セル以内、追加の傾きを±0.16ラジアン以内、縦倍率を0.92〜1.04、被弾の明滅を0.8以下に制限する。HP0・予備隊・退出済みの兵には攻撃や被弾の姿勢を付けず、最後の攻撃形状だけを保存座標へ描く。Canvasの明るさフィルターは画像描画内で保存・復元し、地形・HPバー・陣形印へ漏らさない。

### 維持する時計・接続

第2段階の関連部隊の移動待ち、後続tickの移動と競合する旧攻撃の省略、同tickの重複取込防止を維持する。形状・姿勢は同じ共通時計の進捗から計算し、一時停止中の再描画で状態を進めない。再開・倍速変更・終了後の残り再生・非表示・閉じる・初期化の扱いは第1・2段階に従う。

全体艤装は同じtick・艤装IDの全標的のうち最長の移動待ちへ開始時刻を揃え、静止した標的向けの弾だけが発射光より先に飛ばないようにする。

入力の兵・イベント・座標は読み取り専用とし、表示用にコピーした情報だけを使う。兵画像・戦闘FX・Canvasの再描画回数を増やしても戦闘結果は変えない。砲座の照準・反動・複数艤装間の時間差はこの段階では追加しない。

第3段階は実装・自動検証済み。`battleAttackEffects.test.cjs`で5カテゴリの同色での形状差、20〜90pxのセル、左右と同一点、入力不変・乱数不使用、Canvas復元、カテゴリ対応、未知ID、炎、全体艤装の共通待機・発射光集約、姿勢と明滅の上限、移動待ち、停止・倍速・破棄を確認した。既存の攻撃・移動演出と全機能の`npm test`、変更箇所の静的検査も通過した。

保存を共有しないヘッドレスEdgeで、実戦の連続描画、移動中の一時停止とCanvas画像一致、4倍速再開、被弾明滅とフィルター復元、閉じた後の演出停止、ページエラーなしを確認した。同じ描画関数から5カテゴリの比較画像も作成して見た目を確認した。上限編成とスマートフォン幅での描画・操作・情報表示の調整は後述の第5段階で実施した。

## 8. 第4段階の実装仕様

### 砲座帯と描画座標

戦場の`battleCanvas`は従来どおり正方形とし、地形・部隊・HP・選択・クリック判定を変更しない。直下に`battleRiggingCanvas`を置き、射撃設備を最大5台、装備枠順に横並びで描く。帯の高さは表示上の戦場幅を`boardWidth`として`clamp(boardWidth * 0.12, 56, 88)`pxとする。射撃設備が0台なら砲座を描かず、能力補正だけの艤装にも砲座を作らない。

2枚のCanvasは同じ戦場幅・DPRとワールド座標を使い、帯の描画だけを`translate(0, -boardWidth)`で移す。砲座・砲口・弾道を共通の位置計算から求め、戦場と帯の境界で飛翔軌跡がつながるように両Canvasへ描く。各Canvasの領域外はそのCanvasでクリップされる。表示サイズ・DPR・通常／拡大表示の変更時には両方の解像度を更新し、発射位置と砲口を揃える。`window.resize`でも戦闘画面が表示中なら再描画し、待機・一時停止・終了後も次のポインタ操作を待たず帯の高さと両Canvasの解像度を更新する。停止中の演出進捗は進めず、画面を閉じている場合は再描画しない。盤面のマス数やクリック判定へ帯の高さを加えない。

画像生成は使わず、Canvas図形でモリ、弩、火炎弩、散弾、火炎散弾、砲撃を描く。木台と金属砲身を共通の基本形にし、モリの穂先・弩の横材・砲口の太さと短い設備名で識別させる。火炎や散弾の射撃は共通カテゴリへ色・粒・標的への広がりを重ねる。

### 責務と斉射の単位

| ファイル | 第4段階の担当 |
| --- | --- |
| `src/battle/battleRiggingEffects.js` | 射撃設備の枠順抽出、砲座位置、照準、斉射の予約、発射、反動、復帰、煙、砲口座標 |
| `src/battle/battleEffects.js` | 艤装モデルを共通時計へ接続、標的ごとの攻撃表示、移動待ち・取消と寿命の連携 |
| `src/battle/battleAttackEffects.js` | 共通5カテゴリの弾道・着弾を継続使用 |
| `src/battle/battle.js`・`index.html`・`layout.css` | 専用Canvas帯、両Canvasのサイズ・DPR・描画・画面ライフサイクルの接続 |

同じtick・`equipmentId`の支援イベントを1斉射へまとめる。1艤装の全標的は同じ砲口・同じ時刻から発射し、発射光と反動は1回、飛翔と着弾は標的ごとに保持する。照準は表示用に求め、ゲーム内の標的や攻撃を選び直さない。

同tickで発動した全艤装の全標的について移動待ちの最大値を取り、その完了後80msの照準を置く。そこから発動艤装の装備枠順に0・70・140・210・280msの差で発射する。非射撃設備やそのtickで未発動の設備は発射順の台数へ含めない。時間差・照準待ちでHP、ダメージ確定、戦闘終了、元の射撃間隔・処理順を遅らせない。

### 反動・復帰と寿命

発射から90msで砲身を後退させ、220msかけて静止位置へ復帰させる。木台の揺れは小さく、兵やHPへ適用しない。共通5カテゴリの艤装攻撃表示は発射後420msとし、その後180msまで薄い砲口の煙を残す。射撃設備の形・色・反動の強弱は表示用設定で変え、能力値を変えない。

弾の始点は発射時点の砲口先端で固定する。発射後の砲身の後退・復帰へ弾道を追随させず、表示サイズ変更時だけ新しい同一ワールド位置へ拡大縮小する。全体射撃でも標的ごとに始点や発射時刻をずらさない。

静止した砲座だけを表示するときはフレーム予約を不要とする。照準待ち・発射待ち・攻撃・反動・煙が残る間だけ既存の共通時計を進め、一時停止・再開・倍速・終了後の有限再生・非表示・閉じる・初期化は第1〜3段階の規則へ従う。描画遅延中の後続tick移動によって旧攻撃表示を取り消す場合、その攻撃に対応する未発射の斉射も取り消し、弾のない発射光や反動を残さない。既に発射した斉射の反動・煙は有限の残り時間だけ表示できるが、非表示・閉じる・初期化ではこれらも破棄する。

### 第4段階の受け入れ条件

- 射撃設備0・1・5台と、能力補正だけの艤装で砲座の有無・台数・装備枠順が一致する。
- 6種の砲座を描け、同tickの斉射は発動した装備枠順に70ms差、全体射撃は1回の発射光・反動と標的ごとの着弾になる。
- 砲口と弾の始点が一致し、反動後に姿勢が戻り、飛翔中の始点は後退へ引っ張られない。
- 戦場と帯の境界、8・10・12・15マス、通常／拡大、表示サイズ・DPR変更でも両Canvasの座標が一致する。待機・停止中のウィンドウリサイズでも帯の高さを再計算する。盤面・HP・クリック判定を維持する。
- 一時停止中は砲座・弾・煙の進捗が一致して止まり、再開と1・2・4倍速でも重複せず、静止砲座だけで描画ループを続けない。
- 描画遅延による旧攻撃取消では未発射の斉射も消え、非表示・閉じる・初期化・次の戦闘へ照準・反動・煙を持ち越さない。
- 最終tickの結果は即時確定し、表示中の残り演出は有限で停止する。乱数、戦闘計算、保存、艤装の能力・枠順を変更しない。

保存を共有しないヘッドレスEdgeで、0・1・5台と補正専用設備の表示、装備順の名称、モリ・バリスタ・全体射撃・砲撃の発射光、DPR2、通常／720px拡大時の両Canvasの境界一致、390px幅での配置と帯の最小高さを確認した。一時停止中の両Canvas画像一致、停止中の幅変更と時計停止の維持、4倍速再開、終了後に閉じた後の描画停止、ページエラーなしも確認済み。全盤面サイズ・上限編成・スマートフォン幅での視認性と負荷は後述の第5段階で確認した。

## 9. 第5段階の実装と検証

### 戦況表示の保護

兵の背景や足元の台座は表示せず、HPバーを味方は青、敵は赤にして陣営を区別する。兵画像には小さい暗色の影を付け、森や山でも輪郭を保つ。選択中だけ、陣営共通の淡い金色の円形輪郭を表示する。HPバーは元の位置である中心から0.22セル下へ置き、高さをセル幅に応じた1.5〜4pxとする。選択・HPは移動中心と退出の薄さに追随し、攻撃姿勢では揺らさない。

戦場の描画順を地形・足元→兵画像→攻撃エフェクト→HP・陣形・選択・敗走／動揺表示とする。`drawBattleUnitStatus()`へ情報表示を分け、同じフレームで取得した移動姿勢を画像と情報表示で共有する。情報表示は移動の中心と退出時の薄さへ追随するが、攻撃・被弾の変位、回転、圧縮、明滅は受けない。全体射撃や複数の爆発が重なってもHP・選択が上塗りされない。陣形・敗走／動揺の文字には2pxの暗色縁取りを付け、地形や兵画像の明るさに左右されにくくする。

2枚のCanvasへ共通座標で描く方式、同時攻撃表示160件の上限、古い表示からの省略、1本の共通フレーム予約、有限の反動・煙の寿命を維持する。下帯の通常攻撃もCanvasの領域外へクリップされる現行方式を維持し、下記のブラウザ計測で必要な負荷削減が認められなかったため、描画経路を分岐させる追加変更は行わない。

`renderBattle()`は戦闘画面が閉じている場合に冒頭で終了する。フレーム予約の破棄に加え、画像読込完了など遅れて到着する描画コールバックも隠れた戦場を再描画しない。タブの非表示は従来どおり演出を破棄し、再表示で過去の攻撃を再生しない。

### 自動検証

| 5 | 負荷・視認性：実装・自動検証済み／ブラウザ確認済み | 全盤面サイズと各軍の盤上上限・5艤装同時発動で描画・選択・有限停止を確認。HP・選択・陣形・敗走を攻撃より最前面へ表示し、通常／拡大スクロールと狭い画面で操作できる。表示上限でも戦闘計算・結果・乱数を変えない |

第1段階の自動確認はイベント重複、座標コピー、撃破・相打ち、全体射撃の発射集約、時計、停止再開、速度変更、終了後の消失、破棄を対象とする。既存の戦闘計算再現性・画面接続比較・戦闘関連テストと静的検査も維持する。`battleCore.test.cjs`は画面接続関数を抽出して実行するため、演出接続を追加する場合は表示側のスタブを用意し、計算比較の目的を保つ。

自動テストの通過と物理端末での視認性は別の確認とする。`npm run test:battle-effects`で第1〜5段階の重複・寿命・停止再開・倍率変更・描画遅延時の新規攻撃・撃破・表示上限・上限編成・結果不変などを単独確認できる。保存を共有しないヘッドレスEdgeで、通常射撃、tick間の連続描画、一時停止中のCanvas画像一致、4倍速での再開、閉じた後の演出停止、ページエラーなしを確認し、第5段階では全盤面・上限編成とPC／狭い画面の操作・負荷も確認した。測定条件と限界は前節に記録し、未測定の端末やFPS値を保証しない。

## 11. 再確認用チェック

以下は素材・演出設定を今後変更したときに使う再確認用の項目とする。第0〜5段階の完了範囲と検証結果は前節までに記録しており、チェックが未記入の過去項目を今回の未完了作業として扱わない。

第1段階の確認対象：

- [ ] 弓兵・弩兵・海弓兵・海賊弓兵の射撃が発射→飛翔→着弾となる。
